## 0. 全体像 ― なぜこの分野を学ぶのか

第4章 4.10 では、監査人が独立した立場で情報セキュリティ対策やITシステムの利活用を点検する「監査」を学びました。監査人が点検するとき、何を物差しにして「できている／できていない」を判断するのでしょうか。その答えの一つが、本ノートで扱う**内部統制**です。

内部統制とは、企業などの組織において業務が正常かつ有効に行われるよう、各種の手続や仕組み、プロセスを整備し、それを遂行することです。企業活動に欠くことのできない重要な仕組みであり、2000年代の大規模な不正会計事件をきっかけに、会社法や金融商品取引法によって、経営者が内部統制を整え、その有効性を評価・報告することが法的な義務になりました。

情報セキュリティ担当者にとって内部統制が重要なのは、財務報告の数字がほぼすべて情報システムで作られているからです。会計システムに誰でもログインでき、誰でもマスタを書き換えられるなら、決算書の数字は信頼できません。そのため内部統制の枠組みは「**ITへの対応**」を基本的要素の一つに置き、アクセス管理・変更管理・運用管理といったセキュリティ対策を**IT全般統制**として評価の対象にしています。支援士が日々設計・運用しているアクセス制御やログ管理は、法制度の上では内部統制の一部なのです。

本ノートは次の順で進みます。

1. **内部統制とは何か**：定義と、COSOフレームワーク（3つの目的・5つの構成要素）
2. **日本の内部統制の基本的枠組み**：4つの目的・6つの基本的要素、内部統制の限界、関係者の役割
3. **会社法と内部統制**：取締役会が決めるべきこと、改正の流れ
4. **SOX法と金融商品取引法**：内部統制報告制度、内部統制報告書の構成、監査人の意見
5. **IT統制とCOBIT**：全般統制と業務処理統制の違い、統制の文書化（業務フロー図・RCM）、COBIT 2019

科目Bの業務観点では「①情報セキュリティマネジメントの推進又は支援」（監査、諸規程の策定）と、「③情報及び情報システムの利用におけるセキュリティ対策の適用の推進又は支援」（アカウント管理とアクセス管理、コンプライアンス管理）に対応します。科目A-2では、全般統制と業務処理統制の区別（確認問題で出題）、日本独自の目的・要素、COBITの構成が問われます。

## 1. 内部統制とは何か

### 1.1 内部統制の定義

**内部統制**（Internal Control）とは、企業などの組織の内部で次のことを行い、企業の活動全般を適切にコントロールすることをいいます。

- 違法行為や不正行為、過失による処理の誤りなどが発生しないようにする
- 業務が正常かつ有効に行われるよう、管理や監視などの手続や仕組み、プロセスを整備する
- 整備した手続などを、組織内のすべての者が遂行する

具体的な姿で言えば、「経理担当者が入力した支払伝票は、上長が承認しなければ支払が実行されない」「発注を入力する人と、検収を入力する人を分ける」「会計システムの本番環境を変更するには変更申請の承認が必要」といった仕組みの一つ一つが内部統制です。第4章 4.7 で学んだ職務分離と相互牽制も、内部統制の典型的な手段です。

内部統制は決して新しい概念や用語ではありません。企業活動において本来欠くことのできない重要な仕組みです。この一連の仕組みを「**内部統制システム**」といいます。企業経営者には、内部統制システムを確立し、その有効性や適切性を維持する責任があります。

### 1.2 COSOフレームワークの概要

**COSOフレームワーク**は、米国の**トレッドウェイ委員会組織委員会**（The Committee of Sponsoring Organizations of the Treadway Commission：**COSO**）が提唱した内部統制のフレームワークです。COSOは1992年から1994年にかけて、報告書「Internal Control - Integrated Framework（内部統制－統合的枠組み、俗に**COSOレポート**と呼ばれる）」を公表し、その中でこのフレームワークを示しました。現在では、内部統制に関する事実上の世界標準（**デファクトスタンダード**）となっています。

COSOフレームワークでは、内部統制の三つの目的と五つの構成要素を次のように定義しています。

| 内部統制の三つの目的 | 内部統制の構成要素 |
|---|---|
| Effectiveness and efficiency of operations（業務の有効性と効率性） | Control environment（統制環境） |
| Reliability of financial reporting（財務報告の信頼性） | Risk assessment（リスクアセスメント） |
| Compliance with applicable laws and regulations（関連法令等の遵守） | Control activities（統制活動） |
| | Information and communication（情報及び伝達） |
| | Monitoring（監視活動） |

> **補足**：COSOフレームワークは2013年に改訂版が公表されています。改訂版では、五つの構成要素を支える17の原則が明示されました。また、目的の一つが「財務報告」から、非財務報告や内部報告も含む「報告」へと拡張されています。

## 2. 日本における内部統制の基本的枠組み

### 2.1 基準の成り立ち

**企業会計審議会**内部統制部会（当時の事務局：金融庁総務企画局）は、2005年12月に「**財務報告に係る内部統制の評価及び監査の基準案**」を公表しました。この基準案では、内部統制を「基本的に、企業等の四つの目的（下記）の達成のために企業内のすべての者によって遂行されるプロセスであり、六つの基本的要素（下記）から構成される」と定義しています。

> **補足**：基準案は2007年2月に「財務報告に係る内部統制の評価及び監査の基準」として確定しました。その後、2023年（令和5年）4月に改訂されています。改訂では、COSOの2013年改訂を踏まえて、目的の一つが「報告の信頼性」に改められたほか、経営者による内部統制の無効化への対応や、ITの委託業務に係る統制の重要性などが盛り込まれました。改訂後の基準は、2024年4月1日以後に開始する事業年度の内部統制の評価及び監査から適用されています。

### 2.2 4つの目的と6つの基本的要素

日本の枠組みはCOSOフレームワークを踏襲しながらも、日本の実情を反映して、独自の目的と要素が一つずつ追加されています。目的に「資産の保全」、基本的要素に「ITへの対応」が加わり、「3つの目的・5つの構成要素」が「4つの目的・6つの基本的要素」になりました。

**図：内部統制の4つの目的と6つの基本的要素**

```

                    │ 業務の有効性  │ 報告の信頼性  │ 事業活動に  │ 資産の保全 │
                    │ 及び効率性    │（旧：財務報告 │ かかわる法令│（日本独自）│
                    │               │  の信頼性）   │ 等の遵守    │            │
 ┌──────────────┐   └───────────────┴───────────────┴─────────────┴────────────┘

 │（どうやって） │                      │

**内部統制の四つの目的**

| 目的 | 内容 |
|------|------|
| 業務の有効性及び効率性 | 事業活動の目的の達成のため、業務の有効性及び効率性を高めること |
| 財務報告の信頼性 | 財務諸表及び財務諸表に重要な影響を及ぼす可能性のある情報の信頼性を確保すること（2023年改訂以前は「財務報告の信頼性」。現在は非財務情報を含む「**報告の信頼性**」とされ、その中に財務報告の信頼性が含まれる） |
| 事業活動にかかわる法令等の遵守 | 事業活動にかかわる法令その他の規範の遵守を促進すること |
| 資産の保全（※日本が独自に追加） | 資産の取得、使用及び処分が正当な手続及び承認の下に行われるよう、資産の保全を図ること |

**内部統制の六つの基本的要素**

| 基本的要素 | 内容 | 情報セキュリティでの具体例 |
|------------|------|------|
| 統制環境 | 組織の気風を決定し、組織内のすべての者の統制に対する意識に影響を与えるとともに、他の基本的要素の基礎となるもの | 経営者が情報セキュリティ基本方針を示し、違反には懲戒で臨む姿勢を明らかにする（第4章 4.3） |
| リスクの評価と対応 | 組織目標の達成に影響を与える事象について、組織目標の達成を阻害する要因をリスクとして識別、分析及び評価し、当該リスクへの適切な対応を行う一連のプロセス | 情報資産ごとにリスクアセスメントを行い、対応を決める（第4章 4.1・4.2） |
| 統制活動 | 経営者の命令及び指示が適切に実行されることを確保するために定める方針及び手続 | 承認、職務分離、アクセス権の付与手続、照合、入力チェック |
| 情報と伝達 | 必要な情報が識別、把握及び処理され、組織内外及び関係者相互に正しく伝えられることを確保すること | インシデントの報告経路、内部通報窓口（第4章 4.8） |
| モニタリング | 内部統制が有効に機能していることを継続的に評価するプロセス | 日常的なログの確認（日常的モニタリング）、内部監査（独立的評価、第4章 4.10） |
| ITへの対応（※日本が独自に追加） | 組織目標を達成するためにあらかじめ適切な方針及び手続を定め、それを踏まえて、業務の実施において組織の内外のITに対し、適切に対応すること | IT全般統制と業務処理統制の整備（本ノート5節） |

内部統制の目的の一つである「財務報告の信頼性」については、本ノート4節で解説するSOX法（金融商品取引法）によって、上場企業等に対応が義務付けられています。

### 2.3 内部統制の限界

内部統制は万能ではありません。基準は、内部統制が有効に整備・運用されていても、次のような**内部統制の限界**があると明記しています。試験では「限界に当たるもの」を選ばせる問題が出ます。

| 限界 | 具体例 |
|---|---|
| 判断の誤り、不注意、複数の担当者による共謀によって有効に機能しなくなる場合がある | 起票者と承認者が共謀すれば、職務分離は機能しない |
| 当初想定していなかった組織内外の環境の変化や非定型的な取引等には、必ずしも対応しない場合がある | 新しく始めたクラウドサービスの取引に、既存の承認手続が想定されていない |
| 整備及び運用に際し、費用と便益との比較衡量が求められる | すべての伝票を二重チェックするのは費用に見合わない |
| 経営者が不当な目的のために内部統制を無視ないし無効ならしめることがある | 社長が経理部長に直接指示して、承認手続を経ずに売上を計上させる（**経営者による内部統制の無効化**。2023年改訂で対応が強調された） |

### 2.4 内部統制に関係する者の役割と責任

内部統制は「組織内のすべての者によって遂行されるプロセス」ですが、立場によって役割が違います。

| 立場 | 役割と責任 |
|---|---|
| 経営者 | 取締役会が決定した基本方針に基づき、内部統制を整備・運用する最終的な責任を負う。財務報告に係る内部統制の有効性を評価し、内部統制報告書で報告する |
| 取締役会 | 内部統制の整備・運用に係る基本方針を決定し、経営者による整備・運用を監督する |
| 監査役等 | 独立した立場から、取締役及び経営者の職務の執行を監査する |
| 内部監査人 | モニタリングの一環として、内部統制の整備・運用状況を検討・評価し、改善を促す（第4章 4.10 の内部監査） |
| 組織内のその他の者 | 自らの業務の中で内部統制を遂行する（承認、照合、報告など） |

現場の担当者自身が、ワークショップや質問書を通じて自分たちの業務の統制を評価する手法を**CSA**（Control Self-Assessment：**統制自己評価**）と呼びます。内部監査部門が年に一度点検するだけでは気づけない日常の不備を、業務を一番よく知る担当者が自ら洗い出せる点に意義があります。

## 3. 会社法と内部統制

### 3.1 会社法の施行と内部統制

それまで商法第2編（会社）、有限会社法、商法特例法などに分散していた会社に関する規定は、一つの法典に再編されました。あわせて、現代の社会経済情勢に合わせた大幅な改正が行われ、2006年5月1日に新たに「**会社法**」として施行されました。

会社法の施行により改正された主な内容を次に示します。

1. 株式会社と有限会社を一つの会社類型（株式会社）として統合
2. 新たな会社類型（**合同会社**）の創設
3. 設立時の出資額規制の撤廃（最低資本金制度の見直し）
4. 株式・新株予約権・社債制度の改善
5. 取締役の責任に関する規定の見直し
6. 内部統制システムの構築の義務化 など

6.については、**第362条**で、**大会社**である取締役会設置会社に対し、内部統制システムの整備の基本方針を取締役会で決定することを義務付けています。ここでいう内部統制システムとは、取締役の職務の執行が法令及び定款に適合することを確保するための体制などを指します。

主語を明確にすると、「**取締役会は**、取締役の職務執行が法令・定款に適合することを確保する体制などの**基本方針を決定しなければならない**」という義務です。基本方針には、情報の保存及び管理に関する体制や、損失の危険の管理に関する体制なども含まれるため、情報セキュリティの管理体制は会社法上の内部統制システムの一部として取締役会の決議事項になります。取締役会がこの体制を整えずに情報漏えいなどで会社に損害を生じさせた場合、取締役は善管注意義務違反を問われ得ます。

> **用語解説**：会社法における「大会社」とは、最終事業年度の貸借対照表上の資本金が5億円以上、または負債の合計額が200億円以上の株式会社をいいます。取締役会を設置していない大会社については、**第348条**で同様の義務が定められています。

### 3.2 会社法改正

2006年に施行された会社法を改正する法律（**改正会社法**）が、2014年6月に可決・成立し、2015年5月に施行されました。改正会社法には、次のような内容が盛り込まれています。

- **社外取締役**の起用を促進し、起用しない企業にはその理由の説明を義務付ける
- 重要な子会社を売却するときには、株主総会で3分の2以上の賛同（特別決議）を得なければならないようにする（ただし、水俣病の原因となった企業「チッソ」は適用除外）
- 親会社の株主が、不祥事を起こした子会社の経営陣を訴えられるようにする（**多重代表訴訟**制度の創設）

このほか、「**監査等委員会設置会社**」制度の創設や、内部統制システムの対象を**企業集団**（親会社と子会社からなるグループ）にまで拡大することも規定されました。グループ会社のシステムを親会社の情報システム部門がまとめて管理している場合などは、子会社を含めたセキュリティ管理体制が取締役会の基本方針の対象になる、ということです。

> **補足**：以前は、社外取締役を置かない場合に理由を説明すればよいとされていましたが、2019年12月に成立し、2021年3月に施行された会社法改正により、現在は上場会社等に対する社外取締役の設置が義務化されています。

## 4. SOX法と金融商品取引法

### 4.1 米国SOX法の概要と制定の経緯

**SOX法**とは、法案提出者である上院議員サーベンス（Sarbanes）と下院議員オクスリー（Oxley）の名を冠した「**サーベンス・オクスリー法**（Sarbanes-Oxley Act）」の略称です。その正式名称を "Public Company Accounting Reform and Investor Protection Act of 2002"（上場企業会計改革及び投資家保護法）といいます。

米国SOX法の目的は、投資家を保護することです。そのために、米国上場企業に対し、財務報告の透明性・正確性を確保するための企業改革を促すとともに、投資家に対する経営者の責任・義務や、違反時の罰則等を規定しています。

米国では、1990年代末から2000年代初頭にかけて、**エンロン事件**や**ワールドコム事件**など、企業の不正会計問題が相次ぎました。これらの事件では、経営者が主導して利益を水増しし、投資家は実態と異なる決算書を信じて株式を買い、会社の破綻によって巨額の損失を被りました。これらに対処するため、企業のコンプライアンスや監査の強化、経営者による不正行為の防止等を目的として、2002年7月末にSOX法が成立しました。そして2004年には、同法に基づく内部統制監査制度が導入されました。

> **補足**：SOX法**第302条**は、経営者に財務報告の正確性を宣誓させる規定です。**第404条**は、財務報告に係る内部統制の有効性を経営者が評価し、監査人がこれを監査する規定です。この二つは特に重要な条項として知られています。

### 4.2 日本版SOX法の概要

いわゆる「**日本版SOX法**」とは、米国SOX法にならい、日本国内の上場企業に対して会計監査制度の充実と内部統制の強化を求める法規制を指します。「**日本版企業改革法**」とも呼ばれています。広義には、次の基準や法律の総称となります。

| # | 名称 | 位置づけ |
|---|---|---|
| 1 | **金融商品取引法** | 証券取引法を抜本改正するものとして、2006年6月7日に成立した（狭義の日本版SOX法） |
| 2 | **財務報告に係る内部統制の評価及び監査の基準案** | 日本版SOX法における監査の基準となる文書 |
| 3 | **財務報告に係る内部統制の評価及び監査に関する実施基準** | 日本版SOX法における具体的な対応範囲や対応方法を示すガイドラインとなる文書 |

金融商品取引法では、上場企業等に対し、財務報告に係る内部統制の有効性を経営者が評価した「**内部統制報告書**」の提出を義務付けています。また、その報告書について公認会計士または監査法人による監査（**内部統制監査**）を受けることも求めています。この制度は、2008年4月1日以後に開始する事業年度から適用されています。あわせて、経営者が有価証券報告書の記載内容が適正であることを確認した「**確認書**」の提出も求められます。米国SOX法と対応させると、確認書が第302条（宣誓）、内部統制報告書と内部統制監査が第404条（評価と監査）に当たります。

### 4.3 内部統制報告制度の流れ

主語を補って、制度全体を一つの流れで見ておきます。

```
 ① 取締役会        ② 経営者                     ③ 経営者                ④ 監査人
 基本方針を決定 → 内部統制を整備・運用 →    有効性を評価し        → 内部統制報告書を監査し
（会社法）         （全社的な内部統制、        内部統制報告書を作成     内部統制監査報告書で
                    業務プロセス、IT統制）     （期末日を基準日）       意見を表明
                                                    │                        │
                                                    └──── 有価証券報告書と併せて提出 ──→ 財務局（投資家が閲覧）
```

経営者は、まず全社的な内部統制を評価し、その結果を踏まえて評価範囲の業務プロセスを決め、各プロセスの統制について「統制がきちんと設計されているか（**整備状況**）」と「設計どおりに実際に行われているか（**運用状況**）」を評価します。運用状況の評価では、評価者が承認記録などのサンプルを抽出して、承認が実際に行われていたかを確かめます。

評価の結果、財務報告に重要な影響を及ぼす可能性が高い不備が見つかった場合、それは「**開示すべき重要な不備**」として内部統制報告書に記載されます。この用語は、以前（2011年の基準改訂前）は「重要な欠陥」と呼ばれていましたが、企業そのものに欠陥があるかのような誤解を避けるため、現在の呼び方に改められました。

### 4.4 内部統制報告書の構成

内部統制報告書は、内閣府令で定められた様式に従って作成します。見た目は次のような構成です。

```
【表紙】
  【提出書類】        内部統制報告書
  【根拠条文】        金融商品取引法第24条の4の4第1項
  【提出先】          関東財務局長
  【会社名】          Example株式会社
  【代表者の役職氏名】 代表取締役社長  例示 太郎
  【最高財務責任者の役職氏名】 取締役CFO  例示 花子

1【財務報告に係る内部統制の基本的枠組みに関する事項】
   代表取締役社長及びCFOは、財務報告に係る内部統制の整備及び運用に責任を有しており、
   企業会計審議会の基準に示されている内部統制の基本的枠組みに準拠して整備及び運用している。
   （内部統制の固有の限界についても記載）

2【評価の範囲、基準日及び評価手続に関する事項】
   評価の基準日：2027年3月31日（事業年度の末日）
   評価範囲：全社的な内部統制、決算・財務報告プロセス、
            重要な事業拠点の売上・売掛金・棚卸資産に至る業務プロセス
   評価手続：全社的な内部統制の評価結果を踏まえ、業務プロセスを評価した

3【評価結果に関する事項】
   上記の評価の結果、当事業年度末日時点において、当社の財務報告に係る内部統制は
   有効であると判断した。

4【付記事項】   （基準日後に生じた、内部統制に重要な影響を及ぼす事象など）
5【特記事項】   （該当事項なし）
```

「3 評価結果に関する事項」に経営者が書く結論は、次の三つのいずれかです。

| 経営者の評価結果 | 意味 |
|---|---|
| 財務報告に係る内部統制は有効である | 開示すべき重要な不備がない |
| 開示すべき重要な不備があり、有効でない | 不備の内容と、期末日までに是正されなかった理由を併せて記載する |
| 重要な評価手続が実施できなかったため、評価結果を表明できない | 実施できなかった手続と理由を記載する |

監査人（公認会計士または監査法人）は、この内部統制報告書が適正に表示されているかについて、「**内部統制監査報告書**」で意見を表明します。意見には、無限定適正意見、限定付適正意見、不適正意見、意見不表明の4種類があります。日本の制度では、監査人は経営者の評価結果を監査する形をとっており、監査人が内部統制そのものを直接評価して意見を述べる方式（ダイレクト・レポーティング）は採用していません。

### 4.5 金融商品取引法等の改正

金融商品取引法は、金融市場を取り巻く環境の変化に応じて改正が重ねられています。2023年（令和5年）11月に成立した「金融商品取引法等の一部を改正する法律」には、次のような内容が盛り込まれています。

- 顧客等の最善の利益の勘案義務
- 「デジタル原則に照らした規制の一括見直しプラン」に基づくアナログ規制の見直し
- **ソーシャルレンディング**等に係る規制の見直し
- **セキュリティトークン**関連の見直し
- 金融商品販売業者等の掲げる勧誘方針の公表方法について、インターネット上での掲載義務

## 5. IT統制とCOBIT

### 5.1 ITへの対応における留意点

本ノート2.2で見たように、日本における内部統制の基本的要素の一つとして「**ITへの対応**」が挙げられています。ITへの対応は、「**IT環境への対応**」と「**ITの利用及び統制**」からなっています。

**IT環境への対応**とは、組織の目標を達成するために、あらかじめ適切な方針と手続を定め、それを踏まえて組織内外のIT環境に対して適切な対応を行うことです。たとえば経営者は、自社がどの程度ITに依存しているか、クラウドサービスや外部委託をどこまで利用しているかを把握し、それに応じた統制を設計すべきです。

**ITの利用及び統制**とは、次の二つを行うことです。

- 内部統制の他の基本的要素の有効性を確保するために、ITを有効かつ効率的に利用すること（例：承認ワークフローシステムで承認の記録を自動的に残す）
- 内部統制の他の基本的要素を機能させることにより、ITが有効かつ適正に利用されるよう監視・統制すること（例：会計システムの利用者権限を定期的に見直す）

ITの利用及び統制においては、導入されているITの利便性とその脆弱性、業務に与える影響の重要性等を十分考慮する必要があります。ITは処理を正確に速く繰り返せる反面、プログラムやマスタが一度誤って（あるいは不正に）変更されると、その誤りがすべての取引に一斉に広がるからです。

### 5.2 IT統制の概要 ― 全般統制と業務処理統制

**IT統制**は、**IT業務処理統制**と**IT全般統制**とに大別されます。

**IT業務処理統制**とは、業務プロセスに組み込まれた個々の情報システム（アプリケーションシステム）において、承認された業務がすべて正確に処理・記録されることを確保するためのコントロールをいいます。データの欠落や重複、改ざんなどを防ぎ、処理の正当性・正確性・網羅性・一貫性等を確保することが目的です。具体的には、入力データのチェック（件数、書式、値の範囲等）や、元データと出力結果の突合せなどが該当します。

**IT全般統制**とは、IT業務処理統制が適正かつ有効に機能するために必要な、組織全体のIT基盤や施策、体制などからなる各種のコントロールをいいます。具体的には、次のようなものが該当します。

- 組織のIT戦略
- IT戦略を実行するためのシステム企画・設計・開発・運用・保守などの体制及びプロセス
- ITインフラにおける情報セキュリティ対策をはじめとした各種のコントロール
- 情報セキュリティマネジメントシステム（ISMS）

つまり、アクセス制御、認証システム、データの秘匿化（暗号化）、ログ分析及び管理、バックアップシステムなどの各種セキュリティ対策は、IT全般統制を構成する要素ということになります。

両者の関係は「土台と建物」にたとえられます。受注システムに入力チェック（業務処理統制）が正しく組み込まれていても、開発者が承認なしに本番のプログラムを書き換えられる環境（全般統制の不備）では、そのチェックがいつの間にか外されているかもしれません。全般統制が有効であって初めて、業務処理統制が「昨日も今日も同じように動いている」と信頼できるのです。

**図：財務報告に係る内部統制とIT統制の関係イメージ**

```
┌──────────────────────────────────────────┐
│          財務報告に係る内部統制          │
│  ┌────────────────────────────────────┐  │
│  │ 全社的な内部統制                   │  │
│  │ （統制環境・リスクの評価と対応等） │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │ 業務プロセスに係る内部統制         │  │
│  │  ┌──────────────────────────────┐  │  │
│  │  │ IT業務処理統制               │  │  │
│  │  │（入力チェック、突合せ等）    │  │  │
│  │  └──────────────────────────────┘  │  │
│  └────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐  │
│  │ IT全般統制                         │  │
│  │（開発・保守、運用管理、アクセス    │  │
│  │  管理、外部委託管理等）            │  │
│  │  ※IT業務処理統制の有効性を支える  │  │

### 5.3 実例で区別する ― アクセス権の管理と入力チェック

全般統制と業務処理統制の区別は、確認問題のように選択肢で問われます。迷ったら「その統制は、**特定の業務アプリケーションの個々の取引データ**を対象にしているか（業務処理統制）、**複数のシステムに共通するIT基盤・体制**を対象にしているか（全般統制）」で判断します。

**例1：全般統制 ― アクセス権の管理**

情報システム部門は、会計システムを含む全システムのアカウントについて、申請・承認に基づいて付与し、定期的に棚卸しします。次は四半期ごとのアクセス権レビューの記録の例です。

```
アクセス権棚卸し記録（2026年度 第2四半期）  対象：会計システム（acct.corp.example.jp）
実施者：情報システム部 運用課  承認者：情報システム部長  実施日：2026/10/01

ユーザID   氏名       所属       権限             最終ログイン  判定    措置
u1023      例示 一郎  経理部     仕訳入力         2026/09/30    継続    ―
u1088      例示 二郎  経理部     仕訳承認         2026/09/29    継続    ―
u2051      例示 三郎  営業部     参照             2026/04/12    不要    10/02 削除（異動済み）
adm01      （共用）   情シス     システム管理者   2026/09/15    要是正  個人IDへ切替、使用時は事前承認
```

この統制は、特定の取引ではなく「誰がシステムに入れるか」という基盤を対象にしているので全般統制です。共用の管理者IDのように、誰が操作したかを特定できない状態は、全般統制の不備として指摘されます（第6章 6.1 のアクセス制御、第7章 7.8 のログ管理とつながります）。

**例2：業務処理統制 ― 入力チェック**

受注システムは、営業担当者が受注を入力したときに、プログラムで次のチェックを自動的に行います。

```
┌─ 受注入力（受注システム） ───────────────────────────────┐
│ 顧客コード [C00125  ] → 顧客マスタと照合：Example商事（OK）  │
│ 受注日     [2026/10/03] → 形式チェック：OK                   │
│ 品目コード [P-4410  ] → 品目マスタと照合：OK                 │
│ 数量       [ 12000  ] → 範囲チェック：1〜9,999 を超えています │
│ 単価       [    850 ] → 単価マスタとの差異：0%（OK）         │
│ 与信残高   残り 3,000,000円 → 受注金額 10,200,000円で超過     │
│                                                              │
│ ⚠ 数量の上限超過、与信限度超過のため登録できません。          │
│   上長承認（営業課長）が必要です。      [承認依頼] [取消]     │
└──────────────────────────────────────────────────────────┘
日次処理後：入力件数 1,254件／出荷指示件数 1,254件（件数の突合せ OK）
```

この統制は、受注という個々の取引データの正確性・正当性を確保しているので業務処理統制です。

**表：ITに係る統制の区別（実施基準の例示に基づく）**

| 統制の例 | 区分 | 判断の理由 |
|---|---|---|
| システムの開発、保守に係る管理（変更申請・承認、テスト、本番移行の分離） | 全般統制 | 全システムに共通する開発・保守の体制 |
| システムの運用・管理（ジョブ監視、障害対応、バックアップ） | 全般統制 | 全システムに共通する運用の体制 |
| 内外からのアクセス管理等のシステムの安全性の確保（ID管理、特権ID管理、ファイアウォール） | 全般統制 | IT基盤のセキュリティ |
| 外部委託に関する契約の管理（委託先の評価、SLAの確認） | 全般統制 | 組織全体の委託管理 |
| 入力情報の完全性、正確性、正当性等の確保（範囲チェック、マスタ照合、件数・合計の突合せ） | 業務処理統制 | 個々の取引データが対象 |
| エラーデータの修正と再処理 | 業務処理統制 | 個々の取引データが対象 |
| マスタ・データの正確性の確保（業務別マスタの維持管理） | 業務処理統制 | 特定の業務で使うデータが対象 |
| システムの利用に関する認証・操作範囲の限定（受注システム内で、入力者と承認者の権限を分ける） | 業務処理統制 | 特定アプリケーション内の操作権限 |

最後の行は引っかけになりやすい点です。「アクセス管理」という言葉は両方に出てきます。IT基盤全体のアクセス管理（誰がシステムに入れるか、特権IDの管理）は全般統制、特定のアプリケーションの中で「入力はできるが承認はできない」といった操作範囲を限定する設定は業務処理統制です。

### 5.4 実施基準におけるITに係る統制の評価

「**財務報告に係る内部統制の評価及び監査に関する実施基準**」では、ITに係る全般統制及び業務処理統制の評価について、次のように示しています。

**a. ITに係る全般統制の評価**

経営者は、ITに係る全般統制が、例えば次のような点において有効に整備及び運用されているかを評価する。

- ITの開発、保守
- システムの運用・管理
- 内外からのアクセス管理等のシステムの安全性の確保
- 外部委託に関する契約の管理

**b. ITに係る業務処理統制の評価**

経営者は、識別したITに係る業務処理統制が、適切に業務プロセスに組み込まれ、運用されているかを評価する。具体的には、次のような点について、業務処理統制が有効に整備及び運用されているかを評価する。

- 入力情報の完全性、正確性、正当性等が確保されているか
- エラーデータの修正と再処理の機能が確保されているか
- マスタ・データの正確性が確保されているか
- システムの利用に関する認証・操作範囲の限定等、適切なアクセス管理がなされているか

> 出典：企業会計審議会内部統制部会「財務報告に係る内部統制の評価及び監査に関する実施基準－公開草案－」（平成18年11月21日）
> http://www.fsa.go.jp/news/18/singi/20061121-2.pdf
>
> 実施基準はその後2007年2月に確定し、2023年（令和5年）に改訂されている（確認問題は令和5年版を前提に出題されている）。

評価の実務で全般統制が重視される理由は、自動化された業務処理統制の評価の手間に直結するからです。全般統制（特に変更管理）が有効であれば、プログラムに組み込まれた入力チェックは「一度正しく動くことを確かめれば、期間中も同じように動いている」と推定できます。全般統制に不備があると、評価者はその推定ができず、期間を通じて多くの取引を検証し直さなければなりません。

### 5.5 統制の文書化 ― 業務フロー図とRCM

経営者が内部統制を評価し、監査人がそれを監査するためには、「どの業務に、どんなリスクがあり、どの統制で防いでいるか」が文書になっていなければなりません。実務では、次の三つの文書（いわゆる**3点セット**）を作成するのが一般的です。

| 文書 | 何を書くか |
|---|---|
| 業務記述書 | 業務の手順を文章で記述する（誰が、いつ、何を、どのシステムで行うか） |
| 業務フロー図（フローチャート） | 部門ごとのレーンに分けて、業務と書類・データの流れを図示し、リスクと統制の位置に記号を付ける |
| **リスクと統制の対応表**（**RCM**：Risk Control Matrix） | リスクごとに、それを低減する統制、統制の種類、実施頻度、担当者を一覧にする |

### 5.6 監査との関係 ― 第4章 4.10 とつなげる

内部統制の評価と監査には、複数の主体が関わります。第4章 4.10 の監査と区別して整理しておきます。

| 主体 | 何をするか | 拠り所 |
|---|---|---|
| 経営者（実務は内部統制評価の担当部門や内部監査部門） | 財務報告に係る内部統制の有効性を評価し、内部統制報告書を作成する | 財務報告に係る内部統制の評価及び監査の基準・実施基準 |
| 内部監査部門 | モニタリング（独立的評価）として、内部統制の整備・運用状況を点検し改善を促す。IT統制の点検ではシステム監査の手法を用いる | システム監査基準、システム管理基準（第4章 4.10） |
| 外部監査人（公認会計士・監査法人） | 経営者の内部統制報告書を監査し、内部統制監査報告書で意見を表明する | 同上の基準・実施基準 |
| 監査役等 | 取締役・経営者の職務執行を監査する（会社法） | 会社法 |

第4章 4.10 で学んだシステム管理基準は、ITに係る全般統制・業務処理統制を点検するときの判断の尺度としても使われます。監査人が「監査証拠に基づいて指摘事項と改善提案を書く」という作法も同じです。たとえば上のアクセス権棚卸し記録で共用管理者IDが見つかれば、監査人は「会計システムの管理者IDが共用されており、操作者を特定できない。個人別IDへの切替えと、特権ID使用時の事前承認・操作ログの確認を行う必要がある」と指摘することになります。

### 5.7 COBITの概要

**COBIT**（Control Objectives for Information and related Technology）とは、米国の**ISACA**（Information Systems Audit and Control Association）と**ITGI**（IT Governance Institute）によって策定された、ITガバナンス及びITマネジメントに関する実践規範です。ガイドライン文書、フレームワーク、プロセス参照モデル等からなります。内部統制の評価においては、IT全般統制として何を整備すべきかを網羅的に洗い出すための参照モデルとして使われます。

最新版の**COBIT 2019**では、**ITガバナンス**と**ITマネジメント**を明確に区別しています。そのうえで、ガバナンス領域の一つのドメインと、マネジメント領域の四つのドメインからなる、合計5ドメイン・40プロセスのモデルを定義しています。ガバナンス（EDM）は取締役会などが「評価し、方向付け、モニタする」領域、マネジメント（APO・BAI・DSS・MEA）は経営陣が「計画し、構築し、運用し、モニタする」領域です。第4章 4.10 のシステム管理基準のITガバナンス編がEDMモデルに基づいていたことを思い出してください。

## 6. 確認問題

### 6.1 理解度チェック（Check!）

- **Q1**：内部統制とは何か。
- **Q2**：日本における内部統制の四つの目的と六つの基本的要素を挙げよ。
- **Q3**：会社法（新会社法）では、内部統制システムについて何を義務付けているか。
- **Q4**：IT統制における業務処理統制とIT全般統制について説明せよ。
- **Q5**：COBITとは何か。

> **解答例**
> - Q1：企業などの組織の内部で、違法行為・不正行為・過失による誤りが発生しないよう、管理や監視などの手続・仕組み・プロセスを整備し、それを組織内のすべての者が遂行することで、企業活動全般を適切にコントロールすること（本ノート1.1）。
> - Q2：目的は、業務の有効性及び効率性、財務報告の信頼性（2023年改訂後は報告の信頼性）、事業活動にかかわる法令等の遵守、資産の保全。基本的要素は、統制環境、リスクの評価と対応、統制活動、情報と伝達、モニタリング、ITへの対応。資産の保全とITへの対応が日本独自（本ノート2.2）。
> - Q3：大会社である取締役会設置会社に対し、取締役の職務の執行が法令及び定款に適合することを確保するための体制など（内部統制システム）の整備の基本方針を、取締役会で決定することを義務付けている（第362条。取締役会非設置の大会社は第348条）（本ノート3.1）。
> - Q4：業務処理統制は、業務プロセスに組み込まれた個々のアプリケーションシステムで、承認された業務がすべて正確に処理・記録されることを確保する統制（入力チェック、突合せ、エラーデータの修正と再処理、マスタの正確性など）。IT全般統制は、業務処理統制が有効に機能する環境を支える、組織全体のIT基盤・体制に関する統制（開発・保守、運用・管理、アクセス管理等の安全性の確保、外部委託契約の管理）（本ノート5.2〜5.4）。
> - Q5：ISACAとITGIが策定したITガバナンス及びITマネジメントの実践規範。COBIT 2019は、ガバナンス領域（EDM）1ドメインとマネジメント領域（APO・BAI・DSS・MEA）4ドメイン、計40プロセスで構成される（本ノート5.7）。

### 6.2 確認問題

金融庁“財務報告に係る内部統制の評価及び監査に関する実施基準（令和5年）”にある、ITに係る全般統制に該当するものとして、最も適切なものはどれか。

ア　アプリケーションプログラムの例外処理（エラー）の修正と再処理
イ　業務別マスタ・データの維持管理
ウ　システムの開発、保守に係る管理
エ　入力情報の完全性、正確性、正当性等を確保する統制

*〔情報処理安全確保支援士試験・R6春・午前Ⅱ〕*

> **解答・解説**
> 正解：**ウ**
>
> ITに関する統制は、業務処理統制と全般統制から成る。
>
> - **業務処理統制**：組織の業務プロセスに組み込まれた、個々の情報システム（アプリケーションシステム）の処理（入力・編集・計算・送信・保存・削除等）に対する各種のコントロールである。データの欠落や重複、改ざんなどが発生することを防ぎ、処理の正当性・正確性・網羅性・一貫性等を確保するために行う。
> - **全般統制**：業務処理統制が有効に機能する環境を保証するための統制活動である。複数の業務処理統制に関係する方針と手続を指し、通常、組織全体のIT基盤や体制を対象とする。実施基準では、次のものが例示されている。
>   - ITの開発、保守に係る管理
>   - システムの運用・管理
>   - 内外からのアクセス管理等のシステムの安全性の確保
>   - 外部委託に関する契約の管理
>
> 各選択肢を検討する。
>
> - ア：例外処理（エラー）の修正と再処理は、業務処理統制に該当する。
> - イ：業務別マスタ・データの維持管理は、業務処理統制に該当する。
> - ウ：システムの開発、保守に係る管理は、全般統制に該当する。したがって、これが正解である。
> - エ：入力情報の完全性、正確性、正当性等を確保する統制は、業務処理統制に該当する。
>
> 本ノート5.3の区別表と同じ考え方で、「特定の業務アプリケーションの取引データが対象か、組織全体のIT基盤・体制が対象か」で判断すればよい。

## 7. 試験対策まとめ（重要ポイント）

### 7.1 知識の確認（科目A-2向け）

- **COSOフレームワーク**（トレッドウェイ委員会組織委員会、1992〜1994年）：3つの目的（業務の有効性と効率性、財務報告の信頼性、関連法令等の遵守）と5つの構成要素（統制環境、リスクアセスメント、統制活動、情報及び伝達、監視活動）。2013年改訂で17の原則、目的は「報告」へ拡張。
- **日本の枠組み**：4つの目的と6つの基本的要素。日本独自は目的の「**資産の保全**」と要素の「**ITへの対応**」。2023年改訂で「財務報告の信頼性」は「報告の信頼性」に。
- **統制環境**は他のすべての基本的要素の基礎。**モニタリング**は日常的モニタリングと独立的評価（内部監査）。
- **内部統制の限界**：判断の誤り・不注意・共謀、想定外の環境変化・非定型取引、費用と便益の比較衡量、経営者による無視・無効化。
- **CSA**（統制自己評価）：業務の担当者自身が統制を評価する手法。
- **会社法**（2006年5月施行）：第362条で大会社の取締役会設置会社に内部統制システムの基本方針の決定を義務付け（非設置は第348条）。大会社＝資本金5億円以上又は負債200億円以上。2015年施行の改正で企業集団へ拡大・多重代表訴訟・監査等委員会設置会社。2021年3月施行の改正で上場会社等の社外取締役の設置を義務化。
- **SOX法**（2002年、エンロン・ワールドコム事件が契機）：第302条＝経営者の宣誓、第404条＝内部統制の経営者評価と監査人の監査。
- **日本版SOX法**：狭義は金融商品取引法（2006年成立）。上場企業等に**内部統制報告書**の提出と公認会計士等による**内部統制監査**を義務付け、2008年4月1日以後開始の事業年度から適用。経営者の**確認書**も提出。
- **開示すべき重要な不備**：以前は「重要な欠陥」。日本の内部統制監査はダイレクト・レポーティングを採用しない。
- **ITへの対応**＝IT環境への対応＋ITの利用及び統制。
- **業務処理統制**：入力情報の完全性・正確性・正当性、エラーデータの修正と再処理、マスタ・データの正確性、アプリケーション内の認証・操作範囲の限定。
- **全般統制**：ITの開発・保守、システムの運用・管理、内外からのアクセス管理等の安全性の確保、外部委託に関する契約の管理。ISMSやセキュリティ対策は全般統制の構成要素。
- **3点セット**：業務記述書、業務フロー図、RCM（リスクと統制の対応表）。
- **COBIT 2019**：ISACA（とITGI）。ガバナンス（EDM）とマネジメント（APO・BAI・DSS・MEA）を区別、5ドメイン40プロセス。

### 7.2 記述式で問われる観点（科目B向け）

- **全般統制の不備を指摘する**：「開発者が本番環境のプログラムを承認なく変更できるため、業務処理統制として組み込んだ入力チェックが無効化されても検知できない。」変更申請・承認、開発環境と本番環境の分離、本番移行担当者と開発者の職務分離を対策として挙げる。
- **共用IDの問題点を答える**：「管理者IDを複数人で共用しているため、操作を行った者を特定できず、不正な操作の抑止と事後の追跡ができない。」対策は個人別ID、特権ID使用時の事前承認と操作ログの事後確認。
- **アクセス権棚卸しの目的を書く**：「異動・退職者の不要な権限を削除し、職務に必要な最小限の権限に保つため、システム管理者は定期的に利用者権限を所属・職務と照合し、結果を承認者が確認する。」
- **職務分離が必要な理由を書く**：「一人の担当者が入力と承認を兼ねると、誤りや不正を他者が発見できないため、入力者と承認者を分け、システムの権限設定で操作範囲を限定する。」
- **外部委託・クラウドの統制を答える**：「委託先が運用するシステムも全般統制の評価対象であるため、委託元は契約で管理体制や報告義務を定め、委託先の統制の状況を確認する。」2023年改訂でITの委託業務に係る統制の重要性が強調された点を根拠にできる。
- **統制の限界を踏まえた対策を書く**：共謀や経営者による無効化は通常の統制では防げないため、内部通報窓口（情報と伝達）、取締役会・監査役等による監督、内部監査による独立的評価を組み合わせる。
- **監査人としての指摘の書き方**：第4章 4.10 と同じく、「事実（監査証拠）→ 基準とのずれ → リスク → 改善提案」の順で書く。例：「会計システムの管理者IDが共用されている（事実）。個人別IDを付与すべきとする規程に反する（基準）。不正な仕訳を行った者を特定できない（リスク）。個人別IDへ切り替え、特権ID使用時の承認とログ確認を行う必要がある（改善提案）。」

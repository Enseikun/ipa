# ポートスキャン

## 2.2 ポートスキャン

ポートスキャンとは、ターゲットとなるホスト上で開いている（通信可能な状態になっている）ポートをスキャン（探査）することである。ここでは、ポートスキャンの目的と実行方法、その仕組みと対策を解説する。

### 2.2.1 ポートスキャンの目的と実行

ポートスキャンでは、ターゲットホストの各ポートに対してパケットを送信し、その応答から、ポートがアクティブ状態（サービスが稼働し、通信を受け付けている状態）か、非アクティブ状態かを判断する。

TCPコネクションを確立するタイプのポートスキャンでは、単にポートの状態を確認するだけでなく、ターゲットホストが返すバナー情報から、そのポートに対応したサービスを提供しているアプリケーションの種類やバージョンなども確認できる。また、稼働しているアプリケーションの種類や、ターゲットホストの振る舞い（アクセス要求に対する応答の仕方など）から、OSの種類やバージョンまで推定することも可能である。このような手法を**スタックフィンガープリンティング**とも呼ぶ。

> **バナー（banner）**
> バナーは旗、横断幕を意味し、Webの分野ではホームページ上の広告画像などを指す。本書では、サーバプログラムが接続時などに返すメッセージ（アプリケーション名やバージョン番号などを含む識別情報）の意味として使用している。

#### ポートスキャンの目的

ポートスキャンを行うことによって、次のようなサービスを見つけることができる。

##### セキュリティ上問題のあるサービス

もともとイントラネットなどの閉じたネットワークの中で使用することを前提としたプロトコルやサービスは数多くある。仮にそうしたサービスがインターネットから利用可能であれば、その機能上の脆弱さから侵入や攻撃が容易に行える可能性があるため、侵入者にとっては非常に好都合である。機能上の脆弱さからインターネットに公開すべきではないサービスの例を表に示す。

**表：インターネットに公開すべきではないサービスの例**

| サービス名 | ポート番号 | 概要 |
| --- | --- | --- |
| telnet | 23 | Telnet |
| tftp | 69 | 簡易FTPサービス |
| pop3 | 110 | メール受信 |
| sunrpc | 111 | SUN Remote Procedure Call |
| epmap | 135 | DCE準拠のRPC |
| netbios-ns | 137 | NetBIOS名前サービス |
| netbios-dgm | 138 | NetBIOSデータ通信 |
| netbios-ssn | 139 | NetBIOSセッション通信 |
| snmp | 161 | SNMP（ネットワーク管理） |
| snmptrap | 162 | SNMP（ネットワーク管理：異常報告用） |
| microsoft-ds | 445 | ダイレクトホスティングSMBサービス |
| rexec | 512 | UNIX環境のリモートコマンド実行 |
| rlogin | 513 | UNIX環境のリモートログインサービス |
| rsh | 514 | リモートシェル（TCP） |
| syslog | 514 | シスログ（UDP） |
| ms-sql-s | 1433 | Microsoft SQL Server |
| ms-sql-m | 1434 | Microsoft SQL Monitor |
| nfs | 2049 | Network File System - Sun Microsystems |

> **補足**
> rsh と syslog はいずれもポート番号514を使用するが、rsh はTCP、syslog はUDPであり、トランスポート層のプロトコルが異なるため別のサービスとして扱われる。

##### 既知のセキュリティホールをもつサービス

一般的に利用されている市販ソフトウェアやフリーウェアなどには、既知のセキュリティホール（脆弱性）が数多くある。通常は開発元が提供しているパッチを適用したり、バージョンアップを行ったりすることによって対策は可能だが、そうした対処が行われずにインターネット上に公開されているホストも数多い。前述のように、ターゲットホストからのバナー情報を調べることにより、セキュリティホールをもつサービスが稼働していることを確認できる可能性がある。

#### ポートスキャンの実行

ポートスキャンは、nmapに代表される専用のツールを用いることで、特別な知識がなくても容易に実行できる。こうしたツールが無償で容易に入手可能であることに加え、ワームやトロイの木馬に組み込まれている場合も多い。そのため、インターネット上では無差別的に実行されたポートスキャンのパケットが絶えず飛び交っているのが実情である。

> **nmap（Network Mapper）**
> オープンソースで公開されている代表的なポートスキャンツール。TCPコネクトスキャン、SYNスキャン、UDPスキャン、各種ステルススキャンのほか、OSやサービスのバージョン検出機能も備えている。本来はネットワーク管理者によるセキュリティ診断のためのツールである。

### 2.2.2 ポートスキャンの種類と仕組み

ポートスキャンには、その仕組みによってTCPコネクトスキャン、SYNスキャン（TCPハーフスキャン）、UDPスキャンなどの種類がある。

#### TCPコネクトスキャン

TCPのポート（サービス）を対象とした手法であり、3ウェイハンドシェイクによってターゲットポートとTCPコネクションを確立できるかどうかによって状態を確認する。多くのツールが存在することから、最もよく使われている手法である。ポートが開いている場合にはコネクションを確立するため、ターゲットサーバのログに記録される。したがって、サーバのログを分析することによって、ポートスキャンを受けたことを確認できる可能性がある。

**図：TCPコネクトスキャンのイメージ**

```
攻撃者                              ターゲット
  |  ---- SYN（接続要求） -------->  |
  |  <--- SYN/ACK（アクティブ状態）- |   ※非アクティブ状態の場合は RST/ACK
  |  ---- ACK -------------------->  |   → コネクション確立（ログに記録される）
```

#### SYNスキャン（TCPハーフスキャン）

TCPのポートを対象とした手法であり、3ウェイハンドシェイクの最初のSYNパケットだけを送信し、ターゲットからSYN/ACKが返ってきた場合はアクティブ状態、RST/ACKが返ってきた場合は非アクティブ状態と判断する。アクティブ状態であった場合でもACKは返信せず、RSTを返信するため、コネクションは確立されない。そのため、ターゲットホストのログには記録されない。侵入者が、自身の行為を発見されにくくするために用いる手法であり、**ステルススキャン**とも呼ばれる。

> **試験に出た**
> 情報セキュリティスペシャリスト試験の午後問題において、SYNスキャンに関する問題が出題されている。

**図：SYNスキャンのイメージ**

```
攻撃者                              ターゲット
  |  ---- SYN（接続要求） -------->  |
  |  <--- SYN/ACK（アクティブ状態）- |   ※非アクティブ状態の場合は RST/ACK
  |  ---- RST -------------------->  |   → コネクションは確立されない（ログに残らない）
```

#### UDPスキャン

UDPでは、通信にあたってコネクションを確立する手順が省略されている。そのため、TCPに比べポートスキャンの手段が限られる。UDPスキャンでは、ターゲットポートにデータ（パケット）を送り、その結果、何の応答もなければアクティブ状態、「ICMP port unreachable」が返ってきた場合は非アクティブ状態と判断する。また、UDPアプリケーションの仕様によっては特定の応答を返すものもあるため、それを利用してUDPスキャンの精度を高めることも可能である。

**図：UDPスキャンのイメージ**

```
攻撃者                              ターゲット
  |  ---- データ ------------------>  |
  |  <--- ICMP port unreachable ---- |   → 非アクティブ状態
  |       （応答なし）                |   → アクティブ状態
```

> **補足**
> UDPスキャンでは「応答なし」をアクティブ状態とみなすため、途中のファイアウォールでパケットが破棄された場合やパケットが消失した場合もアクティブ状態と誤判定されることがある。このため、TCPのスキャンに比べて精度が低くなりやすい。

#### その他のステルススキャン

SYNスキャン以外にも、ターゲットホストのログに記録されにくいステルススキャンとして、次の表のような手法もある。これらはいずれも、TCPの正常なコネクションではあり得ないパケットを送ることにより、ターゲットポートの状態を判別するものである。

**表：ステルススキャンの手法**

| 種類 | 内容 |
| --- | --- |
| FINスキャン | FINフラグをONにしたパケットを送り、それに対する反応からポートの状態を判別する |
| ACKスキャン | ACKフラグをONにしたパケットを送り、それに対する反応からポートの状態を判別する |
| Nullスキャン | コードビットのすべてのフラグをOFFにしたパケットを送り、それに対する反応からポートの状態を判別する |
| クリスマスツリースキャン | FIN、PSH、URGのフラグをすべてONにしたパケットを送り、それに対する反応からポートの状態を判別する |

> **補足**
> FINスキャン、Nullスキャン、クリスマスツリースキャンでは、一般に、非アクティブ状態のポートはRSTを返し、アクティブ状態のポートは応答しない（パケットを破棄する）というRFC 793の仕様を利用している。ただし、OSの実装によってはこの仕様どおりに動作しないものもある。ACKスキャンは主に、ファイアウォールによってパケットがフィルタリングされているかどうかを調べる目的で用いられる。

### 2.2.3 ポートスキャンへの対策

ポートスキャンは調査行為であり、ポートスキャンのみでシステムへの侵入を許したり、データが破壊されたりすることはない。したがって、次に挙げる予防・防止対策が行われていれば特に問題はない。しかし、そうでない場合には、ポートスキャンを受けることによって多くの脆弱性を露呈し、本格的な攻撃を受けることにつながることも十分にあり得る。

#### 予防・防止

- 不要なサービスを停止する（ポートを閉じる）
- OS及びアプリケーションのバージョンを最新化し、パッチを適用する
- 脆弱性検査を実施し、セキュリティホールが塞がれていることを確認する
- ファイアウォールを用いて、外部からの不要なポートへのアクセスを遮断する

#### 検知・追跡

- IDSやIPSを用いて検知する
- ファイアウォールのログから検知する
- ホストのログから検知する（TCPコネクトスキャンの場合）

IDSやIPSを用いると、SYNスキャンなどのステルススキャンについても検知することが可能である。一方、各ポートへのアクセスを連続して行うのではなく、1ポートごとにある程度の時間を空け、かつポート番号をランダムに選択して行われた場合などは、検知が非常に困難である。

> **IDS（Intrusion Detection System）**
> 侵入検知システム。ネットワークを流れるパケットや、ホスト上の各種イベント（ログイン、プログラムの実行など）をリアルタイムに監視して、不正なアクセスや異常を検知し、管理者に通知する製品。

> **IPS（Intrusion Prevention System）**
> 侵入防止システム。従来のネットワーク型IDSやファイアウォールに、不正アクセスを防御する機能を追加したもの。不正アクセスを検知するだけでなく、遮断まで行う。IPSはネットワーク型IDSと同様に、導入にあたっては新たにハードウェアを設置する必要がある。

#### 回復

- 予防・防止対策が万全であれば、ポートスキャンを受けても特に問題はないため、回復処置は不要である。予防・防止対策に不十分な箇所があれば対処する。

#### 理解度チェック

- **【Q1】** TCP、UDPによるポートスキャン方法の違いは何か。
- **【Q2】** 検知されやすいポートスキャン手法と、検知されにくいポートスキャン手法は何か。また、後者はなぜ検知されにくいか。
- **【Q3】** 検知されにくいポートスキャンへの対処方法にはどのようなものがあるか。

> **解答例**
>
> - **Q1**：TCPでは3ウェイハンドシェイクの応答（SYN/ACKかRST/ACKか）によってポートの状態を判別する。UDPではコネクション確立の手順がないため、データを送信し、応答がなければアクティブ状態、「ICMP port unreachable」が返ればそれを非アクティブ状態と判断する。
> - **Q2**：検知されやすいのはTCPコネクトスキャンである。検知されにくいのはSYNスキャンやFIN/Null/クリスマスツリースキャンなどのステルススキャンであり、TCPコネクションを確立しないため、ターゲットホストのログに記録されないからである。
> - **Q3**：IDSやIPSを導入してネットワーク上のパケットを監視する。また、ファイアウォールのログを分析する。

## 確認問題

TCPのコネクション確立方式である3ウェイハンドシェイクを表す図はどれか。

［情報処理安全確保支援士試験・平成30年度］

### 解答・解説

TCPの3ウェイハンドシェイクとは、「3ウェイ」の名が示すように、次の①～③の3回のパケットのやり取りによってコネクションを確立する方式である。

1. SYN（要求元が送信）
2. SYN/ACK（要求先が送信）
3. ACK（要求元が送信）

```
要求元（クライアント）              要求先（サーバ）
  |  ---- ① SYN ------------------>  |
  |  <--- ② SYN/ACK --------------- |
  |  ---- ③ ACK ------------------>  |
  |      コネクション確立             |
```

したがって、要求元からSYN、要求先からSYN/ACK、要求元からACKの順にパケットが送信されている図が正解となる。

> **補足**
> ①のSYNでは要求元が自身の初期シーケンス番号を通知し、②のSYN/ACKでは要求先がこれに対する確認応答（ACK）と自身の初期シーケンス番号（SYN）を同時に通知する。③のACKで要求元が要求先のシーケンス番号に対する確認応答を返すことで、双方向の通信路が確立される。

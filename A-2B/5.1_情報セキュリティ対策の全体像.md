## 0. 全体像 ― なぜこの分野を学ぶのか

### 0.1 第2〜4章から第5章へ

第2章では、ポートスキャン、バッファオーバフロー、パスワードクラック、DoS攻撃、Webアプリケーションへの攻撃、マルウェアといった様々な**脅威**を扱いました。第3章では、それらの脅威につけ込まれるネットワーク構成・プロトコル・Webアプリケーションの**脆弱性**を扱い、第4章では、組織としてリスクを評価し対策を決めて運用する**マネジメント**を学びました。本章（第5章）からは、それらに対する具体的な**対策技術**を解説します。

ただ、ファイアウォール、IDS、WAF、サンドボックスと個々の製品を順に覚えていくと、「どれが何を防ぐのか」「なぜ全部必要なのか」がすぐにわからなくなります。そこで本ノートでは、個々の対策技術を学ぶ前に、その**全体像**をとらえておきます。本ノートは第5章全体の「地図」の役割を果たします。

## 1. セキュリティ対策を分類する2つの物差し

各種のセキュリティ対策技術は、次の2つの観点から分類することができます。

1. **セキュリティの要素（機密性、完全性、可用性）からの分類**
   - 機密性・完全性の侵害への対策
   - 可用性の低下への対策
2. **セキュリティ対策の機能・効果からの分類**
   - 予防の働きをする対策
   - 防止・防御の働きをする対策
   - 検知・追跡の働きをする対策
   - 回復の働きをする対策

1つ目の物差しは「**何を守るか**」、2つ目の物差しは「**いつ、どう働くか**」です。2つを縦横に組み合わせると、対策を表の升目に置くことができ、「この升目が空いている＝この種類の対策が足りない」と気づけるようになります。

### 1.1 セキュリティの要素（CIA）

> **機密性（Confidentiality）**：許可された者だけが情報にアクセスできる状態を確保すること。
> **完全性（Integrity）**：情報が正確かつ完全であり、改ざんや破壊を受けていない状態を確保すること。
> **可用性（Availability）**：許可された者が、必要なときに情報や関連資産を利用できる状態を確保すること。
> これら3つの要素は、頭文字をとって「**CIA**」と呼ばれる。

分類表で「機密性・完全性の侵害」をひとまとめにしているのは、攻撃者が侵入に成功すると、情報を盗む（機密性）ことも書き換える（完全性）こともできるようになるため、対策の多くが両方に効くからです。これに対して「可用性の低下」は、DoS攻撃や機器故障のように侵入しなくても起こるため、冗長化や帯域の確保といった別系統の対策が必要になります。

### 1.2 対策の機能 ― 1.2 の4機能との対応

本ノートの分類では、機能を「予防」「防止・防御」「検知・追跡」「回復」の4つに分けています。1.2「情報セキュリティの特性と基本的な考え方」で学んだ4機能（抑止・抑制、予防・防止、検知・追跡、回復）とは区切り方が少し違うので、対応を整理しておきます。

| 本ノート（技術の分類） | 1.2 の4機能 | 働き | 典型例 |
|---|---|---|---|
| ―（技術ではなく人に働きかけるため、第5章の対象外） | **抑止・抑制** | 人の意識に働きかけ、不正を思いとどまらせる | 監視の告知、罰則規定（4.7） |
| **予防** | **予防・防止** | 攻撃を受ける**前に**弱点（脆弱性）をなくしておく | 要塞化、パッチ適用、脆弱性診断、暗号化 |
| **防止・防御** | 同上 | 攻撃が来た**その場で**止める | ファイアウォール、IPS、WAF、認証 |
| **検知・追跡** | **検知・追跡** | 攻撃や異常に気づき、記録して追う | IDS、ウイルス対策ツール、ログ分析、改ざん検出 |
| **回復** | **回復** | 被害を受けた状態から元に戻す | バックアップからの復旧、フェールオーバ |

つまり、本ノートは1.2 の「予防・防止」を、**事前に弱点を塞ぐ「予防」**と、**攻撃の瞬間に通さない「防止・防御」**に分けて細かく見ている、ということです。技術を分類するときにはこの区別が役に立ちます。たとえば、パッチ適用（予防）はファイアウォールを通過した攻撃にも効き、ファイアウォール（防止・防御）はパッチ未適用のサーバへの攻撃も一部止めます。両者は補い合う関係で、どちらか一方では足りません。

## 2. 情報セキュリティ対策の分類表

上記の観点で主なセキュリティ対策を分類した例を、次の表に示します。

### 2.1 表：情報セキュリティ対策の分類

| セキュリティ要素 | 機能 | 情報セキュリティ対策の例 |
|---|---|---|
| 機密性・完全性の侵害 | 予防 | ・**ホストの要塞化**（バージョンアップ、パッチ適用、不要なアカウントやサービスの停止・削除など）<br>・十分なセキュリティ機能を有する製品（**Trusted OS**など）の使用<br>・**脆弱性診断**の実施<br>・機密データの暗号化（通信経路、ハードディスク） |
| | 防止・防御 | ・システム＆ネットワーク構成面での対策（アクセス制御設計、**DMZ**の設置など）<br>・**ファイアウォール**による防御（アクセス制御）<br>・認証システムによる防御<br>・**サンドボックス**、侵入防御システムによる防御<br>・Webアプリケーションファイアウォールによる防御 |
| | 検知・追跡 | ・侵入検知システム、侵入防御システムによる検知<br>・ウイルス対策（AV）ツールによるウイルス検知<br>・ハッシュ関数、**MAC**、デジタル署名（改ざん検出）<br>・ログからの検知・追跡 |
| | 回復 | ・システムの再構築<br>・バックアップデータによる復旧 |
| 可用性の低下 | 予防 | ・回線の二重化、機器の冗長化・**クラスタリング**<br>・十分な帯域と品質をもつ回線の確保<br>・十分な処理能力と耐障害性能を有する機器の使用<br>・**CDN**サービス、DDoS対策サービスの利用<br>・脆弱性診断（DoSの耐性診断）の実施<br>・定期保守点検作業の実施<br>・システム＆ネットワーク設計・構築面での対策（ボトルネックの排除など） |
| | 防止・防御（緩和） | ・負荷分散の実施<br>・ルータやスイッチによる帯域制御<br>・ファイアウォールによるDoS攻撃の排除<br>・侵入防御システムによるDoS攻撃の排除 |
| | 検知・追跡 | ・稼働監視システムによる障害の検知<br>・侵入検知システム、侵入防御システムによるDoS攻撃の検知 |
| | 回復 | ・待機系への切替え（**フェールオーバ**）<br>・障害機器の修理・交換、バックアップデータによる復旧 |

> **MAC**（Message Authentication Code）：メッセージ認証コード。共通鍵を用いてメッセージから生成される認証用のデータで、改ざんの検出と送信者の確認に利用される（第7章で詳しく扱う）。
> **CDN**（Content Delivery Network）：コンテンツを地理的に分散した多数のキャッシュサーバから配信する仕組み。アクセスの集中を分散させるため、DDoS攻撃の緩和にも役立つ。
> **クラスタリング**：複数のコンピュータを連携させて一つのシステムとして動作させ、処理能力や耐障害性を高める技術。

### 2.2 分類表の読み方

この表から、試験や実務で役立つ3つのことが読み取れます。

**1つの技術が複数の升目に現れる**：侵入防御システム（IPS）は、機密性・完全性の「防止・防御」「検知・追跡」と、可用性の「防止・防御（緩和）」「検知・追跡」の4か所に登場します。ファイアウォールも機密性・完全性の防止・防御と、可用性のDoS排除の両方に現れます。支援士は、製品名から機能を1つに決めつけず、「この事例でその製品はどの働きを期待されているか」を読み取るべきです。

**可用性の防御は「緩和」にとどまる**：可用性の防止・防御には「（緩和）」と付いています。大規模なDDoS攻撃では、回線そのものが攻撃トラフィックで埋まってしまうため、組織の入口にあるファイアウォールやIPSで遮断しても、正規の利用者の通信も届かなくなります。組織が自前でできるのは影響を和らげることまでで、根本的な対処には、ISPのDDoS対策サービスやCDNのように、**上流で**攻撃を吸収する仕組みが必要になります（2.7 参照）。

**回復の対策は技術より準備**：回復の升目にある「システムの再構築」「バックアップデータによる復旧」は、製品を導入すれば済むものではありません。システム管理者は、バックアップを取得し、復元手順書を用意し、実際に戻せるかを訓練で確かめておくべきです。これは4.9 で学んだBCPのRTO・RPOと直結します。

### 2.3 分類を使って「足りない対策」を見つける

分類表の本当の使い道は、事例の対策を升目に置いて、**空いている升目**を見つけることです。たとえば、ある会社のWebサイトの対策が次のようだったとします。

```
【A社 ECサイトの現状の対策（事例の記述を整理したもの）】
  ・ファイアウォールで 443/TCP 以外を遮断している        → 機密性・完全性／防止・防御
  ・Webサーバは月1回パッチを適用している                 → 機密性・完全性／予防
  ・DBは毎晩フルバックアップを取得し、遠隔地へ保管している → 機密性・完全性／回復、可用性／回復
  ・Webサーバのアクセスログは取得しているが、誰も見ていない → 検知・追跡（形だけ）
```

升目に置くと、「検知・追跡」がほぼ空で、攻撃を受けても気づけない状態だとわかります。また、443/TCP で届くSQLインジェクションは、ファイアウォールでは止まりません（5.5）。したがって、支援士は「WAFを導入してHTTPの中身を検査する（防止・防御）」「ログを監視して異常を通知する仕組み（IDSやSIEM）を導入する（検知・追跡）」を提案すべきだ、という結論が導けます。科目Bの「追加すべき対策を、その理由とともに述べよ」という設問は、この考え方で解けます。

### 3.2 1つの攻撃を各層がどう見るか

多層防御の意味は、1つの攻撃が各層でどう見えるかを並べるとよくわかります。攻撃者が公開Webサーバに SQLインジェクションを仕掛けた場面を考えます。攻撃者は、データベースの情報を盗み出す目的で、検索フォームに次のような文字列を送ります。

```
GET /search?q=%27+OR+%271%27%3D%271 HTTP/1.1
Host: shop.example.jp
（URLデコードすると q=' OR '1'='1 ）
```

このとき、各層には次のような記録が残ります（形式は製品により異なる、例示です）。

```
[ファイアウォールのログ]  ── 443/TCP は許可ルールなので「通過」とだけ記録される
2026-09-30 02:14:05 ACCEPT TCP 198.51.100.77:50122 -> 203.0.113.10:443 rule=allow-web

[WAFのログ]  ── HTTPの中身を見て SQLインジェクションのシグネチャに一致、遮断
2026-09-30 02:14:05 BLOCK client=198.51.100.77 uri="/search?q=' OR '1'='1" rule="SQLi-942100" action=403

[Webサーバのアクセスログ]  ── WAFで止まったので、ここには届いていない（届いていれば 200 や 500 が残る）
```

ファイアウォールは「443番ポートへの通信」としか見ていないので通してしまいますが、WAFはHTTPの中身を見て止めます。もしWAFのシグネチャをすり抜けられても、Webサーバが要塞化され、アプリケーションがプレースホルダを使っていれば（第8章）、攻撃は成立しません。さらにそれも破られたら、IDSやログ監視が異常に気づきます。このように、**どの層も単独では完璧でないことを前提に、層を重ねて突破の確率を下げる**のが多層防御です。

## 4. 本章で解説する対策技術

本章では、上記の対策のうち、次の技術について解説します。

- ホストの要塞化（5.2）
- 脆弱性診断（5.3）
- Trusted OS（5.4）
- ファイアウォール（5.5）
- ネットワーク型侵入検知システム（**NIDS**）（5.6）
- ホスト型侵入検知システム（**HIDS**）（5.6）
- 侵入防御システム（**IPS**）（5.7）
- Webアプリケーションファイアウォール（**WAF**）（5.8）
- サンドボックス（5.9）

これらは主に、機密性・完全性の侵害への対策となるものですが、それにとどまらず、可用性を確保するうえで非常に重要な役割をもつものもあります（ファイアウォールやIPSによるDoS攻撃の排除など）。

> **NIDS**（Network-based Intrusion Detection System）：ネットワーク上を流れるパケットを監視し、不正な通信を検知するシステム。
> **HIDS**（Host-based Intrusion Detection System）：監視対象のホスト上で動作し、ログやファイルの改ざん、不審なプロセスなどを検知するシステム。
> **IPS**（Intrusion Prevention System）：不正な通信を検知するだけでなく、その通信を遮断して侵入を防御するシステム。
> **WAF**（Web Application Firewall）：SQLインジェクションやクロスサイトスクリプティングなど、Webアプリケーションの脆弱性を狙った攻撃を検知・防御する仕組み。
> **サンドボックス**：外部から隔離された保護領域の中でプログラムを実行し、不正な動作がシステム全体に影響を及ぼさないようにする仕組み。

認証システムや暗号化は、分類表には登場しますが本章では扱いません。認証とアクセス制御は第6章、暗号・MAC・デジタル署名は第7章、セキュアプログラミングは第8章で扱います。

## 5. 確認問題

### 5.1 理解度チェック

- **Q1**：予防の働きをする対策にはどのようなものがあるか。
  - 解答例：機密性・完全性については、ホストの要塞化（バージョンアップ、パッチ適用、不要なアカウントやサービスの停止・削除）、Trusted OSなど十分なセキュリティ機能をもつ製品の使用、脆弱性診断、機密データの暗号化がある。可用性については、回線の二重化・機器の冗長化・クラスタリング、十分な帯域と処理能力の確保、CDN・DDoS対策サービスの利用、DoS耐性診断、定期保守点検、ボトルネックの排除がある。
- **Q2**：防止・防御の働きをする対策にはどのようなものがあるか。
  - 解答例：機密性・完全性については、アクセス制御設計やDMZの設置、ファイアウォール、認証システム、サンドボックス、IPS、WAFによる防御がある。可用性については、負荷分散、ルータやスイッチによる帯域制御、ファイアウォールやIPSによるDoS攻撃の排除（緩和）がある。
- **Q3**：検知・追跡の働きをする対策にはどのようなものがあるか。
  - 解答例：IDS・IPSによる侵入やDoS攻撃の検知、ウイルス対策ツールによるウイルス検知、ハッシュ関数・MAC・デジタル署名による改ざん検出、ログからの検知・追跡、稼働監視システムによる障害の検知がある。
- **Q4**：回復の働きをする対策にはどのようなものがあるか。
  - 解答例：システムの再構築、バックアップデータによる復旧、待機系への切替え（フェールオーバ）、障害機器の修理・交換がある。

### 5.2 過去問題：マスタファイル管理の監査項目

マスタファイル管理に関するシステム監査項目のうち、可用性に該当するものはどれか。

ア　マスタファイルが置かれているサーバを二重化し、耐障害性の向上を図っていること
イ　マスタファイルのデータを複数件まとめて検索・加工するための機能が、システムに盛り込まれていること
ウ　マスタファイルのメンテナンスは、特権アカウントを付与された者だけに許されていること
エ　マスタファイルへのデータ入力チェック機能が、システムに盛り込まれていること

> **解答・解説**
> 正解は**ア**。サーバの二重化は、障害発生時にもサービスを継続して利用できるようにするための対策であり、可用性に該当する。イはシステムの機能性（利便性）に関する項目、ウはアクセスを許可された者に限定する対策であり機密性（および完全性）に、エは誤ったデータの入力を防ぐ対策であり完全性に該当する。

この問題は、4.10 で学んだシステム監査の文脈で、本ノートの「CIAの物差し」を使う典型例です。分類表でいえば、アは「可用性の低下／予防（機器の冗長化）」の升目に入ります。

## 6. 試験対策まとめ（重要ポイント）

### 6.1 知識の確認（科目A-2向け）

- **2つの物差し**：セキュリティの要素（機密性・完全性の侵害／可用性の低下）と、機能（予防／防止・防御／検知・追跡／回復）。
- **1.2 の4機能との対応**：本ノートの「予防」と「防止・防御」は、1.2 の「予防・防止」を「事前に弱点を塞ぐ」と「攻撃の瞬間に止める」に分けたもの。「抑止・抑制」は人に働きかけるため技術の分類表には現れない。
- **CIAの識別**：二重化・冗長化・CDN＝可用性、入力チェック・ハッシュ・MAC・デジタル署名＝完全性、アクセス権の限定・暗号化＝機密性（アクセス権の限定は完全性にも効く）。
- **1つの技術が複数の機能をもつ**：IPSは検知と防御の両方、ファイアウォールはアクセス制御とDoS排除の両方。
- **可用性の防御は「緩和」**：大規模DDoSは自組織の機器だけでは防ぎきれず、CDNやDDoS対策サービスを併用する。
- **第5章の地図**：要塞化（5.2）・脆弱性診断（5.3）・Trusted OS（5.4）は予防、ファイアウォール（5.5）・IPS（5.7）・WAF（5.8）・サンドボックス（5.9）は防止・防御、IDS（5.6、NIDSとHIDS）は検知・追跡。
- **用語**：MAC＝共通鍵で生成し改ざん検出と送信者確認、CDN＝分散キャッシュ配信、クラスタリング＝複数台を1システムとして動かす。

### 6.2 記述式で問われる観点（科目B向け）

- **空いている升目を指摘する**：事例の対策を「機能」で分類し、「予防と防御はあるが検知がないため、侵入に気づけない」のように不足を言語化する。
- **対策と機能を1文で結ぶ**：「WAFを導入する。ファイアウォールが通過させるHTTP通信の中身を検査し、SQLインジェクションを遮断するため」のように、何を・なぜ・どの層で補うかを書く。
- **製品の限界を理由にする**：「ファイアウォールは443/TCPへの通信を許可しているため、HTTPの中身に含まれる攻撃は防げない」のように、各製品が「何を見て、何を見ないか」を根拠にする。
- **可用性の対策を忘れない**：機密性・完全性の議論に偏らず、冗長化・フェールオーバ・バックアップからの復旧（RTO・RPO）まで視野に入れる。

# 情報セキュリティマネジメントの実践

## 4.2 リスクマネジメントとリスク対応

業務や情報システムには様々なリスクが潜んでいる。これらを分析・評価し、適切な処置を講じることで、損失が発生する可能性を最小限にとどめる必要がある。そのために組織を指揮・管理して行う一連の活動が**リスクマネジメント**である。リスク分析やリスクアセスメントも、リスクマネジメントを構成するプロセスの一つと位置付けることができる。

一方、リスクアセスメントによって洗い出されたリスクに対処することを**リスク対応**(リスク対策、リスク処理)という。ここでは、リスクマネジメント全体の流れとリスク対応の概要について解説する。

### 4.2.1 リスクマネジメントのプロセス

リスクマネジメントには、次の四つのプロセスがある。

1. リスクアセスメント
2. リスク対応方法の洗出し
3. リスク対応の実施
4. リスク及びリスク対応方法の見直し

企業環境や情報システムを取り巻くリスクは常に変化している。また、IT化の進展や組織の拡大に伴って増え続けている。こうしたリスクの変化に対処するためには、各プロセスを一度きりで終わらせてはならない。継続的に繰り返し実行していく必要がある。

```mermaid
flowchart LR
    A["①リスクアセスメント"] --> B["②リスク対応方法の洗出し"]
    B --> C["③リスク対応の実施"]
    C --> D["④リスク及びリスク対応方法の見直し"]
    D --> A
```

#### ① リスクアセスメント(リスク分析・リスク評価)

リスクアセスメントとは、4.1.3項で解説したように、次の作業を行うことである。

- 顕在化すれば損失をもたらすリスクが、対象となる組織や情報システムのどこに、どのように潜在しているのかを発見・確認する。
- そのリスクの大きさを測定・評価する。

> **リスクアセスメント**:JIS Q 31000では、リスク特定・リスク分析・リスク評価を網羅するプロセス全体を指す。リスクの大きさは、一般に「発生可能性(頻度)」と「影響度(損失の大きさ)」の組合せで評価される。

#### ② リスク対応方法の洗出し

リスクアセスメントの結果を受けて、損失を最小限に抑えるための適切なリスク対応方法を洗い出す。なお、リスク対応については4.2.2項で解説する。

#### ③ リスク対応の実施

洗い出したリスク対応方法の中から、予算や組織体制などとの兼ね合いを考慮して、実際に実施するリスク対応策(セキュリティ対策)を決定し、実施する。決定したリスク対応方法は、情報セキュリティポリシにも確実に反映させる必要がある。

#### ④ リスク及びリスク対応方法の見直し

リスクそのものと、実施済みのリスク対応方法を定期的に見直す。必要に応じて改善することで、リスク対応の効果を維持する。

> 見直しのきっかけには、定期的なレビューのほか、新たな脅威や脆弱性の発見、システムの変更、組織改編、セキュリティインシデントの発生などがある。

### 4.2.2 リスク対応の概要

リスクアセスメントはリスクマネジメントの中でも重要なプロセスである。しかし、その後の対応方法が間違っていれば、アセスメントの意味はなくなる。次の要素を考え合わせて、最適なリスク対応方法を決定することが重要である。

- リスクの大きさ
- リスクの特性
- 顕在化の可能性
- 情報資産の重要度
- 予算

リスク対応は、大きく**リスクコントロール**と**リスクファイナンシング**に分けられる。

#### リスクコントロール

リスクコントロールとは、リスクの発生を抑止したり、リスクが顕在化した場合の損失を低減したりするための対処である。物理的対策・技術的対策・運用管理的対策といった、一般にセキュリティ対策と呼ばれるものがこれに該当する。

**リスクコントロールの具体例**

| 分類 | 具体例 |
|---|---|
| 物理的対策 | 入退室管理設備、防火・防水・耐震設備、無停電電源設備(UPS) |
| 技術的対策 | アクセス制御、暗号化、ユーザ認証、マルウェア対策 |
| 運用管理的対策 | 情報セキュリティ方針・基準の策定と運用、セキュリティ教育の実施、不測事態の発生に備えた訓練の実施、セキュリティ監査 |

#### リスクファイナンシング

リスクファイナンシング(「リスクファイナンス」ともいう)は、リスクの発生を抑止したり損失を低減したりするための対処ではない。リスクが顕在化して損失が発生した場合に備えて、損失の補填や対応費用などを確保しておくことである。

リスクコントロールをどれだけ施しても、リスクが顕在化する可能性をゼロにすることはできない。そのため、不測事態の発生に備えて資金面での対策を講じておくことも非常に重要である。

大規模な地震のように、発生頻度は低いものの、発生すれば甚大な被害をもたらすと想定されるリスクもある。こうしたリスクには、リスクコントロールに加えて、保険をかけるなどのリスクファイナンシングによる対策を講じておくことが望ましい。

**リスクファイナンシングの具体例**

- 保険を利用して、不測事態発生時の対応費用を組織外に転嫁する。
- 不測事態の発生に備えて、引当金・準備金・積立金などの名目で組織内に対応費用を確保する。

#### リスクの受容

リスクアセスメントの結果に基づき、リスクの大きさや特性を踏まえてリスク対応方法が決まる。

リスクの存在を認識していても、その強度や予算などとの兼ね合いから、あえて対処を行わないという選択をすることもある。これが**リスクの受容**(リスク受容、リスク保有)である。リスクの受容にあたっては、組織としての判断基準(リスク受容基準)をあらかじめ明確に定めておく必要がある。

> **リスク受容基準**:どの程度のリスクであれば対策を講じずに受け入れるかを示す、組織としての判断基準。経営陣の承認を得て定めることが一般的である。受容したリスクは「残留リスク」として認識し、継続的に監視する。

### 4.2.3 リスク対応手法の種類

リスク対応で用いられる各種の対策は、その考え方やリスクへのアプローチ方法によって、幾つかの手法に分類できる。リスクの特性や組織の状況に応じて、適切な対応手法を選択する必要がある。

#### リスクコントロールにおける対応手法

リスクコントロールにおける対応手法は、大きく次の三つに分類できる。

1. リスク回避
2. リスク低減
3. リスク移転

このうちリスク低減は、さらに損失予防、損失軽減、リスク分離(分割)、リスク集中(結合)に分類できる。

**表:リスクコントロールにおける対応手法の例**

| 手法 | | 説明 | 具体例 |
|---|---|---|---|
| リスク回避 | | リスク発生の根本原因(作業、事象など)を排除することによってリスクを処理する方法 | インターネットからの不正アクセスのリスクを処理するために、インターネットへの接続自体を取りやめる |
| リスク低減 | 損失予防 | 損失の発生頻度を減少させることによってリスクを処理する方法 | 保守点検を徹底して、機器故障の発生を防ぐ |
| | 損失軽減 | 損失の度合いを小さくすることによってリスクを処理する方法 | 持ち出し用PCに保存するデータを必要最小限にすることで、紛失・盗難時の損失を軽減する |
| | リスク分離(分割) | 損失を受ける資産や資源を小さな単位に分化・分散することによってリスクを処理する方法 | 処理の分散化や、マシンルームの分散配置(バックアップサイトの設置など) |
| | リスク集中(結合) | 資産や資源を一か所に集中させ、管理を強化・効率化することによってリスクを処理する方法 | 分散していたサーバをデータセンタに集約し、集中管理する |
| リスク移転 | | 契約などによって、リスクを伴う業務や資産の管理を第三者に移すことによってリスクを処理する方法 | システムの運用を外部の専門業者に委託(アウトソーシング)する |

#### リスクファイナンシングにおける対応手法

リスクファイナンシングにおける対応手法には、次の二つがある。

1. リスク保有
2. リスク移転

リスク移転はリスクコントロールの手法にもあるが、リスクファイナンシングにおけるリスク移転とは意味合いが異なる。リスクコントロールでは業務や管理そのものを第三者に移すのに対し、リスクファイナンシングでは損失の金銭的な負担を外部に移す。

**表:リスクファイナンシングにおける対応手法の例**

| 手法 | 説明 | 具体例 |
|---|---|---|
| リスク保有 | リスクが顕在化したときに発生する損失を、組織自体の財務力で負担する方法 | 引当金・準備金・積立金などの名目で、不測事態の対応費用を確保する |
| リスク移転 | 損失負担のリスクを外部に転嫁する方法 | 保険を利用する |

#### PMBOKにおけるリスク対応戦略

PMI(Project Management Institute)が発行しているプロジェクトマネジメントの知識体系PMBOK(Project Management Body of Knowledge)では、リスクへの対応を「リスク対応戦略」として次のように分類している。

| 戦略 | 内容 |
|---|---|
| 回避 | リスクの影響を避けること |
| 転嫁 | リスクの影響を第三者に移転すること |
| 軽減 | リスクの発生確率と影響度を、受容できるレベルまで低減すること |
| 受容 | リスクの影響を受け入れること |

> PMBOKでは、上記のマイナスのリスク(脅威)に対する戦略に加えて、プラスのリスク(好機)に対する戦略として「活用」「共有」「強化」「受容」も定義されている。

#### リスクマネジメントに関する規格

**ISO 31000:2018 / JIS Q 31000:2019(リスクマネジメント-指針)**

あらゆる組織が、あらゆる種類のリスクを運用管理するための汎用的なプロセスを示した規格である。あわせて、そのプロセスを効果的に運用し、継続的に改善していくためのフレームワークも、PDCAの考え方に基づいて提示されている。

> **試験に出る**:情報処理安全確保支援士試験の平成30年度午前Ⅱ問3で、JIS Q 31000及びJIS Q 31010(リスクアセスメント技法)に基づくリスクアセスメントのプロセスに関する問題が出題されている。

> **JIS Q 31000におけるリスクマネジメントプロセス**:「適用範囲・状況・基準の確定」「リスクアセスメント(リスク特定・リスク分析・リスク評価)」「リスク対応」の各段階と、それらを支える「コミュニケーション及び協議」「モニタリング及びレビュー」「記録作成及び報告」から構成される。

### 確認問題

個人情報の漏えいに関するリスク対応のうち、リスク回避に該当するものはどれか。

- ア 個人情報の重要性と対策費用を勘案し、あえて対策をとらない。
- イ 個人情報の保管場所に外部の者が侵入できないように、入退室をより厳密に管理する。
- ウ 個人情報を含む情報資産を外部のデータセンタに預託する。
- エ 収集済みの個人情報を消去し、新たな収集を禁止する。

#### 解答・解説

**解答:エ**

リスク回避とは、リスク発生の根本原因(作業、事象など)を排除することによってリスクを処理する方法である。例えば、インターネットからのサイバー攻撃を受けるリスクを処理するために、インターネットへの接続自体を取りやめることが該当する。

選択肢エは、漏えいリスクの根本原因である「個人情報の保有」そのものをなくしているため、リスク回避に該当する。その他の選択肢は、次のとおりである。

- ア:リスク受容(リスク保有)に該当する。
- イ:リスク低減(損失予防)に該当する。
- ウ:リスク移転に該当する。

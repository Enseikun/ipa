# 情報セキュリティ対策技術(1) 侵入検知・防御

## 5.9 サンドボックス

従来のAV製品では検知が難しいマルウェアに対処するものとして、サンドボックス技術による振る舞い検知型のマルウェア対策製品が近年普及している。ここでは、その仕組みや構成の概要について解説する。

### 5.9.1 サンドボックスの概要

標的型攻撃によるマルウェア感染や情報流出等の被害が多発している。一方で、従来のパターンマッチングを中心としたAV製品では、巧妙に改造・偽装されたマルウェアをほとんど検知できず、対策として限界を迎えている。

そこで近年注目されているのが、サンドボックス技術による振る舞い検知型のマルウェア対策製品である。

サンドボックスとは、実環境から隔離されたセキュアな仮想環境のことである。システムの実環境に影響が及ばないように、実行できる機能やアクセスできるリソースを制限している。この環境でマルウェアの可能性がある不審なファイル等を実行させ、その振る舞いを観察することで、マルウェアであるかどうかを判定する。

サンドボックスの技術自体は従前からJava等でも採用されており、特に新しいものではない。しかし、それを実装したマルウェア対策製品(以下「サンドボックス製品」)をメールやWebの通信経路等に設置し、未知のマルウェアや既知のマルウェアの亜種等に対処する事例が増えてきている。

> **パターンマッチング型AV製品**
> 既知のマルウェアから抽出した特徴(シグネチャ/パターンファイル)と検査対象を照合して検知する方式である。既知のマルウェアには高い精度で対応できる。一方で、未知のマルウェアや、コードを少し改変しただけの亜種には対応が困難である。

> **振る舞い検知**
> プログラムを実際に動作させ、ファイルの生成・改ざん、レジストリの変更、外部との不審な通信、プロセスへのコード注入などの挙動を監視する。これらの挙動からマルウェアかどうかを判定する方式である。ヒューリスティック検知の一種とされる。

### 5.9.2 サンドボックス製品の種類と構成

一般的なサンドボックス製品の種類を表に示す。

**表:一般的なサンドボックス製品の種類**

| 種類 | 機能概要 |
|---|---|
| メール検査型 | ・メールに添付されたファイルからマルウェアを検知<br>・MTAとして動作させることで、マルウェアを検知したメールを遮断可能<br>・管理/連携サーバを介してWeb検査型サンドボックスと連携し、メール本文内の不正なURLリンクを検知 |
| Web検査型 | ・ミラーリングしたHTTP通信をサンドボックスで再現し、マルウェアのダウンロードやマルウェア感染端末からC&Cサーバとの通信(コールバック)等を検知<br>・RSTパケットによって、検知した通信の遮断を試みる |
| ファイル検査型 | ・ファイルサーバを定期的に巡回検査し、ファイルに感染したマルウェアを検知<br>・マルウェアを検知したファイルを隔離可能 |
| 管理/連携サーバ | ・メール検査型とWeb検査型の連携(URLリンクからのマルウェア検知)<br>・最新の脅威情報を入手して各サンドボックス製品に配布 |

続いて、サンドボックス製品の構成例を図に示す。

**図:サンドボックス製品の構成例(概略)**

```
          インターネット
                │
           [ファイアウォール]
                │
   ┌────────────┼──────────────────┐
   │            │                  │
[メール検査型]  [L2スイッチ]──(ミラーポート)──[Web検査型]
 (MTAとして    │
  インライン配置)│
   │        [プロキシ等]
   │            │
[メールサーバ]   │ 社内LAN ── [クライアント端末]
                │
         [ファイルサーバ] ←(定期巡回)── [ファイル検査型]

   [管理/連携サーバ] ⇔ 各サンドボックス製品(脅威情報配布・URL連携)
```

メール検査型のサンドボックスをMTAとして動作させることで、不審なメールを遮断することが可能となる。MTAではなくスイッチのミラーポートに接続する構成もあるが、その場合は検知のみとなり、遮断まではできない。

Web検査型のサンドボックスは、Webの通信パケットをミラーリングして仮想環境で再現する。これにより、マルウェアのダウンロードやC&Cサーバとの通信(コールバック)等を検知することが可能となる。

ファイル検査型のサンドボックスは、ファイルサーバを定期的に巡回検査し、ファイルに感染したマルウェアを検知して隔離することが可能となる。

管理/連携サーバは、主に次の役割を担う。

- メール検査型サンドボックスから受け取ったメール本文内のURLリンク情報をWeb検査型サンドボックスに連携し、検査を仲介する
- 最新の脅威情報を各サンドボックス製品に配布する

> **MTA(Mail Transfer Agent)**
> SMTPを用いてメールを転送・中継するソフトウェアやサーバのことである。サンドボックスをMTAとしてメール経路上にインライン配置すると、検査を終えるまでメールの配送を保留できる。そのため、マルウェアを検知した場合にメールを遮断できる。

> **C&Cサーバ(Command and Control サーバ)**
> マルウェアに感染した端末へ攻撃者が命令を送ったり、窃取した情報を受け取ったりするためのサーバである。感染端末からC&Cサーバへの接続は「コールバック」と呼ばれる。

> **RSTパケット**
> TCPのRSTフラグをセットしたパケットのことで、コネクションを強制的に切断する際に用いられる。ミラーポート接続のように通信経路上にない機器でも、通信の両端にRSTパケットを送り付けることで遮断を試みることができる。ただし、タイミングによっては遮断が間に合わない場合もあり、確実な方法ではない。

### 5.9.3 サンドボックス製品の機能上の限界及び運用上の課題

サンドボックス製品にも、他の侵入検知・防御製品と同様の問題や課題がある。

#### (1) 検知/遮断における課題

- フォールスポジティブ、フォールスネガティブが発生する可能性がある
- 暗号化されたファイル、パスワード付きのファイルは検査できない
- 暗号化されたWeb通信(HTTPS)は検査できない
- 不審なWeb通信を検知しても、遮断することは困難である

> **フォールスポジティブ/フォールスネガティブ**
> フォールスポジティブ(誤検知)は、正常なファイルや通信を不正と判定してしまうことである。フォールスネガティブ(検知漏れ)は、不正なファイルや通信を見逃してしまうことである。

> **サンドボックス回避(検知回避)技術**
> 近年のマルウェアの中には、仮想環境特有の痕跡(仮想デバイス名、特定のプロセス、マウス操作の有無など)を検出してサンドボックス内では不正な動作をしないものがある。また、一定時間が経過してから活動を開始するものもある。これらはフォールスネガティブの一因となる。

#### (2) 運用上の課題

- メール検査型をMTAとして接続する場合、添付ファイル等の検査処理によって、メールの配送に大幅な遅延等が発生する可能性がある
- 上記ケースにおいて、サンドボックス製品の単一障害によってメールが利用不可とならないような構成(冗長化等)をとる必要がある
- Web検査型、ファイル検査型、およびMTA接続しない場合のメール検査型においても、検査漏れや遅延を防ぐため、十分な処理能力を有する製品を選定する必要がある

> **単一障害点(SPOF:Single Point of Failure)**
> その箇所が停止するとシステム全体が停止してしまう構成要素のことである。インライン配置した機器は単一障害点になりやすい。そのため、冗長化やバイパス機能(障害時に通信を素通しさせる機能)などの対策が求められる。

## 0. 全体像 ― なぜこの分野を学ぶのか

1.5 では、クラウドによって「サーバが社外に出ていく」流れと、VDI や RBI によって「端末に情報を残さない」技術を学びました。本ノートでは、もう一方の変化、つまり「**人と端末が社外に出ていく**」流れを扱います。それがテレワークです。

従来の情報セキュリティは、「社員は社内のオフィスにいて、社内のPCから、社内のネットワークを通じて業務をする」ことを前提に組み立てられていました。ファイアウォールで社内と社外の境界を守り、入退室管理で物理的な境界を守れば、ほとんどの業務はその内側で完結していたのです。テレワークはこの前提を崩します。社員は自宅やカフェから、家庭用のWi-Fiや公衆無線LANを使い、場合によっては私物の端末で業務を行います。オフィスなら上司や同僚の目があり、施錠されたキャビネットがあり、情報システム部門が管理するネットワークがありましたが、自宅にはそのどれもありません。

本ノートは、次の流れで進みます。

1. **テレワークとは何か**：形態と、オフィス勤務との違いから生まれる固有のリスクを理解します。
2. **導入時に何を決めるか**：検討事項によってリスクと必要な対策がどう変わるかを見ます。
3. **どの方式で実現するか**：ITインフラから見た3つの実施方式を比較し、それぞれに必要な対策を整理します。
4. **何で守るか**：ルール・人・技術の3つの面から、テレワークのセキュリティ対策をまとめます。

本ノートの最後にたどり着く結論は、「境界の内側を信頼する」という従来の考え方だけでは、テレワークを安全に運用しきれない、ということです。それが次の 1.7 で学ぶ**ゼロトラスト**の出発点になります。

科目Bでは、令和3年度に「テレワーク環境で発生したセキュリティインシデント」、令和6年度に「リモートワークのセキュリティ対策とクラウドサービス利用のセキュリティ対策」が題材になっています。業務観点では「③利用におけるセキュリティ対策の適用（ネットワーク及び利用者エンドポイント機器のセキュリティ管理、アカウント管理）」と、インシデント事例では「④インシデント管理」に対応します。

## 1. テレワークの概要

### 1.1 テレワークとは

**テレワーク**とは、コンピュータやネットワークを活用して、時間と場所を有効に活用する柔軟な働き方・作業形態のことで、**リモートワーク**ともいいます。「テレ（tele＝離れた）」と「ワーク（work＝働く）」を組み合わせた造語です。

日本では、2017年に政府が「テレワーク・デイ」（翌年以降は「テレワーク・デイズ」）という、職場以外での勤務を一斉に試みる取組みを始め、東京オリンピック・パラリンピック期間中の交通混雑の緩和も視野に入れて、多くの企業で主に働き方の面から効果の検証が行われるようになりました。そして2020年以降、新型コロナウイルス感染症の拡大によって、多くの組織で準備が整わないままテレワークの導入が急速に進みました。

この「急速な導入」は、セキュリティの面では大きな爪痕を残しました。VPN装置を急いで増設したものの、脆弱性の修正が追いつかない。私物PCの利用を暫定的に認めたまま、ルールが整備されない。こうした隙を突いて、VPN装置の脆弱性を悪用した認証情報の大量流出や、そこを入り口にしたランサムウェア被害が相次ぎました。警察庁の調査でも、ランサムウェアの侵入経路として VPN機器とリモートデスクトップが上位を占める状況が続いています。

### 1.2 テレワークの形態

テレワークには、主に次の3つの形態があります。

| 形態 | 働く場所 | 主な接続手段 | 固有のリスク |
|---|---|---|---|
| **在宅勤務** | 自宅 | 自宅のインターネット回線、スマートフォンからのテザリング。VPN で社内システムに接続、またはクラウドサービスに接続 | 家庭用ルータの脆弱な設定、家族との端末共用、家族による画面ののぞき見・会話の聞き取り |
| **モバイル勤務** | 外出先、移動中 | ノートPCやスマートフォンで、公衆無線LANやテザリングによりインターネットに接続し、VPN またはクラウドサービスを利用 | 端末の紛失・盗難、公衆無線LANでの盗聴・偽アクセスポイント、第三者によるのぞき見（ショルダーハッキング） |
| **サテライトオフィス勤務** | 自社が用意した、または複数の企業が共同で利用するサテライトオフィス | オフィスに設置されたインターネット回線 | 共同利用の場合は他社の利用者と同じネットワークを使うことがある |

> **テザリング**：インターネット接続機能をもつスマートフォンなどのモバイル端末を介して、他の機器をインターネットに接続すること。

在宅勤務は、新型コロナウイルス感染症の流行によって最も大きく普及した形態です。なお、観光地などで休暇を楽しみながら働く「ワーケーション」も、セキュリティの観点ではモバイル勤務と同様のリスクをもつ形態として扱えます。

### 1.3 オフィス勤務と何が違うのか

テレワークのリスクは、オフィスにあった「見えない防御」がなくなることから生まれます。1.1 で学んだ物理的・論理的セキュリティの分類で比べてみると、よくわかります。

| 分類 | オフィス勤務で自然に効いていた対策 | テレワークで失われるもの |
|---|---|---|
| 物理的セキュリティ | 入退室管理、施錠できるキャビネット、盗難されにくい環境 | 自宅や外出先では端末や書類を物理的に守る仕組みが弱い |
| システム的セキュリティ | 社内のファイアウォール、プロキシ、IDS を必ず通る通信 | 家庭用回線や公衆無線LANから直接インターネットに出る可能性 |
| 管理的セキュリティ | 情報システム部門による端末の一元管理、パッチ配布 | 社外にある端末へのパッチ配布や状態確認が難しい |
| 人的セキュリティ | 上司や同僚の目による牽制（1.2 の抑止・抑制） | 周囲の目がなく、ルール違反に気づかれにくい |

とくに見落とされやすいのが、最後の「人の目による牽制」です。オフィスでは、私用のUSBメモリを挿したり、業務データを個人のクラウドストレージに保存したりすれば、周囲に見られる可能性がありました。自宅ではその心理的なブレーキが働きません。テレワークでは、技術的な対策に加えて、ルールと教育、そしてログによる検知で、この失われた牽制を補う必要があります。

## 2. テレワーク導入における主な検討事項

テレワークを導入する際には、主に次の事項を検討する必要があります。これらの決め方によって、テレワーク環境のセキュリティリスクが変わり、実施すべき対策も変わってきます。

| 主な検討事項 | 内容 | リスクへの影響の例 |
|---|---|---|
| 対象者 | 一部の社員、全社員など、対象とする従業者の範囲 | 全社員に広げるほど、VPN などの設備の負荷と、ITに不慣れな利用者への教育負担が増える |
| 業務内容 | 対象とする業務の範囲や内容 | 個人情報や機密情報を扱う業務を含めるかどうかで、必要な対策の水準が大きく変わる |
| 利用するシステム | メール、社内システム、クラウドサービスなど | 社内システム中心なら VPN の強化、クラウド中心ならクラウドの認証強化が重要になる |
| ネットワーク接続方法 | 会社の VPN に接続、端末から直接インターネットに接続など | 直接接続を認めると、社内のプロキシや監視を通らない通信が生まれる |
| 使用するネットワーク設備 | 自宅のインターネット回線、テザリング、公衆無線LANなど | 公衆無線LANを認めると盗聴のリスクが上がる |
| テレワーク端末 | 会社が貸与するPCやスマートフォン、個人所有の端末（BYOD）など | BYOD では端末の状態を会社が管理しきれない（1.5 の MDM/MAM/MCM 参照） |
| 端末へのファイル保存の可否 | 各端末に業務で使うファイルを保存するか否か | 保存を認めると、紛失・盗難時の情報漏えいのリスクと、暗号化などの対策が必要になる |

これらの検討事項は独立しているわけではありません。たとえば「BYODを認める」なら「端末へのファイル保存は禁止する」、「公衆無線LANを認める」なら「VPN を必須にする」というように、ある項目で緩めたリスクを別の項目で補う組合せを考えることが大切です。

## 3. テレワークの実施方式とセキュリティ対策

### 3.1 ITインフラから見た3つの実施方式

ITインフラから見たテレワークの実施方式にはさまざまな種類があり、前述の検討結果、求めるセキュリティレベル、導入・運用のコストなどによって選択します。ここでは代表的な3つの方式を見ていきます。

**①シンクライアント画面転送型**

テレワークPCには一切ファイルなどを保存せず、オフィスPC（またはVDI上の仮想PC）の画面を転送して遠隔操作するための、シンクライアント端末として使う方式です。テレワークPCは VPN 経由でオフィスPCに接続します。

```
図:シンクライアント画面転送型のイメージ

 テレワークPC ==(VPN・画面転送のみ)==> [VPN装置] --> オフィスPC／VDI --> 社内システム
 （ファイルを保存しない）                                          └--> プロキシ --> インターネット・クラウド
```

| メリット | デメリット／検討・対応が必要な事項など |
|---|---|
| ・テレワークPCに業務情報を保存する必要がない | ・オフィスPCとは別にテレワークPCを手配する必要がある（BYODでない場合） |
| ・レスポンスに問題がなければオフィスと同様に業務が可能 | ・通信機器・回線の大幅な増強が必要となる可能性がある |
| ・インターネットへの通信を集約し、すべて管理・監視できる | ・設備次第でレスポンスや使い勝手が悪化する可能性がある |
| ・BYODとの親和性が高い | |

**②ファットクライアント型1（VPN接続のみ）**

ファットクライアント型のオフィスPC（ノートPC）を持ち出し、テレワークPCとして使う方式です。社内システムへのアクセスも、インターネット上のWebサイトやクラウドサービスへのアクセスも、**すべて VPN 経由**でオフィス側のネットワークを通して行います。すべての通信を VPN の中に通すこの構成を、**フルトンネル**とも呼びます。

```
図:ファットクライアント型1のイメージ

 テレワークPC ==(VPN・すべての通信)==> [VPN装置] --> 社内システム
 （業務情報を保存）                            └--> プロキシ --> インターネット・クラウド
```

| メリット | デメリット／検討・対応が必要な事項など |
|---|---|
| ・オフィスPCをそのままテレワークに使用できる | ・テレワークPCに業務情報を保存する必要がある |
| ・オフィスと同様のPC環境で業務が可能 | ・通信機器・回線の増強が必要となる可能性が高い |
| ・オフィスにはPCが不要 | ・設備次第でレスポンスや使い勝手が悪化する可能性がある |
| ・インターネットへの通信を集約し、すべて管理・監視できる | ・VPN以外の経路でインターネットに接続しないよう徹底する必要がある |

**③ファットクライアント型2（VPN／インターネット直接接続併用型）**

②と同様にオフィスPCをテレワークPCとして使う方式ですが、社内システムへの接続は VPN 経由で行う一方、クラウドサービスなどには VPN を通さず、自宅や拠点から直接アクセスする構成をとります。このように、特定の通信だけを拠点から直接インターネットに出すネットワーク構成を**ローカルブレイクアウト**といいます（VPN側から見ると、宛先によって通信を分けることから**スプリットトンネル**とも呼ばれます）。

```
図:ファットクライアント型2のイメージ

 テレワークPC ==(VPN・社内宛てのみ)==> [VPN装置] --> 社内システム
 （業務情報を保存）
       └------(直接インターネットへ・ローカルブレイクアウト)------> クラウドサービス
```

| メリット | デメリット／検討・対応が必要な事項など |
|---|---|
| ・通信機器・回線などの増強が不要となる可能性がある | ・テレワークPCに業務情報を保存する必要がある |
| ・オフィスPCをそのままテレワークに使用できる | ・Webやクラウドサービス利用時のセキュリティレベルが低下する可能性がある |
| ・オフィスと同様のPC環境で業務が可能 | |
| ・オフィスにはPCが不要 | |

### 3.2 3方式の比較 ― 何がトレードオフになっているのか

3つの方式を並べると、「端末にデータを置くか」「通信を社内に集めるか」という2つの軸で、セキュリティと利便性・コストのトレードオフになっていることがわかります。

| 観点 | ①画面転送型 | ②ファット型1（フルトンネル） | ③ファット型2（ローカルブレイクアウト） |
|---|---|---|---|
| 端末への業務情報の保存 | しない | する | する |
| インターネット通信の経路 | 社内に集約 | 社内に集約 | 一部を直接接続 |
| 社内の監視・フィルタリングの適用 | すべてに適用 | すべてに適用 | 直接接続の通信には適用されない |
| VPN・回線への負荷 | 最大 | 大 | 小 |
| 紛失・盗難時の情報漏えいリスク | 低い | 高い | 高い |
| 追加で必要な対策 | 画面転送以外の経路（ファイル転送・クリップボード）の禁止、基盤の冗長化 | ①に加え、端末の暗号化、EDR、VPN外への通信の禁止 | ②に加え、クラウド側の認証強化、端末の直接接続の保護（ゼロトラスト、SASE） |

**①の方式**では、テレワークPCにファイルを一切保存しないため、端末の紛失・盗難時の情報漏えいリスクを低く抑えられます。一方で、オフィス側のシンクライアントサーバや VDI 基盤への負荷と、通信帯域の確保が課題になります。

**②の方式**では、テレワークPCに業務情報が保存されるため、その情報の流出や不正利用を防ぐ対策（ディスク全体の暗号化、紛失時の遠隔消去など）や、**EDR** によるエンドポイントセキュリティの強化など、①よりも考慮すべき事項が増えます。ネットワーク接続は①と同様すべて VPN 経由ですが、資料作成などの業務はテレワークPCのローカル環境でできるため、通信設備への負荷は①ほど高くないと考えられます。とはいえ、組織全体でテレワークを行う場合は、通信設備の増強が必要になる可能性が高くなります。

> **EDR**（Endpoint Detection and Response）：PCやサーバなどのエンドポイントで発生した事象（プロセスの起動、ファイルの操作、通信など）を記録・分析し、マルウェアの感染や不正な操作の疑いを検知して、隔離などの対応を支援する仕組み。侵入を防ぐことを主目的とする従来のウイルス対策ソフト（EPP）に対し、侵入された後の検知と対応に重点を置く。

**③の方式**では、②と同様にテレワークPCに業務情報を保存するうえに、従業者の自宅のインターネット回線やテザリングで直接インターネットにアクセスするため、考慮すべきセキュリティ対策はさらに増えます。社内のプロキシやファイアウォール、IDS による監視を通らない通信が生まれるからです。具体的には、②の対策に加え、**ゼロトラスト**（1.7 で解説）に基づいたネットワークの構築や、**SASE** と呼ばれるクラウド上の各種セキュリティサービスの導入などが考えられます。なお、業務がクラウドサービスを含めたインターネットの利用中心であれば、VPN などの設備を増強せずに対応できる可能性があります。

ここに、テレワークとクラウドが組み合わさったときの本質的な問題が現れています。業務の中心がクラウドに移るほど、「すべての通信をいったん社内に戻してから外に出す」①②の方式は非効率になります。自宅からクラウドへの通信が、わざわざ社内のVPN装置を往復することになるからです。一方、③のように直接つなげば効率はよくなりますが、社内の境界防御の外で通信することになります。**境界の内側に通信を集めて守る**という従来の方法と、**クラウドを効率よく使う**という要求が衝突しているのです。この衝突を解消するために、「境界ではなく、アクセスのたびに利用者と端末を確かめる」という発想（ゼロトラスト）と、「境界防御の機能をクラウド上に移す」という発想（SASE）が生まれました。

### 3.3 総務省のガイドラインによる分類

テレワークの方式は、総務省の「**テレワークセキュリティガイドライン**」（2021年の第5版）でも整理されています。ガイドラインでは、次の7つの方式を示しています。3.1 の3方式との対応とあわせて見ておきましょう。

| ガイドラインの方式 | 概要 | 3.1 の方式との対応 |
|---|---|---|
| VPN方式 | テレワーク端末から VPN で社内に接続し、社内システムを利用する | ②③ |
| リモートデスクトップ方式 | テレワーク端末からオフィスの PC を遠隔操作する | ① |
| 仮想デスクトップ（VDI）方式 | テレワーク端末から VDI 上の仮想PCを操作する | ① |
| セキュアコンテナ方式 | 端末上に隔離された業務専用の領域（コンテナ）を作り、その中で業務をする | ②③の変形（BYOD向け） |
| セキュアブラウザ方式 | データを端末に残さない専用ブラウザから、社内システムやクラウドを利用する | ①に近い |
| クラウドサービス方式 | 社内を経由せず、直接クラウドサービスを利用する | ③ |
| スタンドアロン方式 | ネットワークに接続せず、端末内のデータだけで作業する | ― |

ガイドラインは、テレワークの安全な運用には「**ルール**」「**人**」「**技術**」の3つのバランスが重要だとしています。また、経営者、システム・セキュリティ管理者、テレワーク勤務者のそれぞれの立場で実施すべき対策を示している点も特徴です。

## 4. テレワークのセキュリティ対策 ― ルール・人・技術

最後に、テレワークで実施すべき主な対策を、ガイドラインの「ルール・人・技術」の3つの面で整理します。1.1 で学んだ管理的・人的・システム的セキュリティの分類に、そのまま対応しています。

### 4.1 ルール（管理的セキュリティ）

テレワークの対策の出発点は、ルールの整備です。テレワークで扱ってよい情報の範囲（機密度による区分）、使用してよい端末とネットワーク（私物の端末や公衆無線LANを認めるか）、端末へのデータ保存や印刷の可否、紛失・盗難やマルウェア感染時の報告手順と連絡先を定めます。ルールがなければ、社員は「何をしてはいけないのか」がわからず、事故が起きても報告が遅れます。

### 4.2 人（人的セキュリティ）

ルールを定めても、知られていなければ守られません。テレワーク勤務者に対して、ルールの周知と教育を行います。とくに、公衆の場所での画面ののぞき見や会話の聞き取りへの注意、不審なメールへの対応、インシデントの疑いがあるときに**すぐ報告すること**の重要性を繰り返し伝えます。テレワークでは周囲に相談できる同僚がいないため、「おかしいと思ったら一人で判断せずに報告する」という行動を習慣にしておくことが、被害の拡大を防ぐ鍵になります。

### 4.3 技術（システム的・物理的セキュリティ）

技術的な対策は、「端末」「通信経路」「接続先」の3つに分けて考えると整理しやすくなります。

| 対象 | 主な対策 |
|---|---|
| 端末 | ディスク全体の暗号化、画面ロック、OSとソフトウェアのパッチ適用の徹底、ウイルス対策ソフト（EPP）とEDRの導入、MDM による遠隔ロック・遠隔消去、のぞき見防止フィルタ |
| 通信経路 | VPN の利用、公衆無線LANでは暗号化されていない通信をしない、家庭用ルータのファームウェア更新と初期パスワードの変更 |
| 接続先（VPN装置・クラウド） | VPN装置の脆弱性の迅速な修正、多要素認証の必須化、接続元や端末の状態による制限、アクセスログの監視 |

中でも、**VPN装置**の管理は最優先事項です。VPN装置はインターネットに直接公開され、社内への入り口そのものになっているため、1つの脆弱性がそのまま社内への侵入口になります。本ノートの冒頭（1.1 節）で述べたとおり、実際に多くのランサムウェア被害が VPN 装置の未修正の脆弱性や、流出した認証情報から始まっています。脆弱性情報の収集と迅速なパッチ適用、パスワードだけに頼らない多要素認証、不要になったアカウントの削除を徹底する必要があります。

もう一つ、テレワーク特有の注意点として、**持ち出した端末をオフィスに戻すとき**の問題があります。テレワーク中に社外のネットワークでマルウェアに感染した端末を、そのまま社内のネットワークに接続すると、社内に感染が広がります。社内に接続する前に端末のパッチ適用状況やウイルス定義の更新状況を確認し、条件を満たさない端末を隔離する**検疫ネットワーク**の考え方が、ここで再び重要になります。この「端末の状態を確認してから接続を許可する」という発想も、1.7 のゼロトラストに引き継がれていきます。

## 6. 試験対策まとめ（重要ポイント）

### 6.1 知識の確認（科目A-2向け）

- **テレワークの3形態**：在宅勤務、モバイル勤務、サテライトオフィス勤務。モバイル勤務は紛失・盗難と公衆無線LAN、在宅勤務は家庭用回線と家族との共用が主なリスク。
- **3つの実施方式**：①シンクライアント画面転送型（端末にデータを残さない・通信を集約・回線負荷が最大）、②ファットクライアント型1（端末にデータを置く・すべてVPN経由）、③ファットクライアント型2（端末にデータを置く・クラウドには直接接続）。
- **ローカルブレイクアウト（スプリットトンネル）**：特定の通信を VPN を通さず直接インターネットに出す構成。回線負荷は下がるが、社内の監視・フィルタリングが効かなくなる。
- **フルトンネル**：すべての通信を VPN 経由にする構成。管理しやすいが、クラウド中心の業務では回線がひっ迫しやすい。
- **EDR と EPP**：EPPは侵入を防ぐ、EDRは侵入後の検知と対応に重点を置く。
- **テレワークセキュリティガイドライン**：総務省。「ルール・人・技術」のバランス。VPN、リモートデスクトップ、VDI、セキュアコンテナ、セキュアブラウザ、クラウドサービス、スタンドアロンの7方式。
- **VPN装置の脆弱性**：ランサムウェアの主要な侵入経路。パッチ適用と多要素認証が必須。

### 6.2 記述式で問われる観点（科目B向け）

- **方式ごとの対策の過不足**：事例のテレワーク方式を読み取り、「端末にデータが残るか」「通信が社内の監視を通るか」の2軸で、欠けている対策（端末の暗号化、EDR、クラウドの認証強化など）を指摘する。
- **インシデントの経路の特定**：テレワーク端末の感染事例では、「VPN を使わずに直接インターネットに接続していた」「私物のUSBメモリを使った」「社内に再接続したときに感染が広がった」など、どの時点・どの経路でリスクが顕在化したかを特定して説明する。
- **VPN装置の侵害への対応**：VPN装置の脆弱性が悪用された事例では、パッチ適用だけでなく、「すでに流出した可能性のある認証情報の無効化（パスワードの変更）」「VPN経由のアクセスログの調査」「多要素認証の導入」まで答える。
- **ルール・人・技術の組合せ**：技術的な対策だけでなく、報告手順のルール化や、周囲の目がない環境を前提とした教育、ログによる検知を組み合わせて、失われた牽制を補う提案ができるようにしておく。
- **方式選択の理由付け**：業務の中心がクラウドか社内システムか、扱う情報の機密度、回線の容量などから、どの方式を採用すべきかと、その理由を述べる。

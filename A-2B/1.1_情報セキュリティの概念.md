# レクチャーノート：情報セキュリティ及びITの基礎 ― 1.1 情報セキュリティの概念

対応範囲：情報処理安全確保支援士試験 科目A-2（専門知識）・科目B（技能）「技術要素」＞「セキュリティ」＞「情報セキュリティ」（知識項目例：情報の機密性・完全性・可用性、多層防御、脅威 ほか）

---

## 0. 全体像 ― なぜこの分野を学ぶのか

ここまでのノートでは、第2章で「誰が・どうやって攻めてくるか（脅威）」、第3章で「どこに隙があるか（脆弱性）」、第4章で「組織としてどう管理するか（マネジメント）」、第5章で「どうやって侵入を検知・防御するか」を学んできました。個々の攻撃手法や防御装置を知った今だからこそ、一度立ち止まって「そもそも私たちは何を守ろうとしているのか」という原点に戻るのが、この第1章の役割です。

原点を押さえる価値は、科目Bの事例問題を解くときにはっきり現れます。長文の事例では「この対策は何のために必要か」「この被害は何が損なわれたのか」を自分の言葉で説明させる設問が必ず出ます。そのとき、判断の拠り所になるのが本ノートで扱う「情報資産」「情報セキュリティの定義」「対策の分類」という、ごく基本的な枠組みです。

本ノートは次の順で進みます。①まず「セキュリティ＝安全」という一般的な意味から出発し、企業が直面するリスクの全体像の中で情報セキュリティがどこに位置するかを確認します。②次に、JIS Q 27000 の定義に沿って「情報セキュリティとは何か」を言語化します。③最後に、対策を「物理的セキュリティ」と「論理的セキュリティ」に分ける考え方を学び、ほかの分類軸（人的・物理的・技術的の3分類、ISO/IEC 27002 の4分類）との対応関係を整理します。

科目Bの4つの業務観点のうち、本ノートは主に「①情報セキュリティマネジメントの推進又は支援」の土台にあたります。科目A-2で単独の設問になることは多くありませんが、ほぼすべての設問の前提になる概念です。

## 1. 「セキュリティ」とは何を守ることか

### 1.1 セキュリティ＝安全な状態を保つこと

**セキュリティ**（security）は「安全」を意味します。安全とは、守らなければならない大切なものが、危害や損傷を受けずに正常な状態にあることです。企業や組織に当てはめれば、社員の生命や保有する財産を危害・損傷から守り、正常な状態を確保・維持することがセキュリティだといえます。

ここで大事なのは「状態を保つ」という点です。セキュリティは一度導入すれば完成する製品ではなく、正常な状態を**確保し、維持し続ける**活動です。この「維持」という発想は、後に 1.3 のPDCAサイクル（継続的改善）へとつながっていきます。

### 1.2 企業や組織が直面するリスクの全体像

企業の生命や財産を脅かすリスクは、情報に関するものだけではありません。代表的なリスクと、それを伝統的に担当してきた部門を整理すると次のようになります。

| リスクの例 | 性質 | 主な担当部門（伝統的な分担） |
|---|---|---|
| 地震、火災、風水害などの自然災害 | 環境的・偶発的 | 総務部門（防災・BCP） |
| 戦争、テロ | 意図的・広域 | 総務部門・経営層 |
| 強盗、泥棒、詐欺 | 意図的・犯罪 | 総務部門（警備） |
| 業務中の事故 | 偶発的 | 総務・人事部門（労働安全） |
| メインバンクや大口顧客の倒産、株価の下落 | 経済的 | 財務部門 |

これらのリスクは顕在化すれば企業活動に影響を及ぼし、場合によっては存続にかかわる問題に発展します。「セキュリティ」を広くとらえれば、こうしたリスクへの対処もすべてセキュリティ対策と呼べます。とはいえ実務上、これらの多くは総務部門や財務部門の守備範囲です。

では、情報セキュリティはこの中のどこに入るのでしょうか。注目したいのは、上の表のリスクの多くが**情報にも波及する**という点です。地震でデータセンタが止まれば情報システムが使えなくなり、窃盗でノートPCが盗まれれば中の顧客情報が漏れます。つまり情報セキュリティは、これらのリスクと並ぶ「もう一つの項目」であると同時に、ほかのリスクが情報資産に与える影響を横断的に扱う分野でもあります。第4章で学んだ事業継続管理（BCP/BCM）が総務部門と情報システム部門の協働になりやすいのは、このためです。

### 1.3 経営資源としての「情報」

組織が守るべき財産は、よく「ヒト・モノ・カネ・情報」の4つにまとめられます。

| 経営資源 | 例 | 守り方の典型 |
|---|---|---|
| ヒト | 役員、社員 | 労働安全、健康管理、防災 |
| モノ | 不動産、オフィス設備 | 警備、施錠、保険 |
| カネ | 預貯金、有価証券 | 内部統制、与信管理 |
| 情報 | 顧客情報、社員情報、商品情報、技術情報 | **情報セキュリティ** |

いずれも重要な財産ですが、ITの活用がビジネスの成否を左右する今日では、情報の重要度が年々高まっています。しかも情報には、ほかの経営資源にはない厄介な性質があります。

- **コピーしても元が減らない**：モノやカネは盗まれれば手元から消えるので気づけますが、情報は複製されても元のデータが残るため、漏えいに気づきにくいのです。
- **一瞬で大量に移動する**：数千万件の顧客情報でも、USBメモリ1本やネットワーク経由で数分のうちに持ち出せます。
- **一度出たら回収できない**：インターネットに流出した情報を完全に消すことは事実上不可能です。

実際、国内でも委託先社員による大規模な個人情報の持ち出し事件や、ランサムウェアによる出版・製造・医療機関の長期業務停止など、情報セキュリティの事故が企業の信用と業績を大きく損なう事例が繰り返し起きています。情報を「有形の資産と同じように、あるいはそれ以上に注意深く守るべき財産」と位置づけるのは、こうした性質があるからです。

## 2. 情報セキュリティの定義

### 2.1 情報資産とは何か

情報セキュリティが守る対象を**情報資産**と呼びます。情報資産というと電子データを思い浮かべがちですが、実際にはもっと広い範囲を含みます。

| 種類 | 例 |
|---|---|
| 電子データ | データベース、ファイル、メール、ログ |
| 紙の情報 | 契約書、設計書、印刷した顧客名簿 |
| ソフトウェア | 業務アプリケーション、OS、開発中のソースコード |
| ハードウェア・媒体 | サーバ、PC、スマートフォン、USBメモリ、バックアップテープ |
| サービス | クラウドサービス、通信回線、電源・空調 |
| 人の知識・ノウハウ | 担当者の頭の中にある手順や経験 |

最後の「人の知識」まで含めるのが実務上のポイントです。ソーシャルエンジニアリング（第2章）が人をだまして情報を引き出す手口であることを思い出すと、人が情報資産の一部であることが実感できるはずです。第4章 4.5「情報資産の管理」で扱った資産台帳の作成は、この「何を守るか」を棚卸しする作業にあたります。

### 2.2 JIS Q 27000 による定義

ISMS関連規格の用語を定める **JIS Q 27000**（ISO/IEC 27000）では、**情報セキュリティ**を次のように定義しています。

> 情報の**機密性**、**完全性**及び**可用性**を維持すること。
> 注記：さらに、**真正性**、**責任追跡性**、**否認防止**、**信頼性**などの特性を維持することを含めることもある。

つまり、中核は機密性・完全性・可用性の3つ（頭文字から **CIA** と呼ばれます）で、必要に応じて4つの付加的な特性が加わる、という二段構えの定義です。各特性の中身と確保の方法は、次の 1.2 で詳しく扱います。ここでは「情報セキュリティとは、何かを禁止することではなく、情報の**良い性質を維持すること**だ」という発想をつかんでおいてください。

### 2.3 「守る」「活かす」「戻す」の3つがそろって初めて情報セキュリティ

企業が保有する情報は、存続に不可欠な財産です。だからこそ情報セキュリティには、次の3つの側面が求められます。

1. **守る**：サイバー攻撃などによって危害や損傷を受けないよう適切に保護する。
2. **活かす**：保護しつつも、業務で有効に活用できる状態を保つ。
3. **戻す**：不測の事態が起きた場合は、速やかに元の正常な状態に復旧する。

「守る」だけに偏ると、厳重すぎて誰も使えないシステムができあがります。これは可用性を損ない、結果的に情報セキュリティを下げていることになります。「戻す」を忘れると、ランサムウェアに暗号化されたときに打つ手がありません。3つを並べて覚えておくと、1.2 で学ぶ「対策の機能（抑止・予防・検知・回復）」や「セキュリティと利便性のバランス」の議論が自然に理解できます。

以上をまとめると、本ノートの結論となる定義は次のとおりです。

**情報セキュリティとは、企業や組織の重要な財産（資産）である情報（情報資産）のセキュリティを確保し、維持することである。**

## 3. 対策をどう分類するか ― 物理的セキュリティと論理的セキュリティ

守る対象が決まったら、次は「どういう種類の対策で守るか」を整理します。情報セキュリティ対策は大きく2つに分けられます。一つは建物や設備に対する**物理的セキュリティ**、もう一つは情報システムやネットワークに対する技術的な対策に代表される**論理的セキュリティ**です。

### 3.1 物理的セキュリティ ― 「モノ」と「場所」を守る

**物理的セキュリティ**とは、建物や設備などを対象とした物理的な対策です。具体的には次のようなものがあります。

- 耐震設備、防火設備（消火設備・耐火金庫など）
- 電源設備（UPS、自家発電装置、電源の二重化）
- 回線設備（通信回線の二重化、異経路化）
- 入退室管理設備（ICカード、**バイオメトリック認証**システムなど）
- 電源ケーブルや通信ケーブルの物理的保護（配管・床下配線、施錠されたラック）

どれほど高度な暗号を使っていても、サーバ室に誰でも入れてディスクを抜き取れるなら意味がありません。物理的セキュリティは、論理的セキュリティが機能するための「土台」です。詳細は第4章 4.6「物理的・環境的セキュリティ」で扱っています。

### 3.2 論理的セキュリティ ― システム・管理・人の3本柱

**論理的セキュリティ**は、情報システムやネットワーク、それを使う組織と人に対する対策で、さらに次の3つに分けられます。

| 分類 | 内容 | 具体例 |
|---|---|---|
| **システム的セキュリティ** | 情報システムやネットワークにおける技術的な対策 | アクセス制御、認証、暗号化、マルウェア対策 |
| **管理的セキュリティ** | 組織や情報システムの運用管理面における対策全般 | 情報セキュリティポリシの策定・運用・監査・見直し、ソフトウェアのライセンス管理 |
| **人的セキュリティ** | 人に対する契約・教育・処分などの対策 | 雇用契約・委託契約における取決め、教育・訓練、事件・事故および誤動作への対処、ポリシ違反の懲戒手続 |

なお、人的セキュリティは管理的セキュリティに含められることもあります。人に対する施策の多くが、規程やルールという「管理」の形で実施されるためです。

この3本柱は互いに補い合う関係にあります。たとえば「パスワードは推測されにくいものにする」という対策は、システム的には文字数や文字種を強制する設定、管理的にはパスワード規程の制定、人的には教育による周知、という3つの面から実装して初めて機能します。どれか1つだけでは穴が残る、という考え方は、1.2 で学ぶ**多層防御**の発想の出発点です。

### 3.3 ほかの分類軸との対応 ― 切り口が違うだけで中身は同じ

情報セキュリティ対策の分類には、本ノートの「物理的／論理的」のほかにも、試験でよく使われる分類があります。科目A-1のノート（`A-1/8.2_情報セキュリティ管理.md`）で学んだ「人的・物理的・技術的」の3分類と、ISO/IEC 27002:2022（JIS Q 27002:2024）の管理策の4分類です。対応関係は次のとおりです。

| 本ノートの分類 | 人的・物理的・技術的の3分類 | ISO/IEC 27002:2022 の4分類 |
|---|---|---|
| 物理的セキュリティ | 物理的セキュリティ対策 | 物理的管理策 |
| 論理的：システム的セキュリティ | 技術的セキュリティ対策 | 技術的管理策 |
| 論理的：管理的セキュリティ | （人的対策または別枠の「管理的対策」） | 組織的管理策 |
| 論理的：人的セキュリティ | 人的セキュリティ対策 | 人的管理策 |

用語は違っても、「モノ・場所を守る」「技術で守る」「ルールと組織で守る」「人に働きかけて守る」という4つの切り口は共通しています。試験では、ある対策がどの分類に入るかを問う設問が出ることがありますが、この表の「行」で考えれば迷いません。たとえば監視カメラは物理的、ログのアクセス制御は技術的（システム的）、アクセス権の定期棚卸しを規程で定めるのは組織的（管理的）、退職者から秘密保持誓約書を取るのは人的、という具合です。ISO/IEC 27002 の4分類は 1.3 で詳しく扱います。

### 3.4 事例で確認する ― ノートPCの紛失

分類の使い方を具体的な場面で確かめてみましょう。「営業担当者が顧客情報の入ったノートPCを電車に置き忘れた」というインシデントを考えます。

- **システム的セキュリティ**が効いていれば、ディスク全体が暗号化されていて中身は読まれず、MDMで遠隔消去もできます。
- **管理的セキュリティ**が効いていれば、「顧客情報をPCに保存しない」「持ち出しは申請制」という規程があり、そもそも持ち出す情報を最小化できていたはずです。
- **人的セキュリティ**が効いていれば、教育によって担当者はすぐに上長とCSIRTに報告し、初動が早まります。
- **物理的セキュリティ**の観点では、PCにワイヤロックを付ける、持ち出し用の施錠できるバッグを使う、といった対策が考えられます。

このように1つのインシデントを複数の分類の目で見直すことで、「どの層の対策が欠けていたか」を洗い出せます。科目Bの事例問題で「再発防止策を述べよ」と問われたときに、技術的対策だけでなく管理的・人的な対策も挙げられるかどうかが、得点の分かれ目になります。

## 5. 試験対策まとめ（重要ポイント）

### 5.1 知識の確認（科目A-2向け）

- **情報セキュリティの定義（JIS Q 27000）**：機密性・完全性・可用性の維持が中核で、真正性・責任追跡性・否認防止・信頼性を「含めることもある」という二段構え。付加的特性が「必須」ではない点が引っかけになりやすい。
- **情報資産の範囲**：電子データだけでなく、紙、ソフトウェア、ハードウェア・媒体、サービス、人の知識まで含む。
- **物理的セキュリティ と 論理的セキュリティ**：建物・設備を守るか、システム・組織・人を守るかの対比。入退室管理は物理的、アクセス制御は論理的（システム的）。
- **論理的セキュリティの3分類**：システム的（技術）・管理的（ポリシ・運用・監査・ライセンス管理）・人的（契約・教育・懲戒）。人的は管理的に含めることもある。
- **分類軸の対応**：物理的／システム的／管理的／人的は、ISO/IEC 27002:2022 の物理的／技術的／組織的／人的管理策にほぼ対応する。

### 5.2 記述式で問われる観点（科目B向け）

- **被害の言語化**：事例のインシデントで「何が損なわれたか」を、機密性（漏えい）・完全性（改ざん）・可用性（停止）のどれにあたるかで説明できるようにしておく。
- **再発防止策の網羅性**：技術的対策だけで終わらせず、管理的（規程・承認フロー）・人的（教育・誓約）・物理的（施錠・持出し管理）の観点を組み合わせて答える。設問が求める観点がどれかを見極めることが先決。
- **守る・活かす・戻す**：対策案が業務の利便性を過度に損なっていないか、復旧手段（バックアップ等）が用意されているかを、提案の妥当性の根拠として書けるようにしておく。

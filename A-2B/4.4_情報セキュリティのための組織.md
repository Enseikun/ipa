# レクチャーノート：情報セキュリティマネジメントの実践 ― 4.4 情報セキュリティのための組織

対応範囲：情報処理安全確保支援士試験 科目A-2（専門知識）・科目B（技能）「技術要素」＞「セキュリティ」＞「情報セキュリティ管理」（知識項目例：ISMS，情報セキュリティ管理策（組織的管理策 ほか），情報セキュリティ組織・機関（CSIRT，SOC ほか） ほか）

---

## 0. 全体像 ― なぜこの分野を学ぶのか

4.1〜4.3 では、リスクを測り（アセスメント）、対策を選び（リスク対応）、それをルールとして書く（ポリシ）という流れを学びました。そのたびに「CISO が承認する」「委員会が決定する」「リスク所有者（部門長）が受容する」という主語が出てきました。本ノートは、その主語たちが組織の中でどこに位置し、どんな責任と権限をもつのかを整理する回です。

情報セキュリティマネジメントを組織全体で推進していくためには、関係者の責任を明確にするとともに、関連する部署の代表が調整しながら継続的に取り組んでいく必要があります。担当者1人に任せきりにすると、その人が異動した途端に活動が止まり、また他部門に協力を頼んでも「権限がない人の依頼」として後回しにされます。本ノートでは、情報セキュリティマネジメントに必要な組織体制と、その役割を次の順で解説します。

1. **あるべき姿**：推進組織に求められる5つの姿（1章）。
2. **体制と役割**：CISO、情報セキュリティ委員会、事務局、推進担当会議、情報管理者、情報システム管理者、監査担当のそれぞれが、何を承認・決定・実施するか（2章）。
3. **CSIRTとの連携**：インシデント対応チームを組織図のどこに置くか（3章）。
4. **実際の動き**：ノートPCの紛失事故を例に、各役割が時系列でどう動くかを追います（4章）。

1.3 の ISMS 確立の10ステップでは、ステップ0（推進組織を作り、経営資源を割り当てる権限をもつ責任者を置く）が本ノートの範囲で、ISO/IEC 27001 の箇条5（リーダーシップ）の「役割、責任及び権限」にあたります。科目Bの業務観点では「①情報セキュリティマネジメントの推進又は支援」と「④インシデント管理の推進又は支援」のうち「管理体制の構築」に対応します。科目A-2では体制の望ましい姿（特定の部署や個人に任せない、監査の独立性）が問われ、科目Bでは事例中の組織図を読んで「誰に報告すべきか」「誰が承認すべきか」を答えさせる設問が頻出です。

## 1. 組織のあるべき姿と役割

情報セキュリティマネジメントを推進する組織には、次のような姿が求められます。

**表11 組織のあるべき姿と役割の例**

| あるべき姿 | 役割の例 | その姿が欠けると何が起きるか |
| --- | --- | --- |
| 経営層が責任をもって関与している | 最高責任者（CISO）の任命、経営資源の割当て | 予算も人員も付かず、対策が「現場の善意」頼みになる |
| 意思決定の仕組みが明確である | 情報セキュリティ委員会による方針・規程の承認 | 誰が決めたかわからないルールが乱立し、守られない |
| 全部門が参加している | 各部門の代表による推進体制の構築 | 情報システム部門以外の部署（営業・人事など）で対策が抜け落ちる |
| 現場で対策が確実に実施されている | 情報管理者・情報システム管理者による日常管理 | 規程は立派でも、現場では誰も実施していない |
| 取組みが客観的に評価されている | 独立した監査担当による監査 | 形骸化に誰も気づかず、改善のきっかけがない |

1行目の「経営層の関与」は、経済産業省と IPA の「サイバーセキュリティ経営ガイドライン」（Ver3.0、2023年）でも強調されています。このガイドラインは、サイバーセキュリティ対策を経営者が自らリーダーシップをとって進めるべき経営課題と位置づけ、経営者が CISO 等の責任者を任命して体制を構築するよう求めています。

## 2. 情報セキュリティ管理体制と役割

### 2.1 体制図と「誰が何をするか」

情報セキュリティ管理体制と役割の例を次に示します。

```
                  ┌──────────────┐
                  │     CISO     │
                  └──────┬───────┘
                         │
   ┌─────────────────────┼─────────────────────┐
   │                     │                     │
┌──┴─────────┐  ┌────────┴─────────┐   ┌───────┴──────┐
│  監査担当  │  │情報セキュリティ  │───│情報セキュリティ│
│            │  │委員会            │   │委員会事務局    │
└────────────┘  └────────┬─────────┘   └──────────────┘
                         │
                ┌────────┴─────────┐
                │情報セキュリティ  │
                │推進担当会議      │
                └────────┬─────────┘
                         │
          ┌──────────────┼──────────────┐
          │              │              │
   ┌──────┴─────┐ ┌──────┴─────┐ ┌──────┴───────┐
   │ 情報管理者 │ │ 情報管理者 │ │情報システム  │
   │ （A部門）  │ │ （B部門）  │ │管理者        │
   └────────────┘ └────────────┘ └──────────────┘
```

この図で注目してほしいのは、監査担当が情報セキュリティ委員会の下ではなく、CISO（経営層）の直下に委員会と並んで置かれている点です。監査担当は委員会が決めたことを「チェックする側」なので、チェックされる側の指揮下に入ってはいけません（2.8 で詳しく述べます）。

各役割が「何を承認・決定し、何を実施するか」を1枚の表にまとめると、次のようになります。

| 役割 | 担う人（例） | 承認・決定すること | 自ら実施すること |
|---|---|---|---|
| 経営層（取締役会・社長） | 代表取締役、取締役会 | CISO の任命、基本方針の承認、リスク受容基準の承認 | 基本方針への署名（コミットメント）、マネジメントレビュー |
| CISO | 役員クラス | 委員会の議長として全社の方針・施策を決定 | 経営層への報告、予算要求、重大インシデント時の指揮 |
| 情報セキュリティ委員会 | CISO（委員長）、各部門の責任者（本部長・部長） | 経営資源の割当て、対策基準などの全社規程の承認、不測事態時の対応方法 | ― （決定機関） |
| 委員会事務局 | 総務部門・情報システム部門の担当者 | ― | 委員会の開催、議案の取りまとめ、決定事項の周知、規程の起案 |
| 推進担当会議 | 各部門の推進担当者 | 部門固有の手順・様式の作成 | 部門内の教育、対策の実施指示、状況把握 |
| 情報管理者 | 各課・グループの責任者（課長・リーダー） | 情報の重要度・取扱い方法の判断、各種申請の承認 | 課内の状況把握と実施指示 |
| 情報システム管理者 | 情報システム部門の責任者 | システムのセキュリティ設定の決定 | システムの対策の実施・管理 |
| 監査担当 | 内部監査部門、又は他部門から選出された監査員 | ― （独立した評価者） | 監査の実施、結果の報告（CISO・経営層へ） |

### 2.2 CISO（Chief Information Security Officer：最高情報セキュリティ責任者）

**CISO** は、当該組織における情報セキュリティの最高責任者で、一般的に経営責任をもつ者（役員クラス）が担当します。役員クラスである必要があるのは、情報セキュリティ対策には予算・人員の配分や、部門をまたぐ業務の変更が伴い、それを決める権限は経営層にしかないからです。

> **CISO**：Chief Information Security Officer の略。組織の情報セキュリティに関する最終的な責任を負う役職であり、経営的な観点から情報セキュリティ戦略を立案・推進します。CIO（最高情報責任者）が兼務する場合もあります。

CIO が兼務する場合は注意が必要です。CIO は「IT を速く安く導入する」ことを求められる立場なので、「セキュリティのために導入を遅らせる」判断と利害が衝突することがあります。兼務させる場合でも、CISO としての判断を経営会議で説明させるなど、けん制が働く仕組みを用意するのが望ましいでしょう。

### 2.3 情報セキュリティ委員会

**情報セキュリティ委員会**は、当該組織における情報セキュリティマネジメントに関する意思決定を行う最高機関で、CISO が委員長を務めます。委員は各部門の責任者（本部長、あるいは部長クラスの者）が務めます。各部門の責任者が委員になるのは、委員会の決定を自部門に持ち帰って実行させる権限をもつのが彼らだからです。なお、呼称や設置形態はさまざまで、組織全体のリスクマネジメントを行う「リスク管理委員会」などに包含されたり、その下部組織として位置付けられたりする場合もあります。

具体的には、委員会は次のような事項を決定／承認する役割を担います。

- 情報セキュリティマネジメントに対する経営資源（予算、人材など）の割当て
- 情報セキュリティマネジメントに関する全社的な方針、規程、施策などの承認
- 情報セキュリティマネジメントに関する不測事態発生時の対応方法（対外的な対応、罰則の適用など）

委員会の議事録は、たとえば次のような形になります。「誰が報告し、何を決定し、誰がいつまでに何をするか」が残っていることが、後の監査で意思決定の証跡になります。

```
第12回 情報セキュリティ委員会 議事録（2026/10/20 14:00〜15:00）
出席：CISO（委員長）、営業本部長、管理本部長、開発本部長、情報システム部長、人事部長
事務局：総務部 情報セキュリティ課

1. 報告事項
  (1) 上期リスクアセスメント結果（事務局）：対応必須リスク 10件（リスク値12以上）
  (2) 9月のインシデント状況（CSIRT）：ノートPC紛失1件（暗号化済み・漏えいなし）
2. 決議事項
  (1) リスク対応計画 R-2026-017（ノートPCの盗難）を承認。予算 年間300万円を割り当てる。
  (2) 情報セキュリティ対策基準 第24条（アカウントの無効化）の改訂を承認。11/1 施行。
3. 宿題
  ・情報システム部長：暗号化の全台適用状況を次回（11月）委員会で報告する。
  ・人事部長：退職者通知を退職日の5営業日前までに情報システム部へ送る運用に改める。
```

### 2.4 情報セキュリティ委員会事務局

**情報セキュリティ委員会事務局**は、総務部門や情報システム部門など、社内の情報セキュリティ関連部門から選出された担当者で構成されます。事務局は、情報セキュリティ委員会の開催、討議事項の取りまとめ、決定事項の周知などの事務作業を行います。実務上は、規程の原案（4.3 の対策基準など）の起案や、リスクアセスメントの取りまとめ（4.1）も事務局が担うことが多く、委員会が「決める場」、事務局が「決めるための材料を用意し、決まったことを広める係」という分担になります。

### 2.5 情報セキュリティ推進担当会議

**情報セキュリティ推進担当会議**は、情報セキュリティ委員会の下部組織として、各部門における情報セキュリティ推進担当者で構成されます。推進担当会議は、情報セキュリティ委員会の決定事項を各部門に展開し、次のような役割を担います。

- 各部門における情報セキュリティ教育の実施
- 各部門における情報セキュリティ対策の実施指示
- 各部門における情報セキュリティ対策実施状況、事件・事故の発生状況などの把握
- 各部門固有の情報セキュリティ対策実施手順、申請書類、管理簿などの作成

委員会（部長クラス）が「何をするか」を決め、推進担当会議（実務担当者クラス）が「各部門でどう実行するか」を具体化する、という上下の関係です。

なお、規模の大きな組織では、このような全社的な情報セキュリティ推進組織を設置するのではなく、各部門内に情報セキュリティ委員会を設置し、同様の役割を担わせる場合もあります。

### 2.6 情報管理者

**情報管理者**は、各部門やプロジェクトなどの責任者（課長、リーダーなど）が、各課やグループ内で取り扱う情報の管理者として就く役割です。情報管理者は次のような役割を担います。

- 情報の重要度や取扱い方法（保管場所、廃棄方法、持出しの可否など）の判断
- 情報セキュリティに関する各種申請の確認／承認
- 情報セキュリティ対策実施状況、事件・事故の発生状況などの把握
- 情報セキュリティ対策の実施指示

4.1 の情報資産台帳で C・I・A の値を確定させた「資産の管理責任者」や、4.2 で残留リスクを承認した「リスク所有者」は、多くの組織でこの情報管理者やその上位の部門長が担います。情報管理者が承認する「各種申請」は、たとえば次のような持出し申請です。

```
情報資産持出し申請書                                 申請No. 2026-0931
申請者    ：営業1課 佐藤（社員番号 10234）
持出し資産：営業用ノートPC（資産ID IA-0015）、顧客提案資料（機密性2）
持出し先  ：株式会社サンプル（顧客先）  期間：2026/10/22 9:00〜18:00
保護措置  ：ディスク暗号化済み、のぞき見防止フィルタ装着、顧客リストは保存しない
承認      ：営業1課長（情報管理者）  2026/10/21  ☑承認  □却下
```

情報管理者は、申請の中身（持ち出す情報の分類と保護措置が対策基準に合っているか）を確認して承認します。承認の記録が残るので、紛失時には「誰が、何を、誰の承認で持ち出したか」を追跡できます（責任追跡性）。

### 2.7 情報システム管理者

**情報システム管理者**は、情報システム部門の責任者が務め、情報システムに対するセキュリティ対策の実施・管理などの責任を負います。4.3 の対策基準の条文で主語になっていた「情報システム管理者」がこの役割です。各部門が独自に管理している情報システム（部門サーバ、部門で契約した SaaS など）については、当該部門の責任者や IT 担当者が管理者となる場合もあります。ただしこの場合、情報システム部門の目が届かない「シャドーIT」になりやすいので、委員会は部門管理のシステムも台帳に載せ、全社の対策基準を適用させるべきです。

### 2.8 監査担当

**監査担当**は、組織内の情報セキュリティ対策が、情報セキュリティポリシや関連規程に従って適切に実施されているかを監査します。監査担当は、内部監査部門などの独立した部署が担当するか、各部門から選出された監査員が担当します。後者の場合、監査の客観性・独立性を確保するため、監査員が自分の所属する部門の監査を行うことがないようにする必要があります。

監査の主なテーマは次のとおりです。

- 情報セキュリティ管理体制（委員会、推進会議など）の活動状況
- 情報セキュリティポリシや関連文書類の適切性
- 各課やグループなどにおける情報セキュリティ対策実施状況
- 社員の情報セキュリティポリシの理解度、セキュリティ意識
- 雇用や契約における情報セキュリティ対策の実施状況

> **監査の独立性**：監査人が被監査部門から独立した立場にあることを指します。自部門の監査では、身内への配慮や問題の見落としが起こりやすく、監査結果の信頼性が損なわれるため、組織的・精神的な独立性の確保が求められます。

各部門から監査員を選出する場合は、次のような「たすき掛け」の割当て表を作り、自部門の監査が起きないようにします。

| 監査員の所属 | 監査対象の部門 | 自部門を監査していないか |
|---|---|---|
| 営業部 | 人事部 | ○ |
| 人事部 | 開発部 | ○ |
| 開発部 | 営業部 | ○ |
| 情報システム部 | 総務部 | ○ |
| 総務部 | 情報システム部 | ○ |

たとえば情報システム部の監査員が情報システム部を監査すると、自分が設定したアクセス権の不備を自分で見逃す（または報告しにくい）ことになります。組織的な独立性（所属が違う）と精神的な独立性（公正不偏な態度）の両方がそろって、初めて監査結果が信頼されます。監査の詳細は 4.10 で扱います。

このように、組織の情報セキュリティマネジメントを推進するためには、情報セキュリティ管理体制を整備し、その責任や役割を明確にする必要があります。

## 3. CSIRTとの連携

近年、相次ぐサイバー攻撃による重大な情報セキュリティインシデントの発生や、それに伴うサイバーセキュリティへの関心の高まりを背景として、組織が **CSIRT**（Computer Security Incident Response Team：「シーサート」と発音）を設置し、連携するケースが増えています。2.1 の体制は「平時にルールを作り、守らせる」ための組織ですが、攻撃を受けた瞬間に委員会を招集していては対応が間に合いません。インシデントが起きたときに即座に動く専門チームが CSIRT です。

CSIRT は、その役割や構成員により、情報セキュリティ委員会（もしくは「リスク管理委員会」等）と並立した組織として位置付けられるケースもあれば、その下部組織として位置付けられるケースもあります。

```
【並立型】                                   【下部組織型】
          CISO                                        CISO
     ┌─────┴─────┐                                     │
情報セキュリティ   CSIRT                         情報セキュリティ委員会
   委員会      （CISO に直接報告）                  ┌──────┴──────┐
                                                推進担当会議      CSIRT
```

| 位置付け | 利点 | 注意点 |
|---|---|---|
| 並立型 | CSIRT が CISO に直接報告でき、緊急時の意思決定が速い | 平時の委員会活動との情報共有を意識的に行う必要がある |
| 下部組織型 | 委員会の方針・規程と一体で運用しやすい | 緊急時に委員会を経由すると判断が遅れないよう、権限委譲を決めておく |

CSIRT の役割をはじめ、情報セキュリティインシデントへの対応は 4.8 で解説します。

> **CSIRT**：Computer Security Incident Response Team の略。組織内で発生した、又は発生のおそれがあるセキュリティインシデントに対応し、原因の調査、被害の拡大防止、復旧支援、再発防止策の立案などを行うチームです。社外の CSIRT や関係機関（JPCERT/CC など）との情報共有の窓口となる役割も担います。

CSIRT と似た名前の組織として、ログを常時監視して攻撃の兆候を検知する **SOC**（Security Operation Center）や、自社製品の脆弱性に対応する **PSIRT**（Product Security Incident Response Team）もあります。SOC が「見張り（検知）」、CSIRT が「対応（判断・指揮）」という分担が一般的で、SOC が異常を検知すると CSIRT にエスカレーションします（4.8 参照）。

## 5. 確認問題

情報セキュリティマネジメント体制に関する記述のうち、適切なものはどれか。

- **ア** 情報セキュリティマネジメントに複数の人間がかかわると意見調整に時間がかかるので、担当者を1名選出し、推進をすべて任せるのが望ましい。
- **イ** 情報セキュリティマネジメントの推進に当たっては、組織の様々な部署から必要な人材を招集するのが望ましい。
- **ウ** 情報セキュリティマネジメントの推進においては、経営者の意見が最も重要なので、経営会議に一任するのが望ましい。
- **エ** 情報セキュリティマネジメントの推進においては、情報システム部門の意見が最も重要なので、情報システム部門にすべて任せるのが望ましい。

> **解答・解説**
>
> 組織によって情報セキュリティマネジメントの推進形態は異なり、また特定の決まりがあるわけではありませんが、情報セキュリティは組織全体にかかわる重要事項であるため、特定の部署や担当者だけに任せるべきではありません。組織は情報セキュリティに関連する部署から広く必要な人材を招集すべきです。
>
> したがって、**イ**が正解。
>
> - ア：担当者1名では、権限も知見も不足し、その人の異動で活動が止まる。1章の「全部門が参加している」に反する。
> - ウ：経営層の関与は必須だが、経営会議に一任すると現場の実情が反映されず、実施も担保されない。
> - エ：情報システム部門だけでは、人事（罰則・雇用契約）、法務（法令）、営業（顧客情報の現場）などの観点が抜け落ちる。

## 6. 試験対策まとめ（重要ポイント）

### 6.1 知識の確認（科目A-2向け）

- **あるべき姿の5つ**：経営層の関与（CISO の任命・経営資源の割当て）、意思決定の仕組み（委員会による承認）、全部門の参加、現場での確実な実施（情報管理者・情報システム管理者）、客観的な評価（独立した監査）。
- **CISO**：情報セキュリティの最高責任者。経営責任をもつ役員クラス。CIO が兼務する場合もある。
- **情報セキュリティ委員会**：意思決定の最高機関。委員長は CISO、委員は各部門の責任者（本部長・部長）。経営資源の割当て、全社的な方針・規程・施策の承認、不測事態時の対応方法を決定する。リスク管理委員会に包含されることもある。
- **事務局**：委員会の開催、討議事項の取りまとめ、決定事項の周知（事務作業）。
- **推進担当会議**：委員会の下部組織。部門での教育、実施指示、状況把握、部門固有の手順・申請書類・管理簿の作成。
- **情報管理者**：課長・リーダー。情報の重要度・取扱い方法の判断、申請の確認・承認。
- **監査担当**：独立した部署、又は他部門の監査員。自部門の監査は禁止（監査の独立性）。
- **CSIRT**：インシデント対応チーム。委員会と並立、又はその下部組織。外部（JPCERT/CC など）との窓口。SOC は監視・検知、PSIRT は自社製品の脆弱性対応。
- **推進体制の原則**：特定の担当者・部署（情報システム部門だけ、経営会議だけ）に任せず、関連部署から広く人材を招集する。

### 6.2 記述式で問われる観点（科目B向け）

- **報告経路を答える**：事例の組織図を読み、「利用者は情報管理者と CSIRT に報告し、CSIRT は CISO に報告する」のように、役割名で報告の流れを書く。
- **承認者の誤りを指摘する**：全社規程を事務局や情報システム部門だけで決めている事例では、「情報セキュリティ委員会の承認を得るべきである。理由は、各部門の責任者が参加する意思決定機関で承認しなければ、全社に実施させる権限がないためである」と書く。
- **監査の独立性の欠如**：情報システム部の社員が情報システム部を監査している、監査担当が委員会の指揮下にある、といった配置を見つけ、独立した部署又は他部門の監査員に替えるべきだと述べる。
- **CISO の権限**：推進責任者が予算・人員の権限をもたない課長クラスである事例では、経営資源を割り当てる権限をもつ役員クラスを CISO に任命すべきだと述べる。
- **CSIRT の位置付けと権限委譲**：緊急時に委員会の招集を待って対応が遅れた事例では、CSIRT に初動対応（ネットワーク遮断、アカウント停止）の権限をあらかじめ委譲しておくべきだと述べる。
- **部門管理システムの抜け**：部門が独自契約した SaaS から情報が漏れた事例では、情報システム管理者の管理外（シャドーIT）になっていたことを原因として挙げ、台帳への登録と全社基準の適用を提案する。

# System Patterns

## ディレクトリ構成
```
ipa/
├─ 0.0_ガイドライン.md      # ノート作成の一次情報源（依頼パターン・テンプレート・品質基準）
├─ 0.1_試験範囲.md          # 中分類×科目 対応表
├─ 0.2_出題傾向.md          # 出題数の実績データ
├─ 0.3_優先順位.md          # 学習着手順
├─ ipa_試験要綱_v5.6.pdf    # 出題範囲・技術レベルの公式一次情報
├─ A-1/                     # 科目A-1（共通知識）のノート
└─ A-2B/                    # 科目A-2・科目Bのノート（出題範囲がほぼ重なるため統一）
```

## 命名規則
`〈章〉.〈節〉_〈分野名〉.md`。章立ての基準はテキストの章構成に対応（A-1は応用情報テキスト
第1〜12章、A-2Bは支援士テキスト第1〜9章）。着手順とファイル名の章番号順は独立している
（例: A-2Bはセキュリティ関連の章から着手し、基礎の第1章は後回し）。

## ドキュメントテンプレート（要点）
科目A-1のノートは次の構成で一貫する（詳細は [0.0_ガイドライン.md](../0.0_ガイドライン.md) 2節）。

1. タイトル・対応範囲（試験要綱の大分類＞中分類＞小分類の表記をそのまま転記）
2. 「0. 全体像」— 前ノートとのつながり・章立て予告・出題傾向コメント
3. 中見出し（キーワードのまとまりごとの本文、地の文中心）
4. 「N. 試験対策まとめ」— 箇条書きで対比構造・頻出式・引っかけポイント
5. 文末に学習配分コメント（*斜体*）

科目A-2・科目Bのノートはこの型を継承しつつ、「試験対策まとめ」を
「知識の確認（科目A-2向け）」「記述式で問われる観点（科目B向け）」の2部構成にする
（[0.0_ガイドライン.md](../0.0_ガイドライン.md) 10.3節）。

## 文章スタイルの設計判断
- プロース中心（過度な箇条書きを避ける）。表は対比・分類・工程の整理にのみ使う。
- 指定キーワードは初出時に太字にする（網羅チェックを視覚化するため）。
- 対比構造（AとBの違い）を最低2〜3箇所は用意する（試験の出題形式に対応）。
- 計算問題が絡む分野は $$…$$ で式を示し、式の意味も言葉で説明する。

詳細な執筆ルール・品質チェックリストは常に [0.0_ガイドライン.md](../0.0_ガイドライン.md) を正とし、
本ファイルには要点のみを置く（重複記載を避ける）。

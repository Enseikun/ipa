# レクチャーノート：技術要素 ― セキュリティ＞情報セキュリティ管理

対応範囲：情報処理安全確保支援士試験（科目A-1／科目A-2共通）「技術要素」＞「セキュリティ」＞「情報セキュリティ管理」

---

## 0. 全体像 ― なぜこの分野を学ぶのか

前回のノート（情報セキュリティ）では、暗号化・認証・ファイアウォールといった個々の技術要素を見てきました。しかし、優れた技術を導入するだけでは組織は守れません。「どの資産を、どこまで、どのような体制で守るか」を決め、継続的に運用し、外部から見ても信頼できる形にする——この視点の転換が、本ノートで扱う情報セキュリティ管理です。技術が「点」の防御だとすれば、管理は組織全体を貫く「仕組み」の設計にあたります。

本ノートは、次の3段階のストーリーで説明します。①まず、何を守るかという基本的な考え方と、具体的な対策の分類を押さえます。②次に、守るべき対象にどれだけの脅威が存在するかを見積もり、対応を決めるプロセスであるリスクマネジメントを学びます。③最後に、こうした管理体制が適切に機能していることを第三者に証明する仕組み（ISMS認証やセキュリティ評価制度）を見ます。

情報セキュリティは情報処理安全確保支援士試験の別格の最重点分野であり、その中でも情報セキュリティ管理は、科目B（技能）の4つの業務観点のうち「情報セキュリティマネジメントの推進・支援」「情報セキュリティインシデント管理の推進・支援」に直結する領域です。科目A-2でも、CIA三要素・リスクマネジメントの用語・ISMS/プライバシーマークの識別は定番論点です。技術的な対策そのものよりも、「誰が」「どのプロセスで」「何を基準に」判断するかという管理の枠組みを正確に理解することが得点につながります。

---

## 1. 何をどう守るか ― 情報セキュリティ対策の基本

技術的な各論に入る前に、まず「何を達成すれば安全と言えるのか」という目的と、対策の切り口を整理します。

### 1.1 情報セキュリティの3要素

情報セキュリティとは、情報資産について次の3つの性質を維持することと定義されます。

| 要素 | 内容 |
|---|---|
| **機密性** | 許可された者だけが情報にアクセスできる状態を保つこと |
| **完全性** | 情報が破壊・改ざん・消去されていない正確な状態を保つこと |
| **可用性** | 許可された者が必要なときに情報にアクセスできる状態を保つこと |

この3要素（CIA）は、以降のすべての対策・リスクマネジメントの評価軸になります。例えば暗号化は機密性を、ディジタル署名は完全性を、冗長構成は可用性を主に高める対策として位置づけられます。3要素は互いにトレードオフになることもあり（例：アクセス制御を厳しくすると可用性が下がる）、この対比で覚えると整理しやすい論点です。

### 1.2 対策の三分類 ― 人的・物理的・技術的セキュリティ対策

前回のノートで見た「脅威の三分類（物理的・技術的・人的）」に対応する形で、対策も同じ3つの軸で整理されます。

- **人的セキュリティ対策**：従業員教育、規程の周知、誓約書の取得など、人の行動に働きかける対策。
- **物理的セキュリティ対策**：入退室管理、施錠、監視カメラなど、物理的な侵入・災害から守る対策。
- **技術的セキュリティ対策**：暗号化、アクセス制御、ファイアウォールなど、システム・機器で実現する対策。**コンテンツフィルタリング**（有害・業務外のWebサイトへのアクセスを技術的に遮断する仕組み）や、**TPM（Trusted Platform Module）**（暗号鍵の生成・格納をハードウェア上で安全に行うセキュリティチップ）は、この技術的対策の代表例です。

脅威の三分類と対策の三分類が対応している、という接続で覚えると、どの脅威にどの対策を充てるべきかが判断しやすくなります。TPMは前回のノートの耐タンパ性の考え方を、鍵管理という具体的な実装に適用したものとして位置づけられます。

### 1.3 対策を文書として体系化する ― セキュリティポリシー

個々の対策は、場当たり的に導入するのではなく、組織として一貫した文書体系のもとで整備する必要があります。この文書体系全体を**情報セキュリティポリシー**と呼び、一般に次の3階層で構成されます。

1. **情報セキュリティ基本方針**：経営層が「なぜ・何のために情報セキュリティに取り組むか」を宣言する、最上位の方針。
2. **情報セキュリティ対策基準**：基本方針を実現するために、組織が守るべき具体的なルール（規程）。
3. **実施手順**：対策基準を、現場で実行できる作業レベルの手順に落とし込んだもの。

上位から下位へと「方針→ルール→手順」の順に具体化していく工程として捉えると理解しやすい論点です。基本方針だけを整備しても現場は動けず、逆に手順だけがあっても経営としての一貫性が保てないため、3階層すべてが揃って初めて実効性のある対策になります。

## 2. リスクをどう見積もり、どう対応するか ― リスクマネジメント

対策の枠組みができたところで、次は「どこにどれだけの資源を割くべきか」を決めるための考え方、リスクマネジメントを学びます。

### 2.1 リスクの性質と種類

**リスク**とは、望ましくない事態が発生する可能性のことです。リスクは、その性質によって次の2種類に大別されます。

- **純粋リスク**：損失しかもたらさないリスク（火災、機器故障、情報漏えいなど）。
- **投機的リスク**：損失だけでなく利益をもたらす可能性もあるリスク（新規事業への投資など）。

情報セキュリティが対象とするのは主に純粋リスクです。さらに、現代の組織が直面するリスクは発生源によって次のように分類されます。

| リスクの種類 | 内容 |
|---|---|
| **オペレーショナルリスク** | 業務プロセスや人、システムの不備から生じるリスク |
| **サプライチェーンリスク** | 取引先や委託先など、供給網の脆弱性を経由して波及するリスク |
| **外部サービス利用のリスク** | クラウドサービスなど、外部の事業者に委ねた部分で生じるリスク |
| **SNSによる情報発信リスク** | 従業員の不適切な投稿などにより、組織の信用や機密情報が損なわれるリスク |

これらは「自社の内部で完結するか（オペレーショナル）」「取引関係を通じて波及するか（サプライチェーン、外部サービス利用）」「個人の発信が組織に跳ね返るか（SNS）」という広がり方の違いで整理すると覚えやすくなります。

### 2.2 リスクマネジメントの手順

リスクへの対応は、思いつきではなく次の工程で進めます。

1. **リスクアセスメント**：リスクを特定し、発生可能性と影響度を分析・評価する工程。
2. **リスク基準**との照合：あらかじめ組織が定めた「どこまでのリスクを許容するか」という基準と、評価結果を突き合わせる。
3. **リスク対応**：基準を超えるリスクに対して、具体的な処置を選ぶ。

リスク対応は、さらに次の2つのアプローチとその手段に分かれます。

| アプローチ | 手段 | 内容 |
|---|---|---|
| **リスクコントロール**（リスクそのものを変化させる） | **リスク回避** | リスクの原因となる活動自体をやめる |
| | **損失防止** | 事故の発生確率を下げる対策を講じる |
| | **損失削減** | 事故発生時の被害の大きさを抑える対策を講じる |
| | **リスク分散** | 資産や拠点を分けて、一箇所への被害集中を避ける |
| | **リスク集約** | 逆に、管理をまとめることで対策の効率と一貫性を高める |
| **リスクファイナンシング**（金銭的に手当てする） | **リスク保有** | 対策コストとリスクの大きさを比較し、あえて対応せず受け入れる |
| | **リスク移転** | 保険への加入や外部委託など、損失の負担を他者に移す |

リスクコントロールが「事故そのものを起こしにくくする・被害を小さくする」発想であるのに対し、リスクファイナンシングは「起きてしまった損失をどう金銭的に手当てするか」という発想である点が対比のポイントです。なお、リスク移転はリスクコントロールの分類の中で語られることもありますが、金銭的な手当てという性質からリスクファイナンシングの一手段として整理されます。あらゆる対策を講じても、すべてのリスクをゼロにはできず、対応後になお残るリスクを**残留リスク**と呼びます。残留リスクを経営層が許容できる水準まで下げることが、リスクマネジメントの最終目的です。

### 2.3 経営の視点で取り組む ― ガイドラインと専門組織

リスクマネジメントは現場任せにできるものではなく、経営課題として取り組む必要があります。経済産業省とIPAが策定した**サイバーセキュリティ経営ガイドライン**は、経営者が認識すべき原則と、実施すべき指示項目を示した指針です。また、リスクマネジメント全般の国際規格として**JIS Q 31000**があり、業種を問わない汎用的なリスクマネジメントの考え方とプロセスを規定しています。

こうした方針を実務で支えるのが、専門の組織・機関です。

| 名称 | 役割 |
|---|---|
| **情報セキュリティ委員会** | 組織内でセキュリティ方針を審議・決定する経営レベルの会議体 |
| **CSIRT** | 組織内でインシデント対応（検知・分析・復旧）を行うチーム |
| **PSIRT** | 自社製品の脆弱性対応に特化したチーム |
| **SOC（Security Operation Center）** | ログの監視・分析により、インシデントの兆候を検知する専門組織 |
| **JPCERT/CC** | 国内の組織横断でインシデント対応の調整や情報提供を行う中立組織 |
| **J-CRAT** | 標的型サイバー攻撃の被害拡大防止を支援するIPAの活動 |
| **JVN** | 日本国内で使われる製品の脆弱性関連情報を公表するポータルサイト |
| **内閣サイバーセキュリティセンター（NISC）／サイバーセキュリティ戦略本部** | 政府全体のサイバーセキュリティ政策を統括する組織 |
| **CIO／CISO** | CIOは情報戦略、CISOは情報セキュリティを担当する経営層の責任者 |
| **CVE** | 個々の脆弱性を一意に識別するための共通の採番・命名基準 |

CSIRTとPSIRTは「自組織のシステム全般を守るか、自社製品を守るか」という対象範囲の違いで区別し、JPCERT/CCとJVNは「組織間の調整を行う機関か、脆弱性情報を公表する媒体か」という役割の違いで区別すると整理しやすい論点です。CVEは組織ではなく識別基準である点が、他の項目との位置づけの違いとして問われます。

## 3. 管理の仕組みを第三者に証明する ― 認証制度と評価基準

自組織内でリスクマネジメントを回すだけでなく、その体制が適切であることを外部に示す仕組みが整備されています。

### 3.1 ISMSとその認定制度

**ISMS（情報セキュリティマネジメントシステム）**とは、組織が情報セキュリティを継続的に維持・改善するためのマネジメントの枠組みです。ISMSは、**PDCA**（Plan：計画、Do：実行、Check：評価、Act：改善）というサイクルを回し続けることで、変化する脅威に対応し続ける点が特徴です。一度対策を完成させて終わりにするのではなく、継続的な改善を前提とする発想として、前章のリスクマネジメントの手順と結びつけて理解すると整理しやすくなります。

ISMSの構築・運用の基準となる規格が、**ISO/IEC 27002**（旧称：**ISO/IEC 17799**）です。この規格に基づき、組織のISMSが適切に構築・運用されていることを第三者機関が審査し認証するのが**ISMS適合性評価制度**です。日本では、**JIPDEC**（一般財団法人日本情報経済社会推進協会）がこの制度の運営を統括し、審査・認証の実務は**BSI**（British Standards Institution、認証機関の一つ）などの審査登録機関が担います。認証の前提として、**情報セキュリティ監査**（対策が基準どおりに機能しているかを独立した立場から検証する活動）が組み込まれています。こうしたISMSの仕組みを経営レベルで方向づけ、組織全体のセキュリティ対応能力を統制する考え方を**情報セキュリティガバナンス**と呼びます。ISMSが実務上の管理の枠組みであるのに対し、ガバナンスはそれを経営の意思決定に組み込む、より上位の概念として位置づけられます。

### 3.2 プライバシーマーク ― 個人情報に特化した認証

ISMSが情報資産全般を対象とするのに対し、個人情報の取扱いに特化した認証制度が**プライバシーマーク**です。個人情報を適切に保護する体制を整備している事業者を認定する制度で、認証基準として**JIS Q 15001**（個人情報保護マネジメントシステムの要求事項）が用いられます。「情報資産全般を対象とするか、個人情報に限定するか」という対象範囲の違いが、ISMSとプライバシーマークを区別する最頻出の論点です。

### 3.3 製品・システムそのものを評価する基準

ここまでは組織の管理体制を評価する仕組みでしたが、IT製品やシステム自体のセキュリティ機能を評価する国際基準も存在します。それが**ISO 15408**（**CC**：Common Criteriaとも呼ばれ、日本では**JIS X 5070**として規格化）です。ISO 15408では、製品がセキュリティ機能をどれだけ厳密な設計・検証プロセスを経て実装しているかを、**評価保証レベル（EAL）**として段階的に格付けします。レベルが上がるほど、設計仕様の記述方法も厳密になり、機能の記述が自然言語に近い**非形式的設計**から、構造化された記法を用いる**準形式的設計**、さらに数学的な検証が可能な**形式的設計**へと段階的に発展します。

評価保証レベルが「どれだけ厳密に検証されたか」という達成度を表すのに対し、準形式的設計・形式的設計は「設計仕様をどう記述するか」という手段の厳密さを表すという、目的と手段の関係として位置づけられます。組織の管理体制を評価するISMS・プライバシーマークと、製品・システム自体を評価するISO 15408という2つの評価軸の違いを押さえておくと、試験での識別がしやすくなります。

## 4. 試験対策まとめ（重要ポイント）

- **機密性・完全性・可用性（CIA）**：情報セキュリティの目的そのもの。個々の対策がどの要素を主に高めるかを結びつけて覚える。
- **人的・物理的・技術的セキュリティ対策**：前回ノートの脅威の三分類と対応する対策の三分類。TPMやコンテンツフィルタリングは技術的対策の具体例。
- **情報セキュリティポリシーの3階層**：基本方針→対策基準→実施手順という具体化の工程。階層を混同しないこと。
- **純粋リスク と 投機的リスク**：情報セキュリティが扱うのは損失のみをもたらす純粋リスク。
- **リスクコントロール と リスクファイナンシング**：事故そのものを減らす・小さくするか、金銭的に手当てするかの対比。回避・低減（防止／削減）・分散・集約と、保有・移転を対応させて覚える。
- **ISMS と プライバシーマーク**：対象が情報資産全般か個人情報に限定かで区別。認証基準はそれぞれISO/IEC 27002とJIS Q 15001。
- **PDCAサイクル**：ISMSが継続的改善を前提とする仕組みであることを示す最頻出のキーワード。
- **CSIRT と PSIRT と SOC**：組織全体のインシデント対応か、自社製品特化か、監視・検知に特化かで役割を区別する。
- **ISO 15408（CC）と評価保証レベル（EAL）**：組織ではなく製品・システムを評価する基準である点が、ISMS・プライバシーマークとの決定的な違い。
- **残留リスク**：対策後もなお残るリスクであり、リスクマネジメントは残留リスクを許容水準まで下げることが目的であるという結論を押さえる。

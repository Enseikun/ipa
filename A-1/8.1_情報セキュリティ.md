# レクチャーノート：技術要素 ― セキュリティ＞情報セキュリティ

対応範囲：情報処理安全確保支援士試験（科目A-1／科目A-2共通）「技術要素」＞「セキュリティ」＞「情報セキュリティ」

---

## 0. 全体像 ― なぜこの分野を学ぶのか

これまでの技術要素分野（コンピュータ構成要素、システム構成要素、ソフトウェア、データベース、ネットワークなど）では、システムが「正しく機能すること」を中心に見てきました。本ノートで扱う情報セキュリティは、視点を「正しく動くか」から「安全に守られているか」へと転換します。どれほど正確に動くシステムでも、盗聴・改ざん・なりすましにさらされれば意味がありません。

本ノートは、次の4段階のストーリーで説明します。①まず、何を守り、何がそれを脅かすのか（情報資産と脅威・脆弱性）という敵の姿を掴みます。②次に、正しい相手と安全にやり取りするための基礎技術である認証と暗号を学びます。③さらに、ネットワークの境界でそれらの技術を組み合わせて防ぐファイアウォールとセキュリティプロトコルを見ます。④最後に、それらを現場でどう実装するか（検知・防御装置とネットワークセキュリティ）で締めくくります。

情報セキュリティは、情報処理安全確保支援士試験において別格の最重点分野です。科目A-2（専門知識）では25問中17問（68%）がセキュリティから出題され、科目A-1（共通知識）でも30問中4問と他分野の2〜4倍の出題数があります。さらに科目B（技能）でも4つの業務観点のうち3つがセキュリティに直結するため、学習時間の半分以上をこの分野に投じる価値があります。定番論点は、暗号方式・認証方式の識別、攻撃手法の名称と対策の対応、ファイアウォール構成、FRR／FARのようなトレードオフです。ここで扱う用語は、支援士テキストの「情報セキュリティにおける脅威」「脆弱性」「アクセス制御と認証」「暗号」といった、より専門的な章の土台にもなります。

## 1. 何を守り、何が脅かすのか ― 情報資産と脅威・脆弱性

対策を学ぶ前に、まず守るべきものと敵の手口を知る必要があります。情報資産にはどのような脅威があり、脅威はどのような手口（脆弱性を突く攻撃）で実行されるのかを、種類ごとに整理します。

### 1.1 情報資産と脅威の三分類

**情報資産**とは、組織が保有するデータ、それを扱うハードウェア・ソフトウェア、さらには人や組織の信用そのものを含む、保護すべき対象の総称です。情報セキュリティとは、この情報資産を脅威から守る活動と言えます。

脅威は、発生源によって次の3種類に分類されます。

| 分類 | 内容 | 具体例 |
|---|---|---|
| **物理的脅威** | 設備・機器そのものへの被害 | 地震・火災、機器の盗難・破壊 |
| **技術的脅威** | 情報システムの技術的な弱点を突く | マルウェア感染、不正アクセス、盗聴 |
| **人的脅威** | 人の行動・判断に起因する | 誤操作、内部不正、ソーシャルエンジニアリング |

試験では、事例（例：清掃業者を装って侵入する）がどの分類に該当するかを判定させる問題が定番です。人的脅威は技術で完全には防げない点が、後述する対策（教育・規程）の必要性につながります。

### 1.2 プログラムに潜む脅威 ― マルウェアの分類

**マルウェア**とは、利用者の意図に反して不正な動作を行う悪意あるソフトウェアの総称です。感染経路や挙動によって次のように分類されます。

| 名称 | 特徴 |
|---|---|
| **トロイの木馬** | 正常なソフトウェアを装って侵入し、内部で不正な動作を行う。自己増殖はしない |
| **ルートキット** | 侵入後に自身や他の不正プログラムの痕跡を隠蔽するツール一式 |
| **マクロウイルス** | 文書ソフトのマクロ機能を悪用して感染するウイルス |
| **ワーム** | 単独のプログラムとして、ネットワークを通じて自己増殖しながら拡散する |
| **ボット** | 外部からの指令（C&Cサーバ）で遠隔操作され、DDoS攻撃などに悪用される |
| **ランサムウェア** | ファイルを暗号化するなどして使用不能にし、復旧と引き換えに金銭を要求する |
| **バックドア** | 正規の認証を経ずに侵入できる裏口を仕込む |
| **スパイウェア** | 利用者に気づかれずに個人情報や操作履歴を収集し外部へ送信する |

試験では「自己増殖するか」「単独で動作するか」「金銭を要求するか」といった挙動の違いで名称を判定させる問題が頻出です。ワームとウイルスの違い（宿主プログラムが必要かどうか）は特に狙われやすい論点です。

### 1.3 人を経由する攻撃 ― クラッキングとソーシャルエンジニアリング

**クラッキング**とは、悪意を持ってシステムに不正侵入したり破壊行為を行ったりすることです。同じ「システムに深く介入する」行為でも、正当な許可のもとで脆弱性を検証するホワイトハッカーの活動とは目的が対照的です。

**ソーシャルエンジニアリング**とは、技術的手段ではなく人の心理的な隙や行動のミスにつけ込んで機密情報を入手する手法です。電話でシステム管理者を装いパスワードを聞き出す、廃棄書類を漁る（トラッシング）などが典型例です。技術的な防御をどれだけ固めても、人的脅威であるソーシャルエンジニアリングは教育や規程の整備でしか防げないという点が、試験でも問われるポイントです。

### 1.4 パスワードを狙う攻撃

利用者認証の要であるパスワードは、次のような手口で狙われます。3つ以上の類似手口が並ぶため、総当たり系と流用系に分けて整理します。

| 攻撃名 | 手口 |
|---|---|
| **辞書攻撃** | 辞書に載っている単語や、よく使われる文字列を順に試す |
| **ブルートフォース攻撃** | あり得る文字の組み合わせをすべて総当たりで試す |
| **リバースブルートフォース攻撃** | パスワードを固定し、逆にID（利用者名）を総当たりで変えて試す |
| **レインボー攻撃** | パスワードとハッシュ値の対応表（レインボーテーブル）を事前に用意し、照合だけで高速に解析する |
| **パスワードリスト攻撃** | 他サービスから流出したID・パスワードの組をそのまま別サービスに試す |

ブルートフォース攻撃とリバースブルートフォース攻撃は「どちらを固定し、どちらを総当たりにするか」という対比で覚えると整理しやすい論点です。レインボー攻撃は計算を事前に済ませておく点でブルートフォース攻撃と異なり、パスワードリスト攻撃は「利用者が複数サービスで同じパスワードを使い回す」という人の習慣を突く点で、他の攻撃と性質が異なります。

### 1.5 Webとネットワークを狙う攻撃

Webアプリケーションやネットワークの仕組みそのものを悪用する攻撃には、次のようなものがあります。

| 攻撃名 | 狙う対象・手口 |
|---|---|
| **DNSキャッシュポイズニング** | DNSサーバのキャッシュに偽の名前解決情報を注入し、利用者を偽サイトへ誘導する |
| **SQLインジェクション** | Webアプリの入力欄に不正なSQL文を注入し、データベースを不正に操作する |
| **ゼロデイ攻撃** | 脆弱性の修正パッチが提供される前（対策が存在しない期間）を突いて攻撃する |
| **水飲み場型攻撃** | 標的がよく訪れるWebサイトを改ざんし、訪問を待ち伏せてマルウェアを感染させる |
| **IPスプーフィング** | 送信元IPアドレスを偽装し、別の送信者になりすます |
| **セッションハイジャック** | 通信中のセッションID（セッション情報）を奪い、正規利用者になりすまして通信を乗っ取る |
| **中間者攻撃** | 通信する2者の間に割り込み、通信内容を盗聴・改ざんする |
| **SEOポイズニング** | 検索エンジンの検索結果を不正に操作し、悪意あるサイトを上位表示させて誘導する |
| **クリックジャッキング** | 見えない透明な要素をWebページに重ね、利用者に意図しないクリックをさせる |
| **フットプリンティング** | 本格的な攻撃の前に、対象組織の情報（ドメイン、公開サーバの構成など）を収集する事前調査 |

これらは「攻撃の準備段階（フットプリンティング）」「経路への割り込み（IPスプーフィング、中間者攻撃、セッションハイジャック）」「誘導・騙し（DNSキャッシュポイズニング、水飲み場型、SEOポイズニング、クリックジャッキング）」「システムそのものへの侵入（SQLインジェクション、ゼロデイ攻撃）」という4つの位置づけで整理すると覚えやすくなります。

### 1.6 ハードウェアとブラウザの弱点

**耐タンパ性**とは、ICカードなどのハードウェアが、内部の秘密情報（鍵など）を外部から解析・改ざんされにくい性質を指します。これに対する代表的な攻撃が**サイドチャネル攻撃**で、処理時間や消費電力、電磁波といった動作時に漏れ出る副次的な情報（サイドチャネル情報）を解析し、内部の鍵情報を推測する手法です。耐タンパ性の高い設計は、このサイドチャネル攻撃への対策として位置づけられます。

**クロスサイトスクリプティング（XSS）**とは、脆弱なWebサイトに悪意あるスクリプトを埋め込み、閲覧した利用者のブラウザ上で実行させる攻撃です。これにより、**クッキー**（Webサイトが利用者のブラウザに保存させる、セッションIDなどの小さなデータ）が盗まれ、セッションハイジャックにつながることがあります。クッキーの管理はこの後4.3節で技術的な分類（ファーストパーティ／サードパーティ）として再度扱います。

## 2. 正しい相手と安全にやり取りするために ― 認証と暗号の基礎

敵の手口を把握したところで、次はそれに対する基礎技術です。「盗聴されても読めなくする」ための暗号と、「相手が本物であることを確かめる」ための認証は、情報セキュリティの二本柱です。

### 2.1 暗号の基本 ― 共通鍵と公開鍵

**暗号化**とは、平文を第三者に読めない形式（暗号文）に変換することであり、**復号**とはその暗号文を元の平文に戻すことです。暗号化・復号の方式は、鍵の使い方によって大きく2つに分かれます。

- **共通鍵暗号方式**：暗号化と復号に同じ鍵（共通鍵）を使う方式です。処理が高速な一方、通信相手ごとに鍵を安全に配送・管理する必要があり、相手が増えるほど鍵の数が組合せ的に増える「鍵管理問題」を抱えます。
- **公開鍵暗号方式**：暗号化用の公開鍵と復号用の秘密鍵という異なる鍵の組を使う方式です。公開鍵は誰に渡しても安全なため鍵配送問題を解決しますが、演算が複雑で共通鍵方式より低速です。

両者は「速度は共通鍵、鍵配送のしやすさは公開鍵」という対比で覚えると整理しやすい論点です。この長所を両取りするのが**ハイブリッド暗号方式**で、データ本体は高速な共通鍵暗号方式で暗号化し、その共通鍵（セッション鍵）自体を公開鍵暗号方式で暗号化して相手に送る方式です。TLSなど、実際のセキュリティプロトコルの多くがこの発想を採用しており、3章で再び登場します。

### 2.2 改ざんとなりすましを防ぐ ― ハッシュ関数とメッセージ認証

暗号化がデータを「読めなくする」技術であるのに対し、ここで扱うのはデータが「途中で変えられていないか」「本当にその相手が送ったか」を確かめる技術です。

**ハッシュ関数**とは、任意の長さのデータから固定長の値（ハッシュ値、メッセージダイジェスト）を生成する関数です。同じ入力からは常に同じハッシュ値が得られ、逆にハッシュ値から元のデータを復元することはできません。この性質は2つの困難性で説明されます。

- **原像計算困難性**：あるハッシュ値から、それを生成した元のデータ（原像）を求めることが計算量的に困難であるという性質。
- **衝突発見困難性**：異なる2つのデータから同じハッシュ値が生成される組（衝突）を見つけることが計算量的に困難であるという性質。

この2つの困難性のおかげで、ハッシュ値はデータの改ざん検知に利用できます。ただし、ハッシュ値だけでは「誰が送ったか」までは分かりません。そこで発展するのが認証の仕組みで、目的に応じて3種類に整理されます。

- **相手認証**：通信している相手が正当な本人であることを確認すること。
- **メッセージ認証**：受け取ったメッセージが改ざんされていないこと（完全性）を確認すること。**メッセージ認証子（MAC）**は、共通鍵とメッセージからハッシュ関数を用いて生成する値で、送受信者双方が共通鍵を持つことで改ざん検知と送信者の確認を同時に行えます。
- **ディジタル署名（メッセージのディジタル認証）**：送信者の秘密鍵でメッセージのハッシュ値を暗号化したものを添付する仕組みです。受信者は送信者の公開鍵で復号し、自分で計算したハッシュ値と照合することで、改ざんの検知に加え、送信者本人しか作成できない（否認防止）ことまで確認できます。

メッセージ認証子とディジタル署名はどちらも改ざん検知に使えますが、メッセージ認証子は共通鍵を共有する当事者間でしか検証できないのに対し、ディジタル署名は公開鍵さえあれば誰でも検証できるという違いが試験でも問われるポイントです。

### 2.3 「本人か」を確かめる ― 認証方式のバリエーション

相手認証を実現する具体的な方式は、何を確認の根拠にするかによって多様化しています。**アクセス管理**（誰が何にアクセスできるかを制御する仕組み）の入口として、まず本人確認の手段を整理します。

- **パスワード認証**：利用者が記憶している文字列（知識）で本人確認する、最も基本的な方式。
- **BASIC認証**：HTTPの標準機能で実装される、利用者IDとパスワードによる簡易な認証方式。通信が暗号化されない場合は盗聴に弱い。
- **2要素認証**：知識（パスワード）・所持（ICカード、スマートフォン）・生体（指紋）のうち異なる2種類の要素を組み合わせて認証する方式。1要素が破られても他方が防波堤になる。
- **バイオメトリック認証**：指紋や虹彩、静脈といった身体的特徴（生体情報）で本人確認する方式。忘却・紛失の心配がない一方、誤判定の可能性がある。この誤判定は**FRR（本人拒否率）**と**FAR（他人受入率）**という2つの指標で評価され、両者はトレードオフの関係にあります。判定の閾値を厳しくするとFARは下がりますがFRRは上がり、逆も成り立ちます。
- **SSL/TLS認証**：通信の暗号化と同時に、サーバ証明書（クライアント証明書）によって通信相手が正当であることを確認する方式。
- **RADIUS認証**：利用者認証の要求を認証サーバに集約して一元管理する方式。具体的な仕組みは4.1節のRADIUSプロトコルとして扱います。

さらに、Web特有の文脈では次のような発展形があります。

- **3Dセキュア**：オンラインのクレジットカード決済時に、カード情報に加えて、カード会社に事前登録したパスワードなどで本人確認を行う追加認証の仕組み。
- **リスクベース認証**：普段と異なる場所・端末からのアクセスなど、「いつもと違う」状況を検知した場合にのみ追加の認証を要求する方式。**秘密の質問**（あらかじめ登録した質問への回答）は、この追加認証の代表的な手段の一つです。
- **SAML**：異なるドメイン間で認証情報や属性情報を安全にやり取りするためのXMLベースの標準規格です。これにより、一度のログインで複数の関連サービスを利用できる**シングルサインオン（SSO）**が実現します。1つのIDで複数システムにアクセスできる利便性の裏返しとして、そのIDが破られた場合の影響範囲が広がる点が試験でも問われます。

認証方式が多様化する理由は、「何を根拠にするか（知識・所持・生体）」と「どの範囲で信頼を広げるか（単一サービス内かドメインをまたぐか）」という2軸で整理すると、名称と特徴の対応が覚えやすくなります。

### 2.4 証明書で信頼を裏付ける ― 認証局とその周辺

公開鍵暗号方式には一つ弱点があります。「この公開鍵は本当にその人（サーバ）のものか」を、公開鍵単体からは確認できないという問題です。この問題を解決するのが**認証局（CA）**で、公開鍵の持ち主の身元を審査したうえで、その公開鍵と持ち主情報を結び付けた**ディジタル証明書**を発行する第三者機関です。

証明書は永久に有効ではなく、秘密鍵の漏えいなどにより失効することがあります。失効した証明書の一覧を**CRL（証明書失効リスト）**と呼び、利用者はこれを確認することで失効済みの証明書を信頼してしまう事態を防げます。ただし、CRLは定期的に配布される一覧であるため、最新の失効情報が反映されるまでに時間差が生じます。この弱点を補うのが**OCSP**で、証明書の有効性を認証局にリアルタイムに問い合わせるプロトコルです。CRLが「更新される名簿を自分で確認する」方式であるのに対し、OCSPは「その場で本人に確認する」方式と捉えると理解しやすいでしょう。認証局・証明書・CRLをどう組み合わせて社会全体の信頼基盤とするかは、3.3節の公開鍵基盤（PKI）で改めて扱います。

## 3. 境界で防ぐ ― ファイアウォールとセキュリティプロトコル

2章で学んだ認証・暗号という部品を、実際にネットワークの境界でどう組み合わせて使うかを見ていきます。

### 3.1 境界を作る ― ファイアウォールとDMZ

**ファイアウォール**とは、組織内部のネットワークと外部（インターネット）の境界に設置し、通過させる通信を制御する仕組みです。代表的な実装方式は次の2つです。

- **パケットフィルタリング方式**：パケットのIPアドレスやポート番号といったヘッダ情報だけを見て通過の可否を判定する方式。処理は高速だが、通信の中身までは検査できない。
- **アプリケーションゲートウェイ方式**：アプリケーション層まで踏み込んで通信内容を中継・検査する方式。中身まで細かく制御できる分、処理負荷が高い。

処理速度を取るか検査の深さを取るかという対比で覚えると整理しやすい論点です。ファイアウォールの内側と外側の中間に設けられる緩衝地帯が**DMZ（非武装地帯）**で、外部に公開する必要があるWebサーバやメールサーバをここに置くことで、万一そのサーバが乗っ取られても内部ネットワークへの被害を限定できます。

**プロキシサーバ**は、内部の利用者に代わって外部と通信を中継するサーバで、利用者の身元を外部から隠しつつ、アクセス制御やキャッシュによる高速化を行います。これと役割が対称なのが**リバースプロキシ**で、外部からのアクセスを受け、内部の複数のサーバに代わって応答する（内部サーバの構成を外部から隠す）サーバです。「利用者を外部から守るのがプロキシ、サーバを外部から守るのがリバースプロキシ」という対比で覚えると整理しやすい論点です。

### 3.2 攻撃の流れを捉える ― サイバーキルチェーンとフォレンジック

**サイバーキルチェーン**とは、標的型攻撃が「偵察」「武器化」「配送」「攻撃実行」「インストール」「遠隔操作（C&C確立）」「目的の実行」という段階を踏んで進行するというモデルです。攻撃を一つの点として捉えるのではなく、連鎖（チェーン）として捉え、どの段階で断ち切るかを考える発想が試験でも問われます。1.5節のフットプリンティングは、このモデルの最初期段階（偵察）に位置づけられます。

攻撃者は、公開されている脆弱性を突くために**エクスプロイトコード**（脆弱性を実際に悪用するために作成されたプログラムやコード）を用いることがあります。一方、攻撃を受けた側が事後に行うのが**フォレンジック**で、インシデントの原因究明や法的証拠の確保のために、システムのログやディスクの内容を保全・解析する活動です。攻撃の「実行手段」と「事後対応」という対の関係として位置づけられます。

### 3.3 通信を暗号化する規格 ― TLSと公開鍵基盤

暗号・認証の部品を実際の通信規格として標準化したものが**セキュリティプロトコル**です。その代表が**TLS（Transport Layer Security）**で、Webブラウザとサーバ間などの通信において、2.1節のハイブリッド暗号方式を用いてデータを暗号化するとともに、2.4節のディジタル証明書によって通信相手の真正性を確認します。

こうした証明書・認証局による信頼の枠組みを社会インフラとして体系化したものが**公開鍵基盤（PKI）**です。認証局、ディジタル証明書、CRL・OCSPといった2.4節の要素をすべて含む、公開鍵暗号を安全に利用するための総合的な仕組みとして位置づけられます。

電子メールの世界にもこの発想は応用されており、代表的な規格が2つあります。

- **S/MIME**：公開鍵基盤（PKI）と認証局が発行する証明書を利用して、メールの暗号化とディジタル署名を行う規格。
- **PGP**：認証局を介さず、利用者どうしが互いの公開鍵の正当性を保証し合う（信頼の輪）という分散的な方式で、メールの暗号化と署名を行う規格。

S/MIMEとPGPは「中央集権的な第三者機関（認証局）を信頼の起点にするか、利用者間の相互保証を信頼の起点にするか」という対比で整理すると理解しやすい論点です。

### 3.4 メールを守るプロトコル群

電子メールは仕組み上「送信者を名乗るだけで誰でも送れてしまう」という弱点があり、これを補うための仕組みが複数あります。

| 名称 | 目的 |
|---|---|
| **SMTP-AUTH** | メール送信時（SMTP）に利用者ID・パスワードによる認証を要求し、第三者による無断中継（不正リレー）を防ぐ |
| **POP before SMTP** | メール受信（POP）時の認証に成功した利用者だけに、一定時間だけSMTPでの送信を許可する |
| **SPF（Sender Policy Framework）** | 送信元ドメインがあらかじめ公開している正規の送信メールサーバの一覧（DNSのTXTレコード）と、実際の送信元を照合し、なりすましメールを検知する |
| **DNSSEC** | DNSの応答に電子署名を付与し、1.5節のDNSキャッシュポイズニングのような偽の名前解決情報への対策とする |

SMTP-AUTHとPOP before SMTPは「送信の直前に認証するか、直前の受信認証を流用するか」という対比、SPFとDNSSECは「メールの送信元ドメインを検証するか、DNSの応答そのものの正当性を検証するか」という対象の違いが試験で問われるポイントです。

### 3.5 なりすましを防ぐ ― チャレンジレスポンス方式とリプレイ攻撃

パスワードそのものをネットワーク上に流さずに認証する工夫が**チャレンジレスポンス方式**です。サーバが毎回異なるランダムな値（チャレンジ）を送り、利用者側はパスワードとそのチャレンジを組み合わせてハッシュ関数などで計算した値（レスポンス）を返します。サーバは同じ計算を行い、結果が一致すれば本人と認めます。パスワード自体を送信しないため盗聴に強いという特徴があります。

この方式が対策として意識しているのが**リプレイ攻撃**で、過去に盗聴した正規の認証データ（レスポンスなど）をそのまま再送信し、なりすましを試みる攻撃です。チャレンジレスポンス方式では、チャレンジが毎回異なる値であるため、過去のレスポンスを再送しても一致せず認証は成立しません。攻撃とその対策が対になる論点として覚えておくとよいでしょう。

## 4. 現場に実装する ― 検知・防御装置とネットワークセキュリティ

最後に、ここまでの技術・プロトコルを、実際の製品・システムとしてどう実装するかを見ていきます。

### 4.1 「誰か」を確かめる基盤 ― 認証サーバ

2.3節で触れたRADIUS認証を実現するのが**認証サーバ**です。利用者認証の要求を1台の認証サーバに集約することで、多数のアクセスポイントやルータそれぞれに利用者情報を持たせる必要がなくなり、管理が一元化されます。この仕組みを実現する代表的なプロトコルが**RADIUS**で、認証・認可・アカウンティング（利用記録）の機能を提供します。RADIUSを拡張し、よりセキュリティと拡張性を高めたプロトコルが**Diameter**で、RADIUSの後継として位置づけられます。

### 4.2 侵入を検知・防止する

ネットワークやサーバへの不正な侵入を監視・防御する装置には、役割の異なる複数の種類があります。

| 名称 | 役割 |
|---|---|
| **IDS（侵入検知システム）** | 不正な通信やアクセスの兆候を検知し、管理者に通知する。遮断は行わない |
| **ネットワーク型IDS** | ネットワーク上を流れる通信全体を監視する |
| **ホスト型IDS** | 監視対象のサーバ（ホスト）自体にインストールし、そのホストへの侵入を監視する |
| **IPS（侵入防止システム）** | 不正な通信を検知した際に、通知だけでなく自動的に遮断する |
| **WAF（Web Application Firewall）** | Webアプリケーションへの通信内容を検査し、SQLインジェクションやXSSといったアプリケーション層の攻撃を防ぐ |
| **ハニーポット** | 意図的に脆弱に見せかけたおとりのシステムを用意し、攻撃者を誘い込んで手口を観察・記録する |
| **サンドボックス** | プログラムを隔離された仮想環境の中で実際に実行し、安全を確認してから本番環境に反映する仕組み |

IDSとIPSは「検知して知らせるだけか、検知して自動的に遮断するか」という対比で覚えると整理しやすい論点です。またWAFは3.1節のファイアウォールがネットワーク層・トランスポート層の制御であるのに対し、アプリケーション層の内容まで検査する点で役割が異なります。

これらの装置が検知の対象とする攻撃の手口として、**バッファオーバーフロー**（プログラムが確保した記憶領域を超えるデータを送り込み、意図しないコードを実行させる攻撃）と、**ポートスキャン**（対象機器の各ポートに順に接続を試み、稼働しているサービスや脆弱性を調べる事前調査）があります。ポートスキャンは3.2節のフットプリンティングと同様、本格的な攻撃の前段階に位置づけられます。

### 4.3 通信経路とアプリを守る

**HTTPS**は、HTTP通信を3.3節のTLSで暗号化した規格です。ブラウザとWebサーバ間の通信を暗号化し、盗聴や改ざん、なりすましを防ぎます。

3.1節のアプリケーションゲートウェイ方式は、Webサイトの閲覧を仲介する仕組みとしても利用され、これによって**クッキー**の扱いにも区別が生まれます。

- **ファーストパーティクッキー**：現在閲覧しているサイト自身が発行するクッキー。ログイン状態の保持などに使われる。
- **サードパーティクッキー**：閲覧しているサイトとは異なる第三者（広告配信事業者など）が発行するクッキー。複数サイトをまたいだ利用者の行動追跡に使われ、プライバシー上の懸念から近年は制限が進んでいる。

社内から外部のクラウド上のデスクトップ環境に安全にアクセスする仕組みとして**VDI（仮想デスクトップ基盤）**があります。実際の処理をすべてデータセンター側の仮想マシン上で行い、手元の端末には画面情報だけを転送するため、情報漏えいのリスクを抑えられます。

### 4.4 ネットワーク層・無線LANで暗号化する

3.3節のTLSがアプリケーション寄りの層で通信を暗号化するのに対し、**IPSec**はより下位のIP層で通信を暗号化するプロトコル群です。IPSecは主に次の要素で構成されます。

- **AH（Authentication Header）**：通信データの改ざん検知と送信元の認証を行うが、データ自体の暗号化は行わない。
- **ESP（Encapsulating Security Payload）**：改ざん検知・送信元認証に加えて、データそのものの暗号化も行う。
- **IKE（Internet Key Exchange）**：AHやESPで使用する暗号鍵を、通信の両者間で安全に交換・共有するためのプロトコル。

AHとESPは「暗号化を伴うかどうか」という対比、IKEはそれらの「鍵をどう用意するか」という前段階の役割として位置づけられます。アプリケーション層に依存しないため、IPSecを使えばどのアプリケーションの通信でも一括して保護できる点が特徴です。

無線LANの通信も同様に暗号化規格が世代交代してきました。

| 規格 | 位置づけ |
|---|---|
| **WPA** | WEP（旧来の脆弱な暗号方式）に代わって登場した規格。暗号化方式に**TKIP**を採用し、鍵を一定時間ごとに自動更新することで解析を困難にした |
| **WPA2** | より強固な暗号アルゴリズム（AES）を採用した規格 |
| **WPA3** | さらに強化された規格で、パスワードが弱い場合でも解析されにくい鍵交換方式を採用している |

WPA→WPA2→WPA3という発展の流れと、その中でTKIPがWPAの暗号化方式として登場した位置づけを合わせて覚えると、規格名と技術要素の対応が整理しやすくなります。

## 5. 試験対策まとめ（重要ポイント）

- **共通鍵暗号方式 と 公開鍵暗号方式**：処理速度は共通鍵が有利、鍵配送のしやすさは公開鍵が有利という対比。ハイブリッド暗号方式はこの両者を組み合わせたもので最頻出。
- **原像計算困難性 と 衝突発見困難性**：ハッシュ関数が改ざん検知に使える根拠となる2つの性質。「元データを求めにくいか」「同じ値になる別データを見つけにくいか」の違いで区別する。
- **メッセージ認証子 と ディジタル署名**：どちらも改ざん検知に使えるが、共通鍵を使うか公開鍵を使うかで検証できる範囲が異なる。
- **FRR と FAR**：生体認証の精度指標で、閾値の設定によりトレードオフの関係になる点が頻出。
- **IDS と IPS**：検知のみか、検知に加えて自動遮断まで行うかの違い。ネットワーク型／ホスト型の区別も併せて問われる。
- **パケットフィルタリング型 と アプリケーションゲートウェイ型**：ファイアウォールの2方式。検査の深さと処理速度がトレードオフ。
- **SPF と DNSSEC と S/MIME**：なりすまし対策だが対象が異なる。SPFは送信元ドメインの検証、DNSSECはDNS応答の正当性検証、S/MIMEはメール本文自体の署名・暗号化。
- **チャレンジレスポンス方式**：パスワードそのものを送らないことでリプレイ攻撃を防ぐ仕組みとして、攻撃と対策をセットで押さえる。
- **辞書攻撃・ブルートフォース攻撃・レインボー攻撃・パスワードリスト攻撃**：総当たりか、事前計算済みの表を使うか、他サービスからの流出情報を流用するかで区別する定番の識別問題。
- **WPA／WPA2／WPA3 と TKIP**：無線LANの暗号規格の世代と、その暗号化方式名の対応関係。

# レクチャーノート：技術要素 ― 5.1 ユーザーインタフェース

対応範囲：応用情報技術者試験・情報処理安全確保支援士試験（午前I／午前II共通）「技術要素」＞「情報デザイン」

---

## 0. 全体像 ― なぜこの分野を学ぶのか

これまでのノートでは、コンピュータの内部構造やOSの仕組みなど、利用者からは見えない部分を中心に扱ってきました。本ノートで扱う**ユーザーインタフェース**は、逆に「人間とコンピュータが実際に向き合う接点」がテーマです。①使いやすさをどう設計し、どう評価するか（**ユーザーインタフェース技術**）、②画面や入力データの具体的な設計をどう行うか（**インタフェース設計**）という2段階のストーリーで説明します。

これまでの分野が「正しく動くか」を主眼としていたのに対し、本分野は「人間にとって使いやすいか・分かりやすいか」という、評価の軸そのものが異なる点が特徴です。出題傾向としては、ユーザビリティ評価手法の名称と手法の内容の対応、GUI部品の名称と用途、コード設計の種類とチェック方式の対応が知識問題として頻出です。

## 1. ユーザーインタフェース技術 ― 使いやすさをどう設計・評価するか

### 1.1 ユーザビリティ

**ユーザビリティ**とは、ある利用者が、ある特定の状況のもとで、システムやサービスを利用して目的を達成する際の「使いやすさ」の度合いを指す概念です。単に「操作が簡単かどうか」だけでなく、効果的に（目的を正しく達成できるか）、効率的に（少ない手間で達成できるか）、そして利用者が満足できるか、という複数の側面を含みます。

**JIS（日本産業規格）**では、ユーザビリティを「特定の利用状況において、特定の利用者によって、ある製品が、有効さ・効率・利用者の満足度をもって特定の目標を達成するために用いられる度合い」といった趣旨で定義しています。「利用者」「利用状況」「目標」という条件によってユーザビリティの評価は変わり得る、という相対的な概念である点がポイントです。

ユーザビリティを高めるための具体的な指針として広く知られているのが**ユーザビリティの10原則**（ヤコブ・ニールセンが提唱したことで知られる、ユーザビリティ評価の際のヒューリスティック＝経験則）です。「システムの状態を常に利用者に分かるようにする」「利用者が使う言葉・概念でシステムを表現する」「利用者に自由と主導権を持たせる（元に戻せるようにする）」「一貫性と標準を保つ」「エラーの発生を未然に防ぐ」「記憶に頼らせず、選択肢を見えるようにする」「柔軟性と効率性を持たせる」「無駄のない最小限のデザインにする」「エラーからの回復を分かりやすく支援する」「ヘルプとマニュアルを用意する」という10項目にまとめられており、後述するヒューリスティック評価法の基準として使われます。

### 1.2 インフォメーションアーキテクチャ

**インフォメーションアーキテクチャ（情報アーキテクチャ）**は、Webサイトやアプリケーションの中にある、膨大な情報やコンテンツを、利用者が目的の情報にたどり着きやすいように、**整理・分類し、構造化する**設計の考え方です。個々の画面デザインの見た目の話ではなく、「どの情報がどこにあり、どうつながっているか」という、サイト・アプリ全体の骨組み（構造）を設計する活動である、という点が重要です。後述する「パンくずリスト」のようなナビゲーション要素は、このインフォメーションアーキテクチャの設計結果を利用者に伝えるための具体的な手段の一つです。

### 1.3 ユーザビリティの評価手法

設計したシステムが実際に使いやすいかどうかを確かめるためには、様々な評価手法が用いられます。代表的な手法を、性質の異なるものとして対比しながら整理します。

- **アンケート法**：多数の利用者に対して質問票（アンケート）を配布し、システムの使いやすさについての意見や満足度を回答してもらう手法。定量的なデータを多くの利用者から効率よく集められます。
- **回顧法**：利用者にシステムを実際に使ってもらった**後で**、その体験を振り返りながら、どこで困ったか、何を感じたかを語ってもらう手法。使用中ではなく事後の記憶に基づく点が特徴です。
- **思考発話法**：利用者にシステムを実際に使ってもらいながら、その場で頭に浮かんだこと（考えていること、迷っていること、感じたこと）を**声に出して話してもらいながら**観察する手法。回顧法とは異なり、操作しているまさにその瞬間の思考過程を直接観察できる点が強みです。
- **認知的ウォークスルー法**：専門家（評価者）が、実際の利用者の立場に立って、想定される操作の手順を一つひとつ**歩きながら（ウォークスルー）**たどり、各画面や各操作の段階で利用者が迷わず正しく次の行動を選べるかどうかを検証する手法。利用者を集めずに、専門家の視点からシミュレーション的に評価できます。
- **ヒューリスティック評価法**：専門家が、前述の「ユーザビリティの10原則」のような、経験則（ヒューリスティック）に基づくチェックリストと照らし合わせながら、システムの画面や操作性を評価する手法。実際の利用者を必要とせず、専門知識をもとに比較的短時間・低コストで評価できる点が特徴です。

これらの手法は、大きく「実際の利用者に協力してもらう手法（アンケート法・回顧法・思考発話法）」と「専門家が代わりに評価する手法（認知的ウォークスルー法・ヒューリスティック評価法）」という軸、また「使用中に観察するか（思考発話法）・使用後に振り返るか（回顧法・アンケート法）」という軸で整理すると理解しやすくなります。

### 1.4 A/Bテスト

**A/Bテスト**は、デザインや機能が異なる2種類（あるいはそれ以上）のバージョン（AパターンとBパターン）を、実際の利用者に対して無作為に振り分けて同時に提供し、クリック率やコンバージョン率（成約率）といった実際の利用データを比較することで、どちらがより効果的かを客観的に判断する手法です。前述の評価手法の多くが少人数を対象とした定性的な評価であるのに対し、A/Bテストは実運用環境で大量の利用者データを用いた定量的な比較検証を行える点が特徴で、Webサービスの改善に広く使われています。

### 1.5 アクセシビリティ

**アクセシビリティ**は、高齢者や障がいのある人を含む、より幅広い利用者が、心身の状態や利用環境に関わらず、情報やサービスに**アクセスし、利用できる**度合いを指す概念です。前述の「ユーザビリティ」が、想定される利用者にとっての「使いやすさ」を追求する概念であるのに対し、アクセシビリティは、より幅広い（多様な状況の）利用者が、そもそも**利用できるかどうか**という、利用の可能性そのものに焦点を当てている点で異なります。後述する「ユニバーサルデザイン」は、このアクセシビリティを実現するための設計思想の一つとして位置づけられます。

### 1.6 レスポンシブWebデザイン

パソコン、タブレット、スマートフォンなど、Webサイトを閲覧する端末の画面サイズは多様化しています。**レスポンシブWebデザイン**は、1つのWebページのHTML・CSSを、閲覧する端末の画面サイズに応じて**自動的にレイアウトを最適化（応答＝レスポンシブに変化）させる**設計手法です。端末ごとに別々のページを用意する必要がなく、1つのソースコードで様々な画面サイズに対応できるため、開発・保守の効率化と、どの端末からアクセスしても見やすい表示を両立できます。

### 1.7 GUI部品

**GUI（Graphical User Interface）**は、文字だけのコマンド入力ではなく、画面上の図形やアイコンを、マウスやタッチ操作で直感的に操作できるようにしたユーザーインタフェースの方式です。GUIを構成する代表的な部品（コントロール）には、それぞれ用途に応じた使い分けがあります。

| GUI部品 | 特徴・用途 |
|---|---|
| **プルダウンメニュー** | 項目名をクリックすると、下方向に選択肢の一覧が開くメニュー |
| **ポップアップメニュー** | 画面上の任意の位置（右クリックなど）で、その場に選択肢が浮かび上がって表示されるメニュー |
| **ラジオボタン** | 複数の選択肢の中から**1つだけ**選ぶための部品（丸い円が特徴） |
| **チェックボックス** | 複数の選択肢の中から**複数（0個以上）**を自由に選ぶための部品（四角い箱が特徴） |
| **リストボックス** | 複数の選択肢を一覧（リスト）として表示し、その中から選ばせる部品 |
| **テキストボックス** | 利用者が自由に文字を入力できる部品 |
| **コンボボックス** | テキストボックスとリストボックス（またはプルダウンメニュー）を組み合わせた部品で、一覧から選ぶことも、自分で直接文字を入力することもできる |

特に「**ラジオボタン＝単一選択**」「**チェックボックス＝複数選択可**」という対比は、GUI設計の基本として最も問われやすいポイントです。

## 2. インタフェース設計 ― 画面・データの具体的な設計

### 2.1 入力チェック方式

利用者が入力したデータに誤りがないかを検証する処理を、まとめて**入力チェック**と呼びます。入力チェックにはいくつかの種類があり、それぞれ検証する観点が異なります。

- **フォーマットチェック**：入力されたデータが、あらかじめ定められた形式（桁数、文字種、書式など）に沿っているかを検証するチェック（例：電話番号が数字とハイフンだけで構成されているか）。
- **バランスチェック**：関連する複数の項目の間で、数値の**合計や整合性が取れているか**を検証するチェック（例：伝票の内訳の合計金額と、合計欄の金額が一致しているか）。
- **論理チェック**：入力された内容が、業務上のルールや常識に照らして矛盾していないかを検証するチェック（例：生年月日が未来の日付になっていないか、開始日が終了日より後になっていないか）。

「フォーマット＝形式の正しさ」「バランス＝数値同士の整合性」「論理＝業務ルール上の妥当性」という、チェックする観点の違いで対比して覚えましょう。

### 2.2 コード設計：桁別コードとその種類

データを一意に識別するための記号・番号（コード）をどう設計するかも、インタフェース設計の重要な要素です。コードの中でも、桁（けた）ごとに意味を持たせる設計方式を**桁別コード**と呼び、代表的な種類には次のものがあります。

- **シーケンスコード（順番コード）**：登録された順番に、単純に1、2、3……と連番を振っていく方式。設計が最も単純ですが、コード自体には特に意味がなく、途中への挿入や分類がしにくいという弱点があります。
- **デシマルコード（区分コード）**：桁ごとに、大分類・中分類・小分類……というように、階層的な分類の意味を持たせる方式（例：図書館の日本十進分類法のように、上位の桁が大分類を、下位の桁がより詳細な分類を表す）。分類体系がそのままコードに反映されるため、コードを見るだけである程度の分類が分かるという利点があります。
- **ニモニックコード（表意コード）**：対象の名称や特徴を連想しやすい文字列を用いる方式（例：空港コードの「NRT」＝成田、商品コードに商品名の頭文字を使う、など）。人間にとって覚えやすく、意味を推測しやすいという利点があります。
- **ブロックコード（区分コード）**：あらかじめ分類ごとに、使用できる番号の**範囲（ブロック）**を割り当てておく方式（例：1000番台は東京支店、2000番台は大阪支店、というように部門ごとに番号の範囲を予約する）。将来の追加にも対応しやすいよう、あらかじめ余裕を持った範囲を確保しておくのが一般的です。

「シーケンス＝単純な連番」「デシマル＝階層的な分類を桁で表現」「ニモニック＝意味を連想できる」「ブロック＝分類ごとに番号の範囲を予約」という、それぞれのコードが**何を重視して設計されているか**の違いで整理すると覚えやすくなります。

### 2.3 フォントとジャギー

画面や印刷物における文字の形状（書体）を**フォント**と呼びます。フォントの選び方一つで、読みやすさや与える印象が大きく変わるため、インタフェース設計における重要な要素の一つです。

デジタル画面上に斜めの線や曲線を描画すると、画面が細かい四角形（画素・ピクセル）の集まりでできているため、線の輪郭にギザギザとした階段状の見た目が生じることがあります。この現象を**ジャギー**と呼びます。文字やアイコンのフォントを表示する際にもジャギーは発生し得るため、輪郭を滑らかに見せるための処理（アンチエイリアシングなど）が、読みやすいインタフェースを作る上で重要になります。

### 2.4 Webデザインとパンくずリスト

**Webデザイン**は、Webサイトの見た目（レイアウト、配色、フォントなど）と、利用者が迷わず目的の情報にたどり着けるようにするための構造（前述のインフォメーションアーキテクチャの実践）を、総合的に設計する活動です。

Webサイトのナビゲーション要素の代表例が**パンくずリスト**です。これは、現在表示しているページが、サイト全体の階層構造の中でどの位置にあるかを、「トップページ ＞ 分類A ＞ サブ分類B ＞ 現在のページ」のように、階層をたどる形でページ上部などに表示する仕組みです（童話「ヘンゼルとグレーテル」で、森の中で道に迷わないようパンくずを落としながら歩いた逸話に由来する名称です）。利用者が「自分は今どこにいるのか」「1つ上の階層に戻るにはどうすればよいか」を直感的に把握できるようにする、インフォメーションアーキテクチャを画面上で具体化した代表的な部品です。

### 2.5 ユニバーサルデザイン

**ユニバーサルデザイン**は、年齢・性別・身体的な能力・言語・文化的な背景といった違いにかかわらず、できるだけ**多くの人が使いやすいように**、あらかじめ製品やサービス、環境を設計しようとする考え方です。前述の「アクセシビリティ」が特定の利用者（高齢者や障がいのある人など）が利用できるかどうかに焦点を当てた**評価の観点**であるのに対し、ユニバーサルデザインは、特別な対応を後から個別に追加するのではなく、最初から**できるだけ多様な利用者が使えるように設計する**という、設計の初期段階からの**方針・アプローチ**である点が対比のポイントです。「アクセシビリティ＝結果として利用できるかどうかの評価軸」「ユニバーサルデザイン＝最初から広く使えるように作る設計思想」という違いを押さえておきましょう。

## 3. 試験対策まとめ（重要ポイント）

- **ユーザビリティ（特定の利用者・状況における使いやすさ）とアクセシビリティ（多様な利用者が利用できる度合い）**、そしてそれを設計段階から実現する**ユニバーサルデザイン**という3つの用語は、視点の違い（評価軸か、設計思想か）を意識して対比で整理する。
- **ユーザビリティ評価手法**は名称と内容の対応が頻出。「実際の利用者に協力してもらうか（アンケート法・回顧法・思考発話法）」「専門家が代わりに評価するか（認知的ウォークスルー法・ヒューリスティック評価法）」という軸と、「使用中に観察するか（思考発話法）・事後に振り返るか（回顧法）」という軸をセットで押さえる。**A/Bテスト**は実データによる定量的な比較検証である点で他の手法と区別する。
- **GUI部品**は「ラジオボタン＝単一選択」「チェックボックス＝複数選択可」の対比が最頻出。プルダウンメニューとポップアップメニュー、リストボックスとコンボボックスの違いもあわせて確認する。
- **入力チェックの3種類**（フォーマットチェック＝形式、バランスチェック＝数値の整合性、論理チェック＝業務ルール上の妥当性）は、チェックする観点の違いで区別する。
- **コード設計の4種類**（シーケンスコード＝単純連番、デシマルコード＝階層的分類、ニモニックコード＝意味を連想、ブロックコード＝分類ごとに番号範囲を予約）は、設計上何を重視しているかで対比して覚える。
- **パンくずリスト**は「サイト内の現在位置を階層で示すナビゲーション」という定義と、インフォメーションアーキテクチャとの関係を押さえる。
- **ジャギー**（画面表示時の輪郭のギザギザ）は、デジタル画面が画素の集合でできていることに起因する現象として理解する。

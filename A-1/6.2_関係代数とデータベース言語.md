## 0. 全体像 ― なぜこの分野を学ぶのか

前回のノートでは、データを表（テーブル）の形に整理し、重複や矛盾のない構造に整える「正規化」までを扱いました。本ノートは、その整った表から、実際に必要なデータを取り出したり操作したりするための理論と手段を扱います。①関係モデル特有の数学的な操作の考え方（**関係代数**）、②その操作をプログラムからどう呼び出すか（**データベース言語とAPI**）、③現在最も広く使われている具体的な言語（**SQL**）という3段階のストーリーで説明します。

前回のノートで、関係モデル（表形式）が「数学的な集合論・関係代数に基づいた理論的な裏付けを持つ」と述べましたが、本ノートの前半は、まさにその「裏付け」の中身にあたります。出題傾向としては、関係演算・集合演算の種類と結果の対応、SQLのSELECT文の各句（WHERE・GROUP BY・ORDER BYなど）の役割と、集約関数を使った計算問題が頻出です。

## 1. 関係代数 ― 表を数学的に操作する

### 1.1 関係代数とは

**関係代数**は、関係モデル（表）に対して行う基本的な操作を、数学の演算のように体系立てて定義したものです。表から必要な行・列を取り出したり、複数の表を組み合わせたりする操作を、あらかじめ決められた種類の演算の組み合わせとして表現できます。関係代数は大きく、1つの表の中で完結する操作である**関係演算**と、複数の表を数学の集合のように扱う**集合演算**の2種類に分けられます。

### 1.2 関係演算：選択、射影、結合

関係演算は、表そのものの「行」や「列」に着目した操作です。

- **選択（セレクト）**：表の中から、指定した**条件に合う行だけ**を取り出す操作。「行」を絞り込む操作であり、SQLでいえば`WHERE`句による絞り込みに相当します。
- **射影（プロジェクト）**：表の中から、指定した**特定の列だけ**を取り出す操作。「列」を絞り込む操作であり、SQLでいえば`SELECT`文で列名を指定する部分に相当します。
- **結合（ジョイン）**：複数の表を、共通する列の値（前回のノートで扱った外部キーなど）をもとに**つなぎ合わせて**、1つの表として扱えるようにする操作。正規化によって複数のテーブルに分割されたデータを、再び関連づけて取り出す際に不可欠な操作です。

「選択＝行を絞る」「射影＝列を絞る」「結合＝複数の表をつなぐ」という、それぞれが操作する対象の違い（行か、列か、表同士の関係か）で整理しておきましょう。

### 1.3 集合演算：和、差、積、直積

集合演算は、複数の表を、数学の「集合」のように扱う操作です。ここでの表は、行の集まり（レコードの集合）として捉えられます。

- **和演算（union）**：2つの表に含まれる行を、重複を取り除いた上で**すべて合わせた**結果を求める操作。
- **差演算（difference）**：一方の表に含まれる行のうち、**もう一方の表には含まれていない**行だけを求める操作。「Aにあって、Bにはないもの」を求める操作です。
- **積演算（共通演算、intersection）**：2つの表の**両方に共通して含まれる**行だけを求める操作。
- **直積演算（cartesian product）**：2つの表の行同士を、**すべての組み合わせ**で掛け合わせた結果を求める操作。表Aがm行、表Bがn行であれば、結果は m×n 行になります。前述の「結合」は、しばしばこの直積を求めた上で、特定の条件（共通の列の値が一致する行だけを選ぶ、など）で絞り込む操作として説明されることがあり、直積演算と結合の関係を理解しておくとよいでしょう。

和・差・積の3つは、いずれも同じ列構成を持つ2つの表を対象とした（重複行を除いた）集合演算である一方、直積は列構成の異なる表同士でも行える、**すべての組み合わせを網羅的に作り出す**演算である、という点で性質が異なります。

## 2. データベース言語とAPI ― プログラムからデータベースを操作する

### 2.1 DDLとDMLの役割分担

前回のノートで、データベースの構造（3層スキーマ）を定義する言語として**DDL（Data Definition Language：データ定義言語）**を紹介しました。これに対し、実際にデータベースに格納されているデータそのものを、検索・追加・更新・削除するための言語を**DML（Data Manipulation Language：データ操作言語）**と呼びます。「DDL＝表の構造を定義する（器を作る）」「DML＝データそのものを操作する（中身を出し入れする）」という役割分担として理解しておきましょう。

### 2.2 DMLをアプリケーションから利用する方式

DMLは、データベースの管理ツールから直接実行することもできますが、業務アプリケーションのプログラムの中からデータベースを操作したい場合も多くあります。この、アプリケーションのプログラム言語（親言語）とデータベース言語(DML)をどう組み合わせるかについては、いくつかの方式があります。

- **親言語方式**：C言語やJavaなど、アプリケーションを開発する際に使う汎用のプログラム言語（親言語）の中に、DMLの命令を組み込んで利用する方式。
- **独立言語方式**：親言語に依存せず、DML（SQLなど）を単独で、対話的に実行できる方式。データベース管理ツールなどから直接SQL文を入力して実行する場合が、この方式にあたります。
- **埋め込み方式**：親言語方式の一種として、プログラムのソースコードの中に、DMLの命令文をそのまま記述（埋め込む）する方式。コンパイルの前段階で、埋め込まれたDML部分が、親言語から呼び出せる形式に変換されます。
- **モジュール言語**：DMLの命令群を、あらかじめ独立した手続き（モジュール）としてまとめて定義しておき、親言語のプログラムからは、そのモジュールを呼び出す形で利用する方式。埋め込み方式のように、DMLの文をプログラムの中に直接記述するのではなく、呼び出しの形を取る点が異なります。
- **API（Application Programming Interface）**：データベース管理システムが提供する、あらかじめ用意された関数群（API）を、親言語のプログラムから呼び出すことで、データベースを操作する方式。現在の多くのアプリケーション開発では、このAPI方式（あるいはそれに準じたライブラリ・フレームワーク）が広く使われています。

いずれの方式も、「アプリケーションのプログラム（親言語）と、データベースを操作するDMLを、どう橋渡しするか」という共通の課題に対する、異なるアプローチである、という点を押さえておきましょう。

### 2.3 カーソル機能

DMLの検索処理（SELECT文など）は、条件に合致する複数の行をまとめて返すことが一般的ですが、親言語のプログラム側では、結果を1行ずつ順番に処理したい場合があります。この、検索結果の複数行を、プログラムから**1行ずつ順にたどって処理できるようにする仕組み**を**カーソル機能**と呼びます。カーソルは、検索結果の中の「今、どの行を指しているか」という位置を管理しており、プログラムはカーソルを1行ずつ進めながら、各行のデータを取り出して処理を行います。前述の「親言語方式」でDMLをプログラムに組み込む際、複数行の検索結果を扱うために欠かせない仕組みです。

## 3. SQL ― 関係データベースの標準言語

### 3.1 SQLとNDL

**SQL（Structured Query Language）**は、関係データベースを操作するための、事実上の標準となっている言語です。前述のDDL・DMLの両方の機能を、統一的な文法で提供しています。関係モデルにおけるSQLに相当する、より一般的な言い方として**NDL（Network Database Language）**のような、他のデータモデル（ネットワークモデルなど）向けのデータベース言語も歴史的には存在しましたが、現在では関係モデルとSQLの組み合わせが、データベース言語の主流となっています。

### 3.2 SQL-DDLと外部キー

SQLのうち、テーブルの構造を定義する部分を**SQL-DDL**と呼びます。代表的な命令として、表を新規に作成する`CREATE TABLE`文があります。表を作成する際には、前回のノートで扱った**主キー**や**外部キー**の指定も、このSQL-DDLの中で行います。外部キーを指定することで、データベース管理システム自身が、「参照先のテーブルに存在しない値を、外部キーの列に登録できないようにする」といった、テーブル間のデータの整合性（参照整合性）を自動的にチェックしてくれるようになります。

### 3.3 SQL-DMLとGRANT文

SQLのうち、データそのものを操作する部分を**SQL-DML**と呼びます。データの検索を行う`SELECT`文、新しい行を追加する`INSERT`文、既存の行を更新する`UPDATE`文、行を削除する`DELETE`文が、代表的なSQL-DMLの命令です。

このほか、データベースに対する操作の**権限**を管理するための命令として**GRANT文**があります。GRANT文は、特定の利用者やロール（役割）に対して、特定のテーブルへの検索・更新などの権限を**付与する**ためのSQL命令です。データベースの内容そのものを操作するDMLとは性質が異なり、誰が何をできるかという**アクセス制御**に関わる命令として、DDLやDMLとは別に整理して理解しておくとよいでしょう。

### 3.4 SELECT文の基本構造

SQL-DMLの中でも特に重要な**SELECT文**は、次のような要素を組み合わせて、柔軟な検索条件を指定できます。

- **IN／BETWEEN**：`WHERE`句の中で使う条件指定の演算子です。**IN**は、指定した複数の値の**いずれかに一致する**行を絞り込む際に使います（例：「東京」「大阪」「名古屋」のいずれかに該当する行）。**BETWEEN**は、指定した**範囲内**にある行を絞り込む際に使います（例：金額が1000円から5000円の間にある行）。
- **ORDER BY**：検索結果の行を、指定した列の値に基づいて、昇順・降順に**並べ替える**ための句です。
- **集約関数とGROUP BY**：複数の行をまとめて、合計・平均・件数といった1つの値に集計するための関数を**集約関数**（COUNT、SUM、AVG、MAX、MINなど）と呼びます。`GROUP BY`句は、特定の列の値が同じ行同士を**グループにまとめた上で**、グループごとに集約関数を適用する際に使います（例：部署ごとの給与の合計を求める、といった集計）。「集約関数だけを使えば表全体の集計、GROUP BYと組み合わせればグループ単位の集計」という違いを理解しておきましょう。
- **副問合せ（サブクエリ）**：1つのSELECT文の中に、**別のSELECT文を入れ子にして**組み込む書き方です。ある検索の結果を、さらに別の検索の条件として利用したい場合などに使われます（例：「平均金額より高い注文だけを取り出す」といった、あらかじめ別の集計結果を条件として使う検索）。

これらの要素を組み合わせることで、前章の関係代数（選択・射影・結合・集合演算）で説明した理論的な操作の多くを、SQLの具体的な文法として実際に記述できるようになります。第1章の「選択＝WHERE句」「射影＝SELECT文の列指定」「結合＝複数テーブルを指定した検索」という対応関係を思い出しながら、理論と実際の文法を結びつけて理解すると定着しやすくなります。

## 4. 試験対策まとめ（重要ポイント）

- **関係演算（選択＝行を絞る・射影＝列を絞る・結合＝表をつなぐ）**と、**集合演算（和・差・積＝同じ列構成の表同士の集合操作・直積＝すべての組み合わせ）**の違いを、操作対象と結果のイメージで区別できるようにする。
- **DDL（構造の定義）とDML（データの操作）**の役割分担をまず押さえた上で、DMLをアプリケーションから利用する方式（親言語方式・独立言語方式・埋め込み方式・モジュール言語・API）の違いを整理する。
- **カーソル機能**は「検索結果の複数行を1行ずつ処理するための仕組み」という定義を正確に覚える。
- **SQL-DDL（CREATE TABLE等、外部キーの指定を含む）とSQL-DML（SELECT/INSERT/UPDATE/DELETE）**、そして権限管理の**GRANT文**は、それぞれ役割が異なる命令群として区別する。
- **SELECT文の各要素**：IN（複数候補のいずれか）とBETWEEN（範囲指定）の違い、ORDER BY（並べ替え）、集約関数（COUNT等）とGROUP BY（グループ単位の集計）の組み合わせ、副問合せ（検索の入れ子）は、いずれも計算・読解問題として頻出。具体的なSQL文を読んで結果を答える練習をしておくと得点効率が高い。
- **関係代数の理論とSQLの文法の対応関係**（選択→WHERE句、射影→SELECT列指定、結合→複数テーブル参照）を意識すると、両者を別々に暗記するのではなく、一体のものとして理解できる。

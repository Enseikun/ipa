# レクチャーノート：ビジネスインダストリ ― 産業別情報システムとeビジネス

対応範囲：情報処理安全確保支援士試験（科目A-1）「経営戦略」＞「ビジネスインダストリ」（ビジネスシステム、エンジニアリングシステム、eビジネスとソリューションビジネス）

---

## 0. 全体像 ― なぜこの分野を学ぶのか

前回のノート（技術戦略マネジメント）では、企業がどう技術を生み出し事業化するかという、技術戦略の視点を見ました。本ノートでは視点をさらに広げ、その技術や情報システムが実際にどの産業・業務分野でどう使われているかという、ビジネスインダストリの知識を扱います。

本ノートは、次の3段階のストーリーで説明します。①まず、流通・物流・行政といった社会全体を支えるビジネスシステムを学びます。②次に、製造業の現場を支えるエンジニアリングシステムを見ます。③最後に、インターネットを介したeビジネスと、情報システムをサービスとして提供するソリューションビジネスの仕組みを見ます。

本分野は科目A-2の出題対象には含まれない科目A-1のみの分野で、略語・カタカナ用語が非常に多いのが特徴です。個々の用語を丸暗記するのではなく、「どの業界・工程を支える仕組みか」「対になる用語と何が違うか」という軸で整理すると効率よく覚えられます。

---

## 1. 社会を支えるビジネスシステム

まず、流通・物流・行政など、社会全体の活動を支える情報システムを見ていきます。

### 1.1 モノと取引を支える情報システム

商品の仕入れ・在庫・販売といった取引（商流）を管理する**流通情報システム**に対し、商品の輸送・保管といった物流業務を管理するシステムを**物流情報システム**と呼びます。流通情報システムが「取引・商流」を扱うのに対し、物流情報システムは「モノの動き」を扱うという対象の違いで区別します。

行政・自治体など公共分野で使われる情報システム全般を**公共情報システム**と呼び、そのうち行政機関の内部業務を支えるシステムを**行政システム**と呼びます。これに対し、行政手続きをインターネット経由で行えるようにする取り組みを**電子政府**と呼びます。行政システムが「行政内部の業務システム」であるのに対し、電子政府は「住民・企業との接点をデジタル化する取り組み」であるという対比で整理できます。

### 1.2 社会の情報基盤とその課題

サイバー空間とフィジカル空間を高度に融合させたシステムにより、経済発展と社会的課題の解決を両立させる、日本が目指す未来社会の姿を**Society 5.0**と呼びます。この実現を支える基盤技術の一つが、あらゆるモノをネットワークに接続してデータを収集・活用する**IoT**です。IoTデバイスの多くは電源配線が難しいため、周囲の光・振動・熱などの微小なエネルギーを電力に変換する**エネルギーハーベスティング**が、給電手段として活用されます。

大量のコンテンツを多数の利用者へ高速に配信するため、利用者に近い場所に複製したコンテンツを配信するネットワークの仕組みを**CDN（Content Delivery Network）**と呼びます。一方、こうした情報化の便利さには課題もあり、検索エンジンやSNSのアルゴリズムが利用者の興味関心に合わせた情報ばかりを表示することで、異なる意見・情報に触れにくくなる現象を**フィルタバブル**と呼びます。IoTやCDNが情報化を支える基盤技術であるのに対し、フィルタバブルはその情報化がもたらす副作用として、対になる位置づけで押さえておきます。

## 2. 製造業を支えるエンジニアリングシステム

次に、製造業の設計・製造・生産管理を支える情報システム群を見ていきます。略語が多いため、「工程のどこを支えるか」で整理します。

### 2.1 設計・製造・検証を支える

| システム | 内容 |
|---|---|
| **CAD（Computer Aided Design）** | 製品の設計をコンピュータで支援する |
| **CAM（Computer Aided Manufacturing）** | 製品の製造・加工をコンピュータで支援する |
| **CAE（Computer Aided Engineering）** | 設計した製品の性能をコンピュータ上でシミュレーション・解析し評価する |
| **CAP／CAPP（Computer Aided Planning／Process Planning）** | 製造工程の計画をコンピュータで支援する |

CAD・CAMが「設計し、作る」ことを支援するのに対し、CAEは「その性能を検証する」ことを支援するという役割の違いで区別すると整理しやすくなります。

### 2.2 生産システム全体を統合する

多品種少量生産に対応できる、柔軟性の高い自動化生産システムを**FMS（Flexible Manufacturing System）**と呼び、その構成単位となる個々の自動化セルを**FMC（Flexible Manufacturing Cell）**と呼びます。FMCが単一のセル単位であるのに対し、FMSは複数のFMCを組み合わせたシステム全体を指すという規模の違いで区別します。工場の生産工程を自動化する仕組み全般を**FA（Factory Automation）**と呼び、設計から製造、生産管理までをコンピュータによって統合的に管理する、より広い概念を**CIM（Computer Integrated Manufacturing）**と呼びます。CAD・CAM・CAE・FA等の個々のエンジニアリングシステムを、CIMが統合的に束ねるという包含関係で位置づけられます。このCIMを実現するために、工場内の様々な機器を接続する通信プロトコル規格が**MAP（Manufacturing Automation Protocol）**です。

### 2.3 生産管理システムとその周辺

生産計画・工程管理・在庫管理など、生産活動全体を管理するシステムを**生産管理システム**と呼びます。企業の競争優位を確立するために戦略的に活用される情報システムを**SIS（戦略情報システム）**と呼び、生産管理システムもその一形態として位置づけられます。製品の生産計画から必要な資材の種類・数量・発注時期を計算する手法が**MRP（資材所要量計画）**、設計図面や部品構成など製品に関する情報を一元管理する仕組みが**PDM（製品情報管理）**です。また、電子機器の製造を受託する事業形態を**EMS（Electronics Manufacturing Service）**と呼びます。

### 2.4 現場での情報管理 ― POPとカンバン方式

生産現場の作業実績・稼働状況をリアルタイムに収集する仕組みを**POPシステム（Point Of Production）**と呼びます。前回までのノートで触れたPOS（販売時点情報管理）が販売現場の情報を捉える仕組みであるのに対し、POPシステムはその生産現場版にあたります。

必要なものを必要な時に必要な量だけ生産・供給するという考え方を**JITシステム（ジャストインタイム）**と呼び、これをトヨタ生産方式で実現する具体的な管理手法が**カンバン方式**です。「かんばん」と呼ばれる指示票を用いて、後工程が前工程から部品を引き取る際に使う**引き取りカンバン**と、前工程に対して生産を指示する際に使う**生産指示カンバン**の2種類があります。JITが実現すべき考え方であるのに対し、カンバン方式はそれを実現するための具体的な情報伝達の手段であるという、目的と手段の関係で整理できます。

## 3. インターネット上の商取引とサービス化 ― eビジネスとソリューションビジネス

最後に、インターネットを介した商取引と、情報システムをサービスとして提供する仕組みを見ていきます。

### 3.1 インターネット上の商取引

インターネットを介して商品・サービスを売買する取引形態を**EC（電子商取引）**と呼び、その代金決済を電子的に行う仕組みを**電子決済システム**と呼びます。オンライン（Web・アプリ）での情報発信・販促活動を、オフライン（実店舗）での購買行動へ誘導する施策を**O to O（Online to Offline）**と呼びます。

金融（Finance）と技術（Technology）を組み合わせた金融サービスの革新を**フィンテック**と呼び、貨幣価値を電子データ化した**電子マネー**や、法定通貨とは異なる電子的な暗号資産である**仮想通貨**は、その具体的な実現例です。電子マネーが特定の発行者が価値を保証する電子的な貨幣であるのに対し、仮想通貨は中央管理者を持たない分散的な仕組みで取引されるという違いがあります。

ECサイトでは、売れ筋商品だけでなく、個々の販売数は少ないが種類が多い商品群を幅広く扱うことで全体の売上を伸ばす**ロングテール**という考え方が知られています。実店舗の陳列棚のような制約を持たない、EC特有の戦略です。また、他サイトが自社商品・サービスを紹介し、その成果に応じて報酬を支払う成果報酬型の広告の仕組みを**アフィリエイト**と呼びます。

### 3.2 SNS時代のマーケティングと推薦の仕組み

利用者間の情報発信・交流を主体とするメディアを**ソーシャルメディア**と呼び、企業が活用する際には不適切な発信を防ぐための**ソーシャルメディアガイドライン**が定められることが一般的です。

利用者の興味・関心に合った商品・情報を推薦する仕組みを**レコメンデーション**と呼び、代表的な方式として次のものがあります。

| 方式 | 内容 |
|---|---|
| **ルールベース** | あらかじめ定めたルールに基づいて推薦する |
| **協調フィルタリング** | 似た嗜好を持つ他の利用者の行動データを基に推薦する |
| **コンテンツベース** | 商品・コンテンツ自体の特徴（属性）を基に、似たものを推薦する |
| **ハイブリッドタイプ** | 協調フィルタリングとコンテンツベースなど、複数の方式を組み合わせて推薦する |

協調フィルタリングが「他の利用者との類似性」に着目するのに対し、コンテンツベースは「商品そのものの特徴」に着目するという、推薦の根拠の違いで区別します。

### 3.3 情報システムをサービスとして提供する ― ソリューションビジネス

個々の製品・技術の提供にとどまらず、顧客の経営課題を解決する仕組み全体を提供するビジネス形態を**ソリューションビジネス**と呼びます。その先駆けとなった形態が、アプリケーションソフトウェアの機能をネットワーク経由でサービスとして提供する**ASPサービス**です。前回のノートで扱った**SaaS・IaaS・PaaS**は、このASPサービスの考え方をより標準化し、多数の顧客に対して提供する形態として発展したものとして位置づけられます（前回接続）。クラウド環境の利用形態としては、不特定多数の利用者が共用する**パブリッククラウド**と、特定の組織専用に構築・運用される**プライベートクラウド**があり、共用か専用かという違いで区別します。

### 3.4 企業間で情報をやり取りする仕組み ― EDI

企業間の商取引に関する情報を、電子的な標準形式で交換する仕組みを**EDI（Electronic Data Interchange）**と呼び、その国際的な標準規格の一つが**EDIFACT**です。EDIは、次の4つの規約によって構成されます。

| 規約 | 内容 |
|---|---|
| **取引基本契約** | EDIを行う当事者間で取り決める、取引の基本的なルール |
| **業務運用規約** | 実際の業務手順・運用方法を取り決める規約 |
| **情報表現規約** | やり取りするデータの表現形式を取り決める規約。データの並べ方などの文法を定める**シンタックスルール**と、個々の項目の意味を定める**データエレメント**から成る |
| **情報伝達規約** | データをどのような通信手順で伝達するかを取り決める規約 |

「契約を結び（取引基本契約）、運用を定め（業務運用規約）、データの形式を決め（情報表現規約）、実際に伝える（情報伝達規約）」という工程の順序で捉えると、4つの規約の位置づけを覚えやすくなります。

### 3.5 新しいデータ活用の形

複数の口座・サービスの情報を一つの画面でまとめて閲覧できるようにするサービスを**アグリゲーションサービス**と呼び、フィンテックの代表例の一つです。現実の設備・製品等の状態を仮想空間上に再現し、シミュレーション・分析に活用する仕組みを**デジタルツイン**と呼びます。2章で見たCAD・CAEが設計段階の仮想化であるのに対し、デジタルツインは稼働中の実物の状態をリアルタイムに反映する点が異なります。

電波を用いてICタグの情報を非接触で読み取る技術である**RFID**は、1章のIoT機器や、物流・生産現場でのモノの識別に広く活用されます。また、個人が自らのパーソナルデータを預け、本人の同意のもとで企業等に提供・活用してもらう仕組みを**情報銀行**と呼び、個人データ活用の新しい形として位置づけられます。

## 4. 試験対策まとめ（重要ポイント）

- **流通情報システム と 物流情報システム**：取引・商流を扱うか、モノの動きを扱うかの違い。
- **行政システム と 電子政府**：行政内部の業務システムか、住民・企業との接点のデジタル化かの違い。
- **CAD／CAM と CAE**：設計・製造を支援するか、性能を検証するかの違い。
- **FMC と FMS**：単一の自動化セルか、それを組み合わせたシステム全体かという規模の違い。
- **CIM と MAP**：設計から生産管理までを統合的に管理する概念か、それを実現する通信規格かの違い。
- **JITシステム と カンバン方式**：実現すべき考え方か、それを実現する具体的な情報伝達の手段かという目的と手段の関係。
- **電子マネー と 仮想通貨**：発行者が価値を保証する電子的な貨幣か、中央管理者を持たない分散的な暗号資産かの違い。
- **協調フィルタリング と コンテンツベース**：他の利用者との類似性に着目するか、商品自体の特徴に着目するかの違い。
- **ASPサービス と SaaS／IaaS／PaaS**：クラウドサービスの先駆けとなった形態か、それを標準化・発展させた形態かという関係（前回接続）。
- **EDIの4規約**：取引基本契約→業務運用規約→情報表現規約→情報伝達規約という、契約から伝達までの工程の順序。

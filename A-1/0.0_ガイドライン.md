# レクチャーノート作成ガイドライン

対象：情報システム分野（応用情報技術者試験・情報処理安全確保支援士試験の共通知識）のレクチャーノート
前提：試験範囲（シラバス）は別途提供される。作業指示は「以下に列挙する項目についてレクチャーノートを作成してください」である。
目的：列挙されたキーワードを、用語集ではなく、学習者が一読して構造を掴める講義として再構成する。

---

## 1. このノートが目指すもの

レクチャーノートは、キーワードの定義を並べた用語集ではない。学習者が「なぜこの分野が必要か → 何が対立・発展してきたか → 試験ではどこが問われるか」まで一気に辿れる、1本の講義である。

作成時の最優先基準は次の3点である。

1. **ストーリーがあること**：キーワードは、宣言した段階（①②③…）の順で登場する。
2. **孤立した用語を作らないこと**：すべてのキーワードは、対比・発展・包含・目的と手段・前回ノートとの接続のいずれかに位置づける。
3. **試験の問われ方が本文中に埋め込まれていること**：まとめ章だけに試験対策を寄せない。

---

## 2. 成果物の標準構成

ファイルは Markdown とし、次の骨格をこの順で固定する。章数は内容に応じて 2〜4 章とする（導入とまとめを除く）。

```
# レクチャーノート：{親分野名} ― {シラバス番号} {単元名}

対応範囲：応用情報技術者試験・情報処理安全確保支援士試験（午前I／午前II共通）「{大分類}」＞「{中分類}」＞「{小分類}」

---

## 0. 全体像 ― なぜこの分野を学ぶのか
（導入。後述）

## 1. {第1段階のテーマ} ― {その段階を一言で表すサブタイトル}
### 1.1 …
### 1.2 …

## 2. {第2段階のテーマ} ― {サブタイトル}
…

## N. 試験対策まとめ（重要ポイント）
（箇条書き）

---

*本ノートは「基本情報／応用情報技術者試験」の出題範囲（{対応範囲の要約}）に基づき作成しています。…*
```

タイトルの親分野名は、シラバス上の直近のまとまりを使う（例：コンピュータ構成要素、システム構成要素、ソフトウェア、技術要素）。対応範囲は、提供されたシラバスの階層を「＞」でつなぐ。

水平線は「対応範囲の直後」と「まとめ章の直後（フッターの前）」に入れる。

分量の目安は、キーワード数にもよるが本文 80〜180 行程度。低優先分野でも用語を落とさず、深追いしない。高優先分野でも、シラバス外の発展解説はしない。

---

## 3. 作業の手順 ― キーワードからストーリーを作る

列挙された項目（キーワード）とシラバスを受け取ったら、いきなり書き始めない。次の順で設計してから本文に入る。

### 手順1：キーワードを「問題」単位でクラスタリングする

キーワードをシラバス掲載順のまま並べない。次の問いでグループ化する。

- 何の問題を解く技術か（速度、信頼性、役割分担、表現、復旧など）
- 同じ軸で対比できるか（A対B、3方式、世代の系譜）
- 抽象度は同じか（理論 / 方式 / 具体規格 / 運用指標）

1クラスタが、本文の1節（`###`）になる。クラスタを無理に増やさず、1ノートあたり本文は 2〜4 章に収める。

### 手順2：ノート全体の「段階ストーリー」を決める

既存ノートは、例外なく導入で次の型を宣言している。

> ①〜、②〜、③〜という N 段階のストーリーで説明します。

この ①②③ は、本文の第1章・第2章・第3章と **1対1** で対応させる。ストーリーの切り方は、分野の性質に応じて次の型から選ぶ（複数を混ぜてよいが、宣言した順は守る）。

| 型 | 展開 | 向いている分野 |
|---|---|---|
| 構造→工夫→拡張 | 基本の仕組み → 速く／強くする工夫 → 複数化・応用 | プロセッサ、メモリ、OS |
| 測る→思想→数値化 | 指標 → 設計思想 → 計算式 | 性能・信頼性 |
| 理論→手段→実装 | 数学・モデル → 呼び出し方 → 具体言語・規格 | 関係代数とSQL、OSIとTCP/IP |
| 役割→信頼性→形態 | 誰が何をするか → 壊れにくさ → どこで処理するか | システム構成 |
| 基礎技術→応用 | データの扱い → それを使った応用 | UI、マルチメディア、DB応用、ネットワーク応用 |
| 範囲→媒体→接続 | 狭い世界 → 伝送の物理 → 広域・インターネット | LAN/WAN |

切り方の原則は「学習者が初めて聞く順」である。完成形や最先端から入らない。まず「なぜその仕組みが必要か」を置き、次に基本形、その限界、限界を超える発展形、対になる別アプローチ、の順にする。

悪い例：RAID6 → RAID0 の順、H.265 → MP3 の順、SQL文法 → 関係代数の順。
良い例：ストライピング／ミラーリングという発想 → RAID0/1 → パリティで両立するRAID5 → さらに耐えるRAID6。

### 手順3：各キーワードの「位置づけ」を1つ決める

キーワードごとに、本文で使う関係の型を1つ（必要なら2つ）割り当てる。型がないキーワードは、まだクラスタリングが不足している。

- **対比**：同じ目的の別解（TCPとUDP、SRAMとDRAM、フェールセーフとフェールソフト）
- **発展**：前の方式の限界を克服する（パリティ→ハミング、H.264→H.265、IPv4→IPv6）
- **包含**：上位概念と下位概念（IC＞LSI＞VLSI、候補キー＞主キー＋代替キー）
- **目的と手段**：何のためか／何で実現するか（DSSとOLAP、SDNとOpenFlow）
- **階層**：同じものの抽象度の違い（概念／論理／物理、OSIの各層）
- **工程**：順番に行う処理（標本化→量子化→符号化、クリッピング→レンダリング）
- **トレードオフ**：一方を立てると他方が犠牲（ホットスタンバイの切替速度と待機コスト）
- **前回接続**：既出概念の別場面への適用（メモリのパリティ→通信の誤り制御、セマフォ→DBロック）

「余ったキーワード」も用語集にせず、最も近い章の末尾に「位置づけ」付きで入れる。どうしても主筋に乗らない場合のみ、「その他の〜」として、主テーマとの距離を一文で明示する。

### 手順4：計算・判定・読図が出る論点を印す

シラバスや既存ノートの傾向から、次のいずれかになりそうな論点には、本文で「考え方 → 式または判定手順 → 試験での出方」まで書く。

- 計算：ヒット率、稼働率、MIPS、正規化判定、SQLの結果
- 対比選択：名称と特徴の組み合わせ問題
- 順序・流れ：割り込み処理、2相コミット、命令サイクル

公式だけを置かない。「何と何の比率／重みづけ平均／掛け算か引き算か」という直感を先に書く。

## 4. 各パートの書き方

### 4.1 導入（## 0. 全体像 ― なぜこの分野を学ぶのか）

導入は次の3ブロックをこの順で書く。見出しは増やさない。

**（1）前後の文脈**
直前ノートまたは直前分野との関係を1〜3文でつなぐ。

- 「これまでのノートでは〜を見てきました。本ノートで扱うのは〜です。」
- 視点が上がる／下がる／裏返る場合は、その転換を明示する（内部構造→システム構成、正しく動くか→使いやすいか、日々の更新→分析、届ける先→信号そのもの）。

**（2）本ノートのストーリー予告**
手順2で決めた段階を、番号付きで宣言する。ここが本文の目次になる。

**（3）学ぶ価値（出題傾向）**
提供されたシラバスと、プロジェクト内の出題傾向を踏まえ、次を短く述べる。

- 知識問題か計算問題か
- 定番論点の名前（2〜4個）
- 当該試験における相対的な優先度（厚くやる／典型論点で止める）
- 後続分野（特にセキュリティ・ネットワーク）への波及があれば一言

導入でキーワードの定義を始めない。定義は本文から。

### 4.2 本文各章（## 1. 以降）

各章の先頭に、その章が扱う「問題意識」を短い段落で置く。キーワードの列挙から入らない。

章タイトルは「名詞 ― その章の役割を表す文」とする。

- 良い例：`メモリシステムの構成 ― キャッシュという発想`
- 悪い例：`キャッシュメモリ`（何を論じる章かが分からない）

節（`###`）は、1つの問題または1つの対比クラスタに1つ。節の中は次の流れを基本とする。

1. その節が解く問題、または親概念の定義
2. 構成要素・方式・種類を箇条書きで展開（各項目は太字の用語名で始める）
3. 各項目：定義 → 特徴 → 用途または具体例 → 兄弟概念との違い
4. 節の締め：対比の公式、または「試験で問われる着眼点」を1文

3つ以上の項目が同じ属性で並ぶときは表にする（層の役割、指標の意味、規格と速度、GUI部品と用途など）。2項目の対比は表にせず、本文の対句で書く。

### 4.3 キーワード解説の定型文

用語の初出は **太字**。略語は初出で正式名称を括弧書きする。

`**RPC（Remote Procedure Call：遠隔手続き呼出し）**は、…`

説明文は、次の型を状況に応じて組み合わせる。1用語あたり概ね 3〜8 文。定義1文で終わらせない。ただし低優先の周辺用語は 2〜3 文で位置づけまで書けば足りる。

**定義**：〜とは、…する仕組み／方式／性質です。
**動機**：〜だけでは…という問題が残る。そこで登場するのが…。
**対比**：「A＝〜」「B＝〜」という対比で整理する。
**具体例**：例：銀行のATM、信号機の全赤、など。
**試験**：〜という点が試験で問われる。
**接続**：{シラバス番号}のノートで扱った〜を、ここでは…に適用したものである。
**位置づけ**：〜の代表的な実現手段／発展形／折衷案として位置づけられる。

対比の締めは、既存ノートで繰り返し使われている次の言い回しを使ってよい。

- 「〜という対比で覚えると整理しやすい論点です」
- 「〜として位置づけられます」
- 「〜と捉えると理解しやすいでしょう」
- 「〜という点が試験でも問われるポイントです」

比喩は使ってよいが、1節に1つまでにする（パイプライン＝流れ作業、データウェアハウス＝倉庫、など）。比喩で定義を置き換えない。

### 4.4 過去ノートとの接続

既出概念を再利用するときは、再定義せず「どのノートの何を、この場面に適用したか」を書く。参照は次で統一する。

- 直前のノート：「前回のノート」
- それ以外：「{シラバス番号}のノート」（例：2.2のノート、3.2のノート）
- 「第N回」という通算番号は使わない（番号の解釈が揺れやすいため）

接続の典型は次である。

- 同じ原理の別適用（主記憶のパリティ → 通信路の誤り制御）
- 抽象から具体（SoC → マイコン、キャッシュの発想 → スプーリング）
- 対極（OLTP → OLAP、集中処理 → 分散処理）

### 4.5 まとめ章（## N. 試験対策まとめ）

本文の縮小コピーにしない。学習者が試験直前に見る対比カードとして書く。

- 箇条書き 6〜10 項目
- 1項目は「対になる用語＋区別の軸＋（必要なら）最頻出である旨」
- 計算論点は式の意味（直列は掛け算、並列は故障確率を引く、など）を残す
- 暗記方法の指定は必要なときだけ（表で覚える、図でイメージする、判定練習をする）

本文で扱ったキーワードをすべて繰り返す必要はない。落とすなら、まとめに無い用語が本文で対比・位置づけ済みであることを確認する。

### 4.6 フッター

まとめ章の後に水平線、続けて次の要素を1段落のイタリックで書く。

1. 依拠した出題範囲（基本情報／応用情報の該当箇所）
2. プロジェクト内の出題傾向に基づく、当該分野の相対優先度
3. 学習配分の指針（深追いしない／計算を優先する／後続分野への波及を意識する、のいずれか）

シラバス外の参考文献リストは付けない。未提供の出題傾向を推測で数値化しない。傾向情報が無ければ、フッターは出題範囲の明示と「典型論点の理解を優先する」程度にとどめる。

## 5. 文体・表記

- 常体ではなく、です・ます調の講義体にする。
- 読者は初学者〜午前対策者。専門家向けの省略をしない。
- 箇条書きの先頭は **太字の用語名** で始め、直後に読点またはコロンで説明を続ける。
- 英語略語は半角。日本語と英語の境界に不要な空白を入れない。
- 数式は Markdown の数式記法を使い、式の前に「何を重みづけ／何を割っているか」を書く。
- 章番号・節番号は階層を飛ばさない（1の次に3を置かない）。
- 「など」で用語を曖昧にまとめ、指定キーワードを本文から消さない。指定された項目は、見出しになるか、太字で本文に出す。

---

## 6. やってはいけないこと

- キーワードを五十音順・リスト順に定義だけ書いて終わる。
- 導入で宣言した①②③と、本文の章立てがずれる。
- 対比できる用語を別章に散らし、違いを読者に推測させる。
- 発展の結果（RAID6、コンテナ、H.265）から書き始め、基本形を後回しにする。
- 計算式だけを置き、加重平均・直列／並列などの意味を書かない。
- 既存ノートで既に定義した概念を、接続なしにゼロから長く再解説する。
- シラバスにない周辺知識で章を膨らませる。
- まとめ章を本文のコピペにする、または本文に無い新出用語をまとめだけに出す。
- 用語集・参考リンク・演習問題のセクションを独自追加する（構成を標準から外さない）。

## 7. 完成前チェックリスト

- [ ] タイトルと対応範囲が、提供シラバスの階層と一致している
- [ ] 導入が「文脈 → 番号付きストーリー → 出題上の価値」の3点をこの順で含む
- [ ] 導入の①②③と本文の章が1対1である
- [ ] 指定キーワードがすべて本文に太字で出現している
- [ ] 各キーワードに、対比・発展・包含・目的手段・階層・工程・トレードオフ・前回接続のいずれかがある
- [ ] 各章の冒頭に問題意識があり、用語の羅列から始まっていない
- [ ] 3つ以上の並列項目は表になっている
- [ ] 計算・判定論点は「考え方 → 式または手順 → 出題のされ方」がある
- [ ] 直前分野および関連する既出ノートへの接続がある（孤立した単元になっていない）
- [ ] まとめは対比カードになっており、フッターに範囲と学習配分がある
- [ ] です・ます調で、講義として通読できる

## 8. 指示文を受けたときの解釈

作業指示が「以下に列挙する項目についてレクチャーノートを作成してください」である場合、列挙項目は **本文で必ず扱うキーワード** であり、見出し順ではない。見出し順とストーリーは、本ガイドラインの手順1〜2で作成者が再構成する。

シラバスは **範囲の境界と正式な単元名** を与える。シラバスの小項目名は章タイトルの候補になるが、小項目をそのまま機械的に章にする必要はない。ストーリー上まとめた方が分かりやすければ、シラバスの隣接小項目を1章に統合してよい。逆に、1小項目でも対比軸が複数ある場合は章を分けてよい。

列挙項目に無い用語は、説明に必要な最小限の接続語（例：ユニキャスト、ホストOS）に限り、位置づけを添えて使ってよい。それを新たな学習対象として膨らませない。
